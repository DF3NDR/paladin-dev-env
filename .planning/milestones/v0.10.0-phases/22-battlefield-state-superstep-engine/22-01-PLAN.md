<task type="checkpoint:decision" gate="blocking">
  <name>Task 1: Decide the graph fingerprint algorithm and canonicalization (D-04, one-way)</name>
  <decision>How `GraphFingerprint` is computed and encoded, since it is written into every persisted Waypoint from this task forward.</decision>
  <context>
    ENG-FR-14 stores a graph fingerprint in every Waypoint and `resume` refuses to continue when it
    does not match. Once v0.10.0 ships, changing the hash function or the canonicalization makes
    every already-stored Waypoint mismatch, so every existing thread fails `resume` with
    `GraphMismatch` on a graph the user never changed. That is a data migration, not a refactor —
    this is a one-way door and it is being opened by the very first task that writes a Waypoint.
    CONTEXT.md D-04 was auto-selected in `--auto` mode, so no human has confirmed it.
  </context>
  <options>
    <option id="option-a">
      <name>D-04 exactly as written: blake3 over a canonical, deterministically ordered serialization of node ids, edge specs and schema, hex-encoded, excluding prompts/models</name>
      <pros>Matches the recorded decision verbatim; blake3 is already a paladin-core dependency and is used the same way in three existing version services; shortest path.</pros>
      <cons>The stored fingerprint carries no algorithm marker, so a future change is undetectable and unrecoverable — every stored Waypoint simply stops resuming.</cons>
    </option>
    <option id="option-b">
      <name>D-04 plus a version tag: the stored fingerprint string is `v1:{blake3_hex}` over the same canonical stream (RECOMMENDED)</name>
      <pros>Identical hashing to option-a, but a future algorithm change emits `v2:` and can be detected, so old Waypoints can be recognised and migrated or grandfathered instead of failing every resume. Converts a one-way door into a costly-but-recoverable one, which is the preferred move over merely gating it.</pros>
      <cons>Four extra characters in every stored Waypoint; the tag must be documented in MIGRATION.md 9.4 as part of the payload format.</cons>
    </option>
    <option id="option-c">
      <name>sha2 instead of blake3 over the same canonical stream</name>
      <pros>sha2 is also already a paladin-core dependency; more universally recognised.</pros>
      <cons>Contradicts D-04 and the PRD's implied choice for no benefit — the fingerprint is a change-detection hash, not a security control (RESEARCH.md Security Domain, V6 marginal). Slower than blake3.</cons>
    </option>
  </options>
  <resume-signal>Select: option-a, option-b, or option-c</resume-signal>
</task>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| node output -> Battlefield | A node's `StateDelta` is arbitrary JSON entering shared typed state |
| Battlefield -> Waypoint payload | In-memory state crosses into a durable, serialized, later-re-read artifact |
| stored Waypoint -> resume | Previously serialized data is deserialized back into live engine state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-01 | Tampering | `Waypoint` deserialization in `waypoint.rs` / `InMemoryWaypointStore` | medium | mitigate | X-04 `schema_version` on every persisted type plus a typed `WaypointError::SchemaVersionUnsupported` / `BattlefieldError::SchemaVersionUnsupported` — an unknown newer version is an explicit error, never a panic and never a silent structural misparse |
| T-22-02 | Information Disclosure | `BattlefieldError` variants embedding field values | medium | mitigate | `TypeMismatch` carries `expected`/`got` as type NAMES and `UnknownField`/`MissingRequiredField` carry field NAMES only — no `BattlefieldError` variant embeds a `serde_json::Value` drawn from state, so an LLM output or secret in a field cannot reach a log line through an error |
| T-22-03 | Spoofing | `resume` accepting a Waypoint written for a different graph | high | mitigate | `GraphFingerprint` stored in every Waypoint and compared on `resume`, failing with `EngineError::GraphMismatch { expected, got }` before any node executes |
| T-22-SC | Tampering | cargo dependency additions | high | mitigate | No new crate name is introduced: only a `v7` feature on the existing pinned `uuid 1.8.0`, verified against docs.rs in RESEARCH.md's Package Legitimacy Audit (verdict OK, no `[ASSUMED]`/`[SUS]`/`[SLOP]` rows) |
</threat_model>
