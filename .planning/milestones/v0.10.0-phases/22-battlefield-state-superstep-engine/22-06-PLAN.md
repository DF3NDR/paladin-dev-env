<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied ThreadId / WaypointId -> SQL | Caller strings become query parameters and key column values |
| database URL -> error strings and logs | A connection string carrying a password can reach an error envelope |
| stored payload -> deserialization | Previously written JSON, possibly from an older release, is parsed back into live types |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-17 | Tampering | SQL injection via `thread_id` / `waypoint_id` in either SQL backend | high | mitigate | Every statement uses `.bind(...)` parameters, matching the existing `sqlite_workflow_repository.rs` convention; an acceptance grep asserts no `format!` builds a SELECT/INSERT/UPDATE/DELETE, and a test round-trips a `thread_id` containing a SQL metacharacter as data |
| T-22-18 | Information Disclosure | database password embedded in a `WaypointError::Backend` string | high | mitigate | Credentials are redacted before any truncation, per the project's security instructions — bounding first can slice a secret across the truncation boundary; a test asserts a password-bearing URL does not appear in the resulting error string |
| T-22-19 | Tampering | deserializing a payload written by an unknown newer release | medium | mitigate | The payload's embedded `schema_version` is checked and an unrecognised version maps to `WaypointError::SchemaVersionUnsupported` rather than a structurally-successful misparse (X-04) |
| T-22-20 | Denial of Service | unbounded `waypoints` table growth from long cyclic runs | medium | mitigate | `WaypointRetentionConfig` bounds by age and per-thread count with two hard exclusions; the per-run Waypoint count is independently bounded by `EngineLimits` |
| T-22-21 | Denial of Service | retention deleting a checkpoint a human is waiting on | high | mitigate | The prune routine treats "never the thread's latest" and "never an `AwaitingInput` Waypoint" as its own invariants rather than caller responsibilities, each with a dedicated failing-first test |
| T-22-SC | Tampering | new cargo feature pulling a database driver | high | mitigate | The `postgres` feature enables `sqlx/postgres` on the already-pinned `sqlx 0.8` — no new crate name (RESEARCH.md Package Legitimacy Audit verdict OK). `cargo tree -e features` confirms the `paladin-ai` default set is unchanged (X-11.4) |
</threat_model>
