<objective>
Implement the three seams later epics consume — the `TraceSink` hook, the ordered `NodeInterceptor`
chain, and the `CancellationToken` to `Halted` path — as working, non-interfering mechanisms with no
consumers.

Purpose: PRD section 8 hands these seams to Docs 03, 05 and 07. ENG-07's whole value is that a
later epic finds a working hook rather than having to reopen the engine's execution path. The
hardest requirement here is the negative one: a slow or failing trace sink must never stall or fail
a run, and that is only credible when tested with a sink that genuinely blocks forever.

Output: `TraceSink` in `paladin-ports`, a bounded drop-oldest dispatcher, an ordered interceptor
chain defaulting to empty, and cancellation producing a `Halted` Waypoint.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| engine -> trace sink | Run-internal data crosses into a caller-supplied sink that may export it off-process |
| interceptor -> node delta | Caller-supplied code can mutate state before it merges, or suppress a node entirely |
| external signal -> run lifecycle | A cancellation token from outside the run decides when it stops |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-30 | Denial of Service | a slow or blocking `TraceSink` stalling every run | high | mitigate | Emission is fire-and-forget over a bounded channel with a drop-oldest policy; the engine never awaits the sink's handler and never awaits channel backpressure, proven by a permanently blocking sink test with an explicit timeout |
| T-22-31 | Repudiation | trace events silently discarded, making a trace look complete when it is not | medium | mitigate | Drops are counted in an atomic the caller can read, so a consumer can detect and report loss rather than infer a gap-free stream (ENG-FR-21) |
| T-22-32 | Information Disclosure | `DeltaMerged` events carrying field values off-process to an exporter | medium | mitigate | The event carries the set of changed field NAMES rather than their values, so attaching an exporter does not by itself export shared state |
| T-22-33 | Tampering | a `NodeInterceptor` silently altering a delta or suppressing a node | low | accept | The chain is empty by default and populated only by the application; a `Skip` is recorded in the Waypoint as `Skipped` with its reason rather than becoming an invisible no-op, so suppression is auditable in the checkpoint history |
| T-22-34 | Denial of Service | cancellation abandoning a superstep mid-merge and leaving unresumable state | high | mitigate | Cancellation is observed at the superstep boundary only: the in-flight superstep completes and merges before the `Halted` Waypoint is written, so every halt point is a consistent restart point, verified by a resume-from-Halted test |
</threat_model>
