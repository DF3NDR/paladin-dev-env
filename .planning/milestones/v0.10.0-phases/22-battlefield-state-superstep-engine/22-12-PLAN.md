<objective>
Close gap G-22-1: make the `PostgresWaypointStore` Tier 2 contract suite actually execute.

The suite is environment-gated on `WAYPOINT_POSTGRES_TEST_URL` and returns early (printing a
named reason, then passing) when no server is reachable. Nothing in this repository sets that
variable except `make test-integration-docker`, which needs a local Docker daemon no development
environment here has. The consequence: the suite has never run anywhere, while reporting green
in every CI run — the same failure shape Phase 17 found and fixed for the Ollama suite.

Purpose: ENG-05 claims three `WaypointPort` backends pass one shared contract suite. Today that
claim is proven for two of them. This plan gives the third a place to run.
Output: a `postgres-integration` CI job that starts a real Postgres, runs the suite against it,
and fails loudly if the suite skipped or if the filter selected nothing.
</objective>

Add a new top-level job keyed `postgres-integration` to `.github/workflows/ci.yml`, placed
immediately after the `ollama-integration` job and before `coverage`, with no `needs:` edge —
matching how `ollama-integration` sits in the graph (it gates nothing and is gated by nothing).

Precede the job with a comment block, in the same voice as the `ollama-integration` block, that
states the reason this job exists: the Postgres Tier 2 waypoint contract suite is env-gated and
returns early — and therefore passes — when no server is reachable, so before this job the suite
executed in no environment at all while every CI run reported green. Say explicitly that the
reachability assertion, the early-return detection and the selected-count assertion are what give
the job its meaning and must not be removed.

Job body, following the `ollama-integration` step sequence:

- `name: Postgres Waypoint Contract Suite (live server)`, `runs-on: ubuntu-latest`.
- Checkout with `actions/checkout@v5`; install Rust with `dtolnay/rust-toolchain@stable`;
  `Swatinem/rust-cache@v2` with `key: postgres-integration`.
- Start the service: `docker compose -f docker/docker-compose.test.yml up -d postgres-test`,
  then wait on the container healthcheck with
  `timeout 180 sh -c 'until docker inspect paladin-postgres-test --format="{{.State.Health.Status}}" 2>/dev/null | grep -qx healthy; do sleep 3; done'`.
  Carry over the `ollama-integration` comment explaining that `-qx` is load-bearing because an
  unanchored match also matches the unhealthy status, and that the value is piped into grep
  rather than command-substituted inside single quotes (shellcheck SC2016).
- Assert the server is actually accepting connections before any test runs:
  `docker exec paladin-postgres-test pg_isready -U paladin -d paladin_waypoint_test`. A failure
  here must fail the job — this is the reachability assertion the gap calls for, and it is what
  distinguishes "the suite ran and passed" from "the suite found nothing and returned".
- Run the suite, with `set -o pipefail` first so `tee` cannot mask a cargo failure:
  `WAYPOINT_POSTGRES_TEST_URL=postgres://paladin:paladin@localhost:5433/paladin_waypoint_test cargo test -p paladin-storage --features postgres --lib waypoint::postgres -- --test-threads=1 --nocapture 2>&1 | tee /tmp/postgres-waypoint-test.log`.
  Two flags are load-bearing and each needs an inline comment. `--nocapture`: the suite announces
  its early return on stdout, which cargo swallows without it, so the detection step below would
  have nothing to read. `--test-threads=1`: this module's tests share one database (unlike the
  SQLite suite's per-test in-memory database), and
  `list_threads_empty_then_three_threads_newest_activity_first` asserts a literally empty store —
  under default parallelism a peer test's writes land inside that assertion's window and the job
  goes red for a reason that is not a real contract violation.
- Detect the early-return path: read `/tmp/postgres-waypoint-test.log`; if the suite's
  unreachable-server marker is present, echo a `::error::` line saying the live server was not
  exercised, print the matching lines, and `exit 1`. Take the marker literal from
  `store_or_skip` in `crates/paladin-storage/src/waypoint/postgres.rs` rather than inventing one —
  read the function and use exactly what it prints.
- Assert a non-empty selection, which the `ollama-integration` job does not do and which this
  gap specifically motivates: parse the `test result: ok. N passed` line out of the log and
  compare `N` against the number of test functions the module declares, counted at job runtime
  with `grep -c '#\[tokio::test\]' crates/paladin-storage/src/waypoint/postgres.rs`. Fail with a
  `::error::` if `N` is lower. Derive the expected number rather than hard-coding it: sibling
  gap-closure plan 22-13 adds contract functions to this same module, and a hard-coded figure
  would go stale the moment it lands. Without this assertion a stale or mistyped filter selects
  zero tests, cargo reports success, and the job is green having run nothing — the exact defect
  this plan closes, one level up.
- `Collect logs on failure` with `if: failure()` running
  `docker compose -f docker/docker-compose.test.yml logs postgres-test`.
- `Stop services` with `if: always()` running
  `docker compose -f docker/docker-compose.test.yml down -v`.
