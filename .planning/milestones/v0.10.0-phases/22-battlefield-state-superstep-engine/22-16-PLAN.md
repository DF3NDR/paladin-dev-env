<objective>
Complete gap G-22-3 by doing the fixture audit ENG-FR-02a acceptance 2a requires, and by
surfacing what that audit finds.

Plan 22-15 added the validation. Acceptance 2a additionally requires that every test or fixture
working around strandedness be revisited, and that no remaining test route around the bug — the
requirement singles out the crash-resume fixture's looping-node arrangement by name. The reason
this clause exists is that the workarounds were the strongest evidence the defect was real: the
tests had been shaped by it.

Planning-time reading of that fixture found something the audit must handle honestly. Its comment
states the arrangement exists because the frontier readiness rule treats a node's own self-edge
as unresolved until the node has executed once — so a node that is both self-looping and fed by
an upstream edge can never execute, and the run still reports completion. That is a second
instance of the same truthful-outcome defect class, reached by a different mechanism, and it is
**not** the one plan 22-15 fixed: such a node is statically reachable and passes the new
validation cleanly. Removing the arrangement would therefore produce a deadlocking graph, not a
cleaner test.

Purpose: finish the audit truthfully — clean up what is genuinely a strandedness dodge, correct
the wording where an arrangement has a different cause, and register the residual defect with a
runnable reproduction instead of letting it disappear into a satisfied checkbox.
Output: a per-fixture audit record, corrected fixtures and comments, an ignored reproduction test
for the readiness defect, and the confirmed pre-release classification.
</objective>
