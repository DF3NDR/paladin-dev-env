# Phase 22.1 Plan 06: Resume restores the Frontier from a persisted snapshot (BUG-04 / ENG-FR-12a) Summary

**Persisted a serializable `FrontierSnapshot` on every `Waypoint`, keyed by edge identity rather than edge index, seeded into the superstep engine's `Frontier` on resume so a pre-crash fired edge into a not-yet-ready join node is never lost -- landed test-first with a genuinely-observed RED proof, proven byte-identical across all three `WaypointPort` backends, and registered as BUG-04 / ENG-FR-12a.**

## Accomplishments

- Fixed BUG-04: `WarEngine::resume_with_options` handed `superstep::run` the Waypoint's Battlefield, Vanguard and visit counts, but `run` always called `Frontier::new(graph)` -- every edge rebuilt `Pending`, `last_executed` empty -- so per-edge resolutions recorded before an interruption were silently discarded. A pre-crash fired edge into a join node not yet ready was never seen again, and the resumed run could report `Completed` without a node the uninterrupted run executes.
- Added `FrontierSnapshot`/`FrontierEdgeState` (`paladin_core::platform::container::waypoint`), additive and `#[serde(default)]` exactly matching `visit_counts`' precedent, plus `canonical_edge_condition()` -- the SAME serde form `WarGraph::fingerprint` already hashes for an edge condition, so an edge that fingerprints as the same edge is also snapshot-keyed as the same edge. `Waypoint::new_root`/`new_child` gain a trailing, explicit `frontier: FrontierSnapshot` parameter (never silently defaulted), so Phase 24's forking path cannot reintroduce this defect.
- Added `Frontier::snapshot`/`Frontier::from_snapshot` (`engine::superstep`, `paladin-battalion`): resolutions are matched onto the (possibly changed) graph strictly by `(from, to, condition)` identity -- never by edge index -- so a snapshot edge absent from the new graph is dropped and a new-graph edge with no snapshot entry starts `Pending`, proven by a dedicated `allow_graph_change` regression test. Every `build_waypoint` call site inside `run()` now passes the CURRENT frontier snapshot, so a `Halted`/`Failed`/limit-tripped `Waypoint` resumes with the same fidelity as a `Running` one.
- Ran the mandated TDD sequence for real: committed the two/three new `engine::tests` end-to-end resume tests alone first (`test(22.1-06)`, `c4dc9859`), confirmed the conditional-join test genuinely FAILED against the unmodified production code (`left: 0, right: 1` -- d never executed), confirmed the equivalence and `allow_graph_change` tests already PASSED at that commit (BUG-03's starvation release masks the divergence for the unconditional shape, exactly as the plan's assumption predicted), then landed the fix as a separate commit (`fix(22.1-06)`, `9cf69ee0`) and re-verified GREEN.
- Proved the frontier survives all three `WaypointPort` backends via two new shared contract clauses (`frontier_survives_save_latest_and_get_round_trip`, `pre_bug_04_payload_without_frontier_loads_with_an_empty_snapshot`), each wired into `InMemoryWaypointStore` (26 tests, was 24), `SqliteWaypointStore` (30, was 28) and `PostgresWaypointStore` (28 declared, was 26) with per-clause `#[tokio::test]` wrappers matching each module's existing style. No SQL migration and no `BATTLEFIELD_SCHEMA_VERSION` change (D-23): all three backends persist the whole `Waypoint` as JSON.
- Registered BUG-04 and ENG-FR-12a in `.project/v0.10.0`'s defect register, traceability matrix and engine PRD, mirroring BUG-02/BUG-03's pre-release classification (no `MIGRATION.md`/`CHANGELOG.md` entry, since the `waypoint` and `engine` modules are both absent at the `v0.9.0` tag). `resume_with_options`' rustdoc now states the restored-frontier guarantee and the `allow_graph_change` degradation rule instead of pointing at the open BUG-04 candidate Plan 22.1-03 had recorded.
- Full verification green: `cargo test -p paladin-battalion --lib engine` (128 passed), `cargo test -p paladin-ai-core --lib platform::container::waypoint` (19 passed), `cargo test --test e2e_crash_resume` (27 passed, `e2e_1_crash_resume_matches_control_run_with_no_reexecution` unmodified), `cargo test --workspace` (0 failed across the whole suite, twice), `cargo fmt --check` and `cargo clippy --workspace --all-targets --all-features -- -D warnings` (both clean).
