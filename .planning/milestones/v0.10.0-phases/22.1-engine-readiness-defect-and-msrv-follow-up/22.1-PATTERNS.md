### `crates/paladin-battalion/src/engine/superstep.rs` — `compute_next_vanguard` (D-03)

**Analog:** same function, same file (lines 737-761) — the existing two-pass structure (normal
ready, then `defer` release) is the exact shape a third "starvation release" pass extends.

**Core pattern to extend** (lines 737-761):
```rust
fn compute_next_vanguard(graph: &WarGraph, frontier: &Frontier) -> Vec<NodeId> {
    let mut ready = Vec::new();
    let mut seen = HashSet::new();
    for edge in graph.edges() {
        let target = &edge.to;
        if graph.is_deferred(target) || seen.contains(target) {
            continue;
        }
        if frontier.is_ready(graph, target) {
            seen.insert(target.clone());
            ready.push(target.clone());
        }
    }
    if !ready.is_empty() {
        return ready;
    }

    let mut deferred_ready = Vec::new();
    for node in graph.node_order() {
        if graph.is_deferred(node) && frontier.is_ready(graph, node) {
            deferred_ready.push(node.clone());
        }
    }
    deferred_ready
    // D-03 inserts pass 3 HERE, gated on `deferred_ready.is_empty()`:
    // scan graph.node_order() for nodes that are !frontier.dead.contains(node),
    // have >=1 incoming edge resolved Fired (fresh, per is_ready's threshold logic),
    // and are blocked only by Pending edges from live, never-executed sources.
    // Release those, ordered by node_order (same discipline defer release uses).
}
```

**Per-edge resolution helper to reuse, not duplicate** (`is_ready`, lines 705-727, and
`edge_resolution`, lines 637-650): both already compute the exact `(any_pending, any_fresh_fire)`
/ `Fired`-vs-`Pending`-from-live-source information D-03's third pass needs. RESEARCH.md's Open
Question 2 recommends factoring a private helper returning per-node edge-resolution state once,
called by both `is_ready` and the new pass, rather than re-deriving the loop:
```rust
fn edge_resolution(&self, graph: &WarGraph, idx: usize) -> Option<(bool, u64)> {
    match self.edge_state[idx] {
        EdgeState::Fired(s) => Some((true, s)),
        EdgeState::NotFiring(s) => Some((false, s)),
        EdgeState::Pending => {
            let source = &graph.edges()[idx].from;
            if self.dead.contains(source) {
                Some((false, 0))
            } else {
                None   // <-- Pending from a LIVE source: this is what D-03's
            }          //     third pass must distinguish from "genuinely blocked"
        }
    }
}
```

**Ordering discipline to copy** (ENG-FR-04, already established by the `defer` release):
iterate `graph.node_order()`, never raw `HashMap`/`HashSet` iteration — the `defer` pass at
lines 754-759 is the direct template.

**Rustdoc pattern to extend** (lines 730-736, the existing doc comment on
`compute_next_vanguard`) — add a third paragraph describing the starvation-release fallback,
mirroring how the existing doc already describes the `defer` fallback as "if no non-deferred
node is executable, releases every defer-marked node... instead."
