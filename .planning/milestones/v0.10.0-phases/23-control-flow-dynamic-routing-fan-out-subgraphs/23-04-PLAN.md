<objective>
Give `NodeSpec::Paladin` a per-node `DirectiveParser` so a Paladin node can emit a routing
`Directive` from its own output, with `PlainOutput` as the backward-compatible default and
`StructuredDirective` parsing a documented JSON envelope under configurable parse-failure handling.

Purpose: CF-FR-06 is what lets an LLM-backed node — not just a Rust `Function` node — steer
routing, which is the whole point of node-driven control flow. The default must be invisible: a
graph that does not opt in must behave exactly as it does today.

Output: a `DirectiveParser` enum with both built-ins, `OnParseError` handling, the parse seam wired
into the Paladin dispatch arm, and every existing Paladin node construction still compiling.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output -> routing directive | A `PaladinResult.output` string — produced by a third-party model — is parsed into state deltas and routing instructions. This is the phase's principal untrusted-input surface. |
| envelope delta -> Battlefield schema | Field names inside the envelope are attacker-influenced strings applied through the schema's dispatch rules; the schema is the allowlist. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-14 | Tampering (of Battlefield state via model output) | `StructuredDirective`'s envelope delta | high | mitigate | The delta is applied through the Battlefield schema's dispatch rules, so only declared fields are writable; an unknown field fails the run as a schema error, asserted by `envelope_delta_naming_an_unknown_field_fails_the_run`. The parser performs no implicit `output_field` write, so a structured node cannot silently overwrite the field a downstream edge condition reads. |
