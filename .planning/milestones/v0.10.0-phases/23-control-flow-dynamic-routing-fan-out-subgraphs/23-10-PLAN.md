<objective>
Bump the graph fingerprint from `v2` to `v3` and hash everything this phase added that changes
scheduling or merge semantics: the worker-template set, each `Battalion` node's child fingerprint
plus `StateMap` plus `restart_on_resume`, and each Paladin node's `DirectiveParser` kind plus

hashed" (22.1 D-15…D-19). This phase added six such properties; leaving any of them out means a
resumed run could silently execute a materially different graph than the one that was checkpointed.
Doing the bump ONCE here, after all three producing plans have landed, avoids re-pinning the golden
digest three times.

Output: `v3`, three new length-prefixed sections, six difference tests, a re-pinned golden, and an
extended exclusion test proving `max_muster_tasks` stays out.
</objective>

  <context>
CONTEXT.md D-18 rates this decision **one-way after v0.10.0 ships**: every Waypoint stores a
`{version}:{blake3_hex}` fingerprint, so once v0.10.0 is released, any later layout change makes
every stored fingerprint mismatch — each affected thread's `resume` then reports a graph-change
rather than continuing. It is free right now only because no released build carries `v3`.
CONTEXT.md was gathered in `--auto` mode, so this door was auto-selected on the recommended default
rather than chosen by a human; this checkpoint is the first human look at it.

The bump itself is also the moment the fingerprint's coverage rule is applied to this phase's six
new scheduling-relevant properties. Under-hashing means a resumed run can silently execute a
materially different graph; over-hashing (for example including `max_muster_tasks`) means a
legitimate operator limit change invalidates every stored thread.
  </context>

      <pros>Applies 22.1's coverage rule consistently ("everything that changes scheduling or merge semantics is hashed"); the version tag makes the layout change detectable rather than silent; a single bump after all three producing plans have landed re-pins the golden digest exactly once; free while pre-release.</pros>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored fingerprint -> resumed run | A Waypoint's `{version}:{digest}` is what a resume trusts to decide the graph has not materially changed; a fingerprint that matches when the graph differs is a silent divergence. |
| graph author -> hashed byte stream | Author-supplied `NodeId`s, `FieldName`s and `StateMap` entries with no charset restriction are concatenated into the hash input, so the encoding must be unambiguous. |
