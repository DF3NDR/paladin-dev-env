  <context>The fingerprint is stamped on every persisted Waypoint and checked by `resume`/`resume_with`/`replay`/`fork` (ENG-FR-14). Bumping it makes every thread suspended under a `v3` fingerprint report `GraphMismatch` on resume rather than being silently reinterpreted.   <options>

      <name>Bump to v4 with a `;gates:` section (recommended)</name>
      <pros>Follows the `v1`→`v2`→`v3` precedent exactly; Gate routing properties (`kind`, `output_field`, `choices`, `on_expire` kind) change scheduling and merge, so ENG-FR-14 requires them hashed; old threads fail closed with a typed `GraphMismatch`.</pros>
      <cons>Every stored `v3` Waypoint becomes non-resumable except through `replay`/`fork` from an earlier point.</cons>
    </option>
    <option id="stay-v3">
      <name>Add the gates section without bumping the version tag</name>
      <pros>No mismatch for pre-existing threads.</pros>
      <cons>Two different hash layouts share one version tag — the exact ambiguity the version tag exists to prevent; contradicts D-09 and the established fingerprint discipline.</cons>
    </option>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| graph author -> `GateRequestTemplate.payload_template` | Author-controlled template output is rendered from the Battlefield and persisted verbatim in the Waypoint |
| expired parley -> `on_expire: ResumeWithDefault(value)` | An author-supplied default value is substituted as if it were a real human response |
| graph redeploy -> stored fingerprint | A changed graph must not be silently reinterpreted against an old suspended thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-24-05 | Information Disclosure | `GateRequestTemplate.payload_template` rendered into a persisted, later HTTP-readable `ParleyRequest.payload` | medium | mitigate | The renderer copies only Battlefield fields the author templated; no engine-held credential is reachable from a template. The graph-author warning ("never template a secret into a Gate payload") ships with the mdBook page in plan 24-12 |
| T-24-06 | Elevation of Privilege | `on_expire: ResumeWithDefault` bypassing an approval gate with an unchecked default | high | mitigate | Task 1 validates the default against its own `ParleyKind` at graph-validate time using the SAME shared per-kind validator `resume_with` calls in plan 24-04 — one validator, not a parallel weaker check |
| T-24-07 | Tampering | Gate routing properties omitted from the graph fingerprint | high | mitigate | `kind`, `output_field`, `choices` and `on_expire` kind are hashed into a sorted, length-prefixed `;gates:` section under a bumped `v4` version tag, so a redeployed graph fails closed with `GraphMismatch` |
| T-24-08 | Tampering | Fingerprint field-boundary collision | medium | mitigate | Every field is written through the existing `push_field` length-prefix helper (the Phase 22.1 CR-01 fix), pinned by a dedicated collision test |
| T-24-SC | Tampering | package-manager installs | low | accept | No new package is installed by this plan; every type is built from `paladin-battalion`'s and `paladin-core`'s existing dependencies |
</threat_model>
