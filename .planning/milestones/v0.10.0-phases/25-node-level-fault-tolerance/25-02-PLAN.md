<objective>

`transience()` on `PaladinError` and `LlmError`, the structured `PaladinError::LlmFailure` and

`semver` CI job.

handler's decision — reads transience **by value**. Until it exists, every later plan would have to
guess from a string.

three allowlist entries, the matching per-crate lint suppressions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider HTTP response -> `LlmError::ProviderError.message` | Remote, attacker-influenceable text becomes a field on a public error type that is later logged and persisted |
| `LlmError` -> `PaladinError::LlmFailure` | A port-layer error crosses into the core-visible error taxonomy carrying provider name, status and message |
| public enum shape -> downstream crates | Marking three published enums non-exhaustive changes what every external consumer can compile |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-06 | Information Disclosure | `ProviderError.message` / `LlmFailure.message` | high | mitigate | The message field is populated only by the shared `map_http_status` helper (plan 25-05), which redacts through `crates/paladin-llm/src/redaction.rs` **before** bounding (D-03, D-34); this plan adds the field and asserts classification never reads it, so no new unredacted path is created here |
| T-25-07 | Tampering | transience classification | high | mitigate | Classification reads typed fields only - a negative grep in this plan's acceptance criteria proves no substring inspection exists on either `transience()` path, so a provider cannot influence retry behaviour by shaping its error text (FT-FR-01) |
| T-25-08 | Spoofing | downstream consumers matching on the enums | medium | accept | Marking the enums non-exhaustive is deliberate-breaking under X-10.6 and registered in §9.2 with an allowlist entry; downstream crates gain a compile error rather than a silent behaviour change, which is the safe failure direction |
| T-25-09 | Denial of Service | `circuit_breaker.rs` behaviour drift | high | mitigate | `is_retryable()` returns `true` for `LlmFailure`, the same answer the legacy `LlmError(_)` arm gave, pinned by `legacy_retryability_predicates_are_unchanged` so the breaker's open/close thresholds cannot shift under the new variant (X-03) |
| T-25-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package: RESEARCH.md's Package Legitimacy Audit records zero proposed packages, verified by direct `Cargo.toml` read |
</threat_model>
