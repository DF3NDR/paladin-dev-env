<objective>
Make the Aegis a validated part of the graph contract: the `EngineRegistries` bundle, the
`RetryPredicateEvaluator` and `ErrorHandler` trait objects with fail-closed registration, the
node-kind support matrix, and the `v4` -> `v5` fingerprint change that hashes the routing- and
merge-affecting parts of an `Aegis` while excluding the tuning parts.

Purpose: every later plan (retry expansion, timeouts, handlers, cache) assumes that by the time a
node runs, its policy has already been checked — unregistered names rejected, unsupported node kinds
rejected, undeclared annotations rejected. That check has to exist before the behaviour it guards.

Output: two new registry modules, one bundle type, the extended `WarGraph::validate` matrix, and a
fingerprint at `v5` with its goldens re-pinned.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| graph author -> `Custom(name)` string | An author-supplied name selects executable behaviour through a registry lookup |
| stored `GraphFingerprint` -> `resume` | A persisted hash decides whether a stored Waypoint may continue against the in-process graph |
| parent engine registries -> child Battalion graph | A child subgraph resolves names against the parent's registry set |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-10 | Elevation of Privilege | `RetryPredicate::Custom` / `ErrorHandlerSpec::Custom` resolution | high | mitigate | Fail-closed at graph validation before any node executes, listing every offender (D-13, CF-01); a name never resolves to a default, and there is no dynamic registration path after validation |
