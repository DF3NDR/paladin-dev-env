The guide must state four limitations plainly rather than leave them to be discovered:

1. **The idle-timeout degradation.** An `idle_timeout` on a node whose `PaladinPort` does not
   implement `execute_observed` degrades to a per-attempt wall clock, because a port that reports no
   progress genuinely claims none (D-19).
2. **The `Append`-dispatch cache replay hazard.** Caching a node whose output field uses `Append`
   dispatch is allowed, but a fork replays the append; the schema-level `cache: Deny` marker is the
   opt-out (FT-FR-20).
3. **Author-visible state carries raw content.** An `error_field` written by a `Route` handler, and a
   Waypoint payload, inherit the existing M-B-04 raw-content warning — a downstream node or LLM call
   reading them is reading provider-influenced text (D-34).
4. **R-23-01 remains accepted.** A hanging `EdgeConditionEvaluator` is still unbounded: per-attempt
   timeouts wrap node execution, not edge evaluation. State this in the guide's own words, matching
   `23-SECURITY.md`'s wording, rather than letting the new timeout machinery read as coverage it does
   not provide (D-34).

Also record the node-kind support matrix (D-12) — which policies each node kind accepts and why
`retry`/`cache` are rejected on a Battalion node and any Aegis on a Gate node — and the security rule
that every provider excerpt entering an error is redacted before it is bounded.

Register the page in `docs/src/SUMMARY.md` immediately after the Parley entry at line 24, matching the
neighbouring entries' indentation and link form.
