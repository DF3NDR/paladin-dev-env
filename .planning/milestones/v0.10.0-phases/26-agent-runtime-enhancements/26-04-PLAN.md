`pub struct Namespace(Vec<String>)` — a newtype with a private field so the invariants cannot be
bypassed. `Namespace::new(segments: Vec<impl Into<String>>) -> Result<Self, VaultError>` and
`Namespace::parse(&str) -> Result<Self, VaultError>` both validate: 1–16 segments; each segment
1–64 characters; no segment contains `/`; no segment is `.` or `..`; no segment contains a control
character. Count characters, not bytes (a multi-byte segment must not be rejected for being long in
bytes). `Display` joins with `/`. `segments(&self) -> &[String]` for read access.
`is_prefix_of(&self, other: &Namespace) -> bool` compares `self.0` against `other.0` **element by
element** and returns true when `self` is equal to or an ancestor of `other`. Its rustdoc states, in
one sentence, why a string comparison is wrong here and names the sibling case
`["user","alice"]` vs `["user","alice2"]` as the concrete counterexample — this is the security
primitive and the comment is the reason a future reader will not "simplify" it.

`pub struct VaultRecord { namespace: Namespace, key: String, value: serde_json::Value, created_at:
