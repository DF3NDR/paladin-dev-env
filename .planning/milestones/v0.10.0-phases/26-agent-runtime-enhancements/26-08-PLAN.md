<objective>
Ship the `Guardrail` middleware: named rules that screen outbound prompt sections and inbound
responses with a regex or a code predicate, and act by failing with a structured error, redacting in
place, or finishing the run with a fixed message.

Purpose: RT-FR-07 is the phase's only user-facing content-control surface, and it is the one place a
config-supplied pattern reaches a matching engine — so the pattern-size bound and the "why this is
not a ReDoS surface" argument have to be built in and written down at construction time rather than
assumed.

Output: `middleware/guardrail.rs` with `Guardrail`, `GuardrailRule` and its three enums; the new
`PaladinError::GuardrailTripped { rule, target }` variant.
</objective>

Implement `ExecutionMiddleware` for `Guardrail`. `before_model` iterates the rules whose target is
`Prompt` or `Both` in declaration order, applying each to the `PromptAssembly`'s text-bearing parts
**individually** (system, retrieved context, each history entry's content, input, accumulated output,
each `PromptSection`'s body) — this is why D-02 made the buffer structured; a redaction must land in
the section it matched rather than in an opaque blob. `after_model` does the same for rules targeting
`Response` or `Both` over `resp.content`.

Action semantics: `Redact(r)` replaces every match with `r` in place and continues to the next rule,
so a later rule sees the redacted text (state this — it is the only ordering question a reader will
have). `Fail` returns `MiddlewareFlow::Fail(PaladinError::GuardrailTripped { rule, target })`
immediately. `Finish(msg)` returns `MiddlewareFlow::Finish(FinalResult { output: msg,
stop_reason: StopReason::Completed })` immediately — deliberately `Completed` rather than a new
`Guardrail` variant, which is a Deferred Idea (D-09). Document the "first terminal action wins,
redactions accumulate" rule on the struct.

Guardrail holds no per-run state, so nothing goes on the context (D-03) — the compiled patterns are
immutable and shared, which is exactly why the middleware is a plain `Arc<dyn>`.

Test 7 is the local echo of the phase's empty-chain invariant: an installed-but-non-matching
guardrail must be observationally identical to no guardrail, including the rendered prompt bytes.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-supplied regex → the matching engine | Config text becomes a compiled program run against every prompt and response |
| model response content → the response screen | Provider-controlled text crosses into a matcher and into a rewritten output |
| guardrail rule name → `PaladinError::GuardrailTripped` | An operator-chosen string enters an error a caller may log |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-04 | Denial of Service | a config-supplied `Guardrail` regex | medium | mitigate | Two layers, both written down: the `regex` crate is a finite-automata engine with no backtracking and guarantees linear-time matching against any haystack, and every pattern is compiled through `RegexBuilder::size_limit(pattern_size_limit_bytes)` with an explicit documented default rather than the crate's generous internal ceiling (D-09, RESEARCH Pitfall 5). Compilation happens once, at construction, with a typed failure — an unparseable or oversized pattern can never reach a run. Substituting `fancy-regex` would invalidate the first layer and is a recorded prohibition. |
| T-26-30 | Information Disclosure | a redaction that misses because the prompt was flattened first | medium | mitigate | Screens run over the `PromptAssembly`'s individual text parts before rendering, so a match cannot straddle a section boundary and a redaction lands where it matched (D-09, D-02); `prompt_screen_redacts_in_the_matching_section` asserts the untouched section is byte-identical |
| T-26-31 | Information Disclosure | an operator rule name echoed into an error | low | accept | `GuardrailTripped.rule` carries the operator's own configured rule name, which is not secret material and is the only useful identifier for diagnosing a trip; no matched *content* is included in the error |
| T-26-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package; `regex 1.12.3` is already a workspace dependency |
</threat_model>
