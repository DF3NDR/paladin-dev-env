<objective>
Ship the two assembly-mutating, best-effort middlewares: `SummarizationMiddleware`, which compresses
an over-long conversation into a compounding Garrison summary and degrades to trimming rather than
failing, and `VaultRecallMiddleware`, which injects top-k long-term memory into a clearly delimited
section on the first model call of a run.

Purpose: both are the "never break the run" class. Summarization is the only feature in the phase
that makes its own model call, so its failure path has to be self-sufficient — degradation cannot
depend on another middleware being installed. Recall is the point where model-controllable stored
text re-enters a prompt, so its framing is a security control, not presentation.

Output: `middleware/summarization.rs`; `middleware/vault_recall.rs`; the latest-summary-wins
effective-history rule in the service's assembly construction.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored Vault content → the prompt | Text an agent itself may have written re-enters a later prompt |
| conversation history → the summarizer's own model call | User- and model-authored text is sent to a second model and its output is persisted |
| summarizer output → Garrison → every future prompt | A model's summary becomes durable context |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-02 | Tampering | prompt injection via recalled Vault content | high | mitigate | Recalled entries are rendered in their own delimited `## Long-term memory` section, after RAG context and before history, with a fixed preamble stating they are stored notes and not instructions (D-25, D-41). The preamble is a single named constant asserted by `section_frames_entries_as_stored_notes`, and the section is a structured `PromptSection` so it can never be concatenated into the system prompt. The guide inherits M-B-04's raw-content warning for anything an agent `vault_put`s. |
| T-26-49 | Tampering | a model-authored summary becoming durable, trusted context | medium | mitigate | The summary is stored as a `ConversationRole::System` Garrison entry flagged `is_summary`, carried in the history region rather than the system prompt, and `metadata["summarized_through"]` records exactly which entries it stands for — so a bad summary is traceable to its inputs rather than anonymous (D-16) |
| T-26-50 | Denial of Service | a failing summarizer stalling or failing runs | medium | mitigate | Any summarizer error degrades to the embedded trimmer, sets `scratch["summarization.degraded"]`, warns, and returns `Continue`; degradation is self-sufficient and does not depend on another middleware being installed, pinned by `degradation_does_not_depend_on_chain_order` (D-16) |
| T-26-51 | Denial of Service | a per-run warning storm from an unsupported search | low | mitigate | `VaultError::Unsupported` is a deployment fact, not a per-run event: it warns once per service instance and skips thereafter (D-25) |
| T-26-05 | Denial of Service | a hanging summarizer model call | medium | accept | Like any hook, the summarizer's call is bounded only by the node's Aegis `run_timeout` and the service's per-run timeout; D-41 records this as stated-not-solved, and a per-hook timeout is a named later decision |
| T-26-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package |
</threat_model>
