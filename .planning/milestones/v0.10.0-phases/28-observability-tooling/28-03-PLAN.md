<objective>
Make the engine emit the four variants only it can produce, and expose the one `seq` authority to the
producers that live below it. `EdgeEvaluated` at the edge-condition call site, `ParleyRaised` at the
`AwaitingInput` construction, rate-limited `NodeProgress::Heartbeat` at the idle-timer receiver, and a
fully-populated `RunFinished`; plus `muster_task_key` on `NodeStarted` and the real outcome, duration
and token count on `NodeFinished`, and `WarEngine::trace_emitter()`.

Purpose: OBS-01 / OBS-FR-01, per D-03 and D-04. `edge_fired`, `parley_raised` and `total_tokens_max`
assertions in the eval harness (28-08) and the exact fired/evaluated edge sets in the overlay (28-10)
are only possible once these exist.

Output: an engine whose trace stream is the complete account PRD 07 §2.1 specifies, and the
`trace_emitter()` handle 28-06 hands to the fallback adapter, the middleware chain and the execution
service.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Battlefield field values → `DeltaMerged` payload | Opt-in value inclusion moves potentially sensitive state into an observability record. |
| Node heartbeat loop → trace queue | An adversarial or buggy node could flood the bounded queue and evict real events. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-28-03-01 | Information disclosure | `FieldChange.value` when value inclusion is enabled | high | mitigate | Redact through `crates/paladin-llm/src/redaction.rs` BEFORE truncating to the configured cap, per the security-instructions ordering rule; default is names-and-sizes only (D-05). |
| T-28-03-02 | Denial of service | Heartbeat flood evicting real events from the bounded queue | medium | mitigate | Per-node last-emitted rate limit at the configured interval, tested at the interval boundary under a paused clock (D-04). |
| T-28-03-03 | Information disclosure | `ParleyRaised` carrying prompt text | medium | mitigate | The variant carries `parley_id`, `node_id` and `kind` only — no `prompt`, no author-supplied context. |
| T-28-03-04 | Repudiation | `RunFinished` unable to distinguish success from failure | medium | mitigate | `status` derived from the `RunOutcome` arm, table-tested across all four (D-02, closing 27-CONTEXT D-25's correction). |
</threat_model>
