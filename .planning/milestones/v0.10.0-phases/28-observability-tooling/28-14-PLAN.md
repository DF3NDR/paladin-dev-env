<objective>
Give the web layer a way to ask "what happened on this thread" without learning the graph vocabulary:
a core-typed `RunInspectorPort` in `paladin-ports` and its facade implementation over the execution
overlay, Waypoint history and persisted traces.

Purpose: OBS-03 / OBS-FR-10's data half, per D-24. ADR-0031 forbids `paladin-web` depending on
`paladin-battalion` in the default build, and 27-CONTEXT D-27 set the pattern this copies: a
core-typed input port is the only channel in.

Output: `crates/paladin-ports/src/input/run_inspector_port.rs` and
`src/application/services/run/inspector.rs`.
</objective>

From 28-10: `ExecutionOverlay { visits, fired_edges, evaluated_edges, source, observed_only }`,

(`crates/paladin-ports/src/output/waypoint_port.rs:212`); `Waypoint { vanguard, completed, status,

cache_hit }` (`crates/paladin-core/src/platform/container/waypoint.rs:526-680`). Diffing consecutive
Waypoints' Battlefields BY FIELD NAME is how `field_changes` is derived when no trace is persisted.

ADR-0016: core owns port value types and ports re-export. ADR-0038: port parameter types are core
types.

The UI-SPEC's four panels consume exactly these fields — the diagram from `mermaid`, the visits panel
from `visits`, the fired-edge panel from each `SuperstepRow.fired_edges` plus the overlay's
`evaluated_edges`, and the superstep table from `supersteps`. Anything the page needs that is not on
this view is a gap in this plan, not something the page may compute itself.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stored execution history → `InspectorView` → web layer | Internal run structure crosses toward an HTTP surface. |
| `ThreadId` from a web request → storage reads | A caller-supplied identifier drives history reads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-28-14-01 | Information disclosure | State field VALUES reaching the view | high | mitigate | `field_changes` is `Vec<FieldName>` by type, and `serialized_view_contains_no_field_values` proves it for a whole serialized view; there is no configuration that changes this. |
| T-28-14-02 | Elevation of privilege | `paladin-web` gaining an engine dependency to render the diagram | high | mitigate | The `mermaid` string is rendered facade-side and handed over as text; the port's types are core-only, asserted by a zero-occurrence check on the battalion crate in the port file and its manifest (ADR-0031). |
| T-28-14-03 | Information disclosure | A thread id acting as a capability | medium | mitigate | The port documents, as `waypoint_port.rs` does, that `ThreadId` is not an authorization boundary; the route's admin auth layer is 28-15's control. |
| T-28-14-04 | Repudiation | A derived overlay presented as exact through the view | medium | mitigate | `source` and `observed_only` are carried on the view and the page labels the Waypoints-only case explicitly. |
</threat_model>
