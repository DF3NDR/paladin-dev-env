<objective>
Wire both consumers to the shared resolver so the two precedence walks become one. `Commissary::new`
calls it once with the strict policy and an absent config table, stores the resolved count, and maps
the resolver's refusal into its own pre-existing undeclared-window error with byte-identical wording
(D-03, D-04). `HistoryTrimmer::resolve_limit` becomes a call-through with the lenient policy, and the
facade's local three-variant source enum is deleted in favour of the shared one (D-05, the promote
decision recorded in plan 32-02's assumption-delta block).

Purpose: until both consumers actually call it, the shared resolver is a third implementation rather
than a replacement for two. This plan is where the duplication is removed, and the equivalence
fixtures committed green in plan 32-02 are what prove the removal changed no behaviour — Commissary
resolves the same windows, HistoryTrimmer produces the same trims.

Output: one precedence walk in the workspace, consumed by a strict caller and a lenient caller; six
untouched equivalence fixtures still green; three untouched precedence tests still green; and no
inline fallback expression left in either consumer.
</objective>
