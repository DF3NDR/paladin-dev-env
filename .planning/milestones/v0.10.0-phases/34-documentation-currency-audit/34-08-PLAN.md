<objective>
Measure and settle the examples partition: build status for every program under the exact feature
sets CI splits on, plus a three-check currency verdict per program, plus the gap list of Phase
22-33 capabilities that no example demonstrates.

Purpose: ROADMAP Success Criterion 3 asks for build status *and* currency — a program can build
perfectly while demonstrating an API that no longer exists in the shape the example shows, and a
capability can ship with no example at all. The gap list is the part Phase 36 cannot reconstruct
from a build log.
Output: `34-AUDIT.md` §4 — the build/currency table, the `examples/README.md` audit, the
`doc-examples` include map, and the capability gap list — with `EX-nn` IDs and D-04 sizes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository working tree → git commit | `cargo build --examples` writes into `target/` (gitignored); a commit carrying an edited example falsifies SC5 and the read-only premise |
| example source and build output → `34-evidence/` | Example programs carry API-key placeholders and endpoint URLs; build captures are committed verbatim |
| a live-vendor example → the network | `live_vendor_smoke` reaches a real provider and needs a credential if run |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-01 | Tampering | phase commits, `examples/`, `crates/`, `Cargo.toml` | high | mitigate | Both task verifies require `git status --porcelain -- examples crates Cargo.toml` empty in addition to the `':!.planning'` check — an obsolete example is recorded, never quietly corrected (D-00c, D-22) |
| T-34-02 | Information Disclosure | `34-evidence/34-08-examples-builds.txt`, obsolete-API grep hits quoted into rows | high | mitigate | `live_vendor_smoke` is built, never run, so no credential is loaded and no vendor response is captured; no provider environment variable is exported by any command in this plan. Grep hits are quoted as `file:line` plus the matched identifier, never a whole line that might carry a key. Before commit the capture and the audit diff are grepped for key-shaped tokens (`sk-`, `_API_KEY=`) and any hit is redacted before the surrounding text is truncated, per the house rule in `crates/paladin-llm/src/redaction.rs` |
