<objective>
Close the one ledger row Phase 36 left open: make the run-failing tool-error policy produce the
sanitized reason its own doc contract promises, on both arms, with a test that fails if either arm
regresses.

This is the phase's only security-relevant change. The project's security instructions make
redact-before-bound the primary manual control for credential-handling code, and the failing arm
currently bypasses it entirely — a tool or provider error body carrying an API key reaches a
structured error surface verbatim. The fix is bounded by design: one existing helper reused, one
visibility widening that stops at crate scope, no public item touched.

Decisions honoured: D-03 (both run-failing arms route the reason through the formatter's own
sanitizer, widened from private to crate visibility only, never public; not through the
model-facing formatter entry point, which would garble the error's Display; one pinning test that a
secret-shaped tool error does not appear raw; `make api-surface` unchanged), D-00j (Phase 36's
docs-only boundary is why row 38 was filed open rather than fixed — that boundary was Phase 36's,
and this phase owns the row), D-27 (nothing under `src/` or `crates/` changes except the two arms,
the widened sanitizer and their test), D-28 (`fix(36.1):` subject).

Purpose: `/gsd-ship` blocks while the ledger's open count is above zero, the row is unowned, and
Phase 37 is the release. Waiving it would leave a documented contract contradicted by the tree on
the tag commit.

Output: a sanitized reason on both arms, a pinning test that proves it, and an unchanged public API
baseline.
</objective>
