## Accomplishments

- `ScheduleService`'s doc comment now carries a `# Examples` section that constructs the service from `paladin_storage::run_schedule::in_memory::InMemoryRunScheduleRepository` and a minimal local `RunSubmissionPort` implementation (no shipped in-memory adapter exists for that port), then calls `tick_once()` once and asserts it processes nothing — a single call that needs no live backend, proving the wiring is load-bearing rather than merely type-checking.
- `WebhookDeliveryService`'s doc comment now carries a `# Examples` section that constructs the service from `paladin_storage::webhook::in_memory::InMemoryWebhookDeliveryRepository` and `paladin_storage::run::in_memory::InMemoryRunRepository`, wrapping construction in a fallible entry function (`fn build() -> Result<WebhookDeliveryService, Box<dyn std::error::Error>>`) that propagates `WebhookDeliveryService::new`'s `Result` with `?` — the constructor's fallibility (it builds its own no-redirect HTTP client) is now visible to a reader instead of being unwrapped away.
- Re-measured `cargo doc --workspace --no-deps` after both sections landed: still zero warning lines (ADR-0033 bar unaffected), captured to `36.1-evidence/36.1-08-services-measure.txt`.
- `bash scripts/check-public-api-examples.sh --list` now reports both items `OK`; the `TOTAL` MISSING count for the whole workspace dropped from 7 to 5, matching this plan's two-item scope.

## Decisions Made

- The `ScheduleService` example exercises `tick_once()` once against an empty repository (asserting the outcome vector is empty) rather than stopping at bare construction — D-10's "no skipped block teaches nothing" concern is best answered by a call that actually runs, not just a value that type-checks.
- The `WebhookDeliveryService` example deliberately stops at construction (no `run_once` call) — D-10 asks for construction from port dependencies for a service example, and the fact this example exists to surface is the constructor's fallibility, which a `run_once` call would not add evidence for.
- Both examples reuse existing shipped shapes rather than inventing new ones: the inline `RunSubmissionPort` implementation is a direct copy of the port's own doctest fixture (`AlwaysAccepts`, already present from plan 36.1-05..07), and both in-memory adapters are the ones the plan's `read_first` pointed at.

## Deviations from Plan

None - plan executed exactly as written. Both examples use plain compiling fences (not `no_run`), since neither construction path performs real I/O: `InMemoryRunScheduleRepository`/`InMemoryWebhookDeliveryRepository`/`InMemoryRunRepository` are in-process stores, and `WebhookDeliveryService::new`'s HTTP-client build (`reqwest::Client::builder()...build()`) does not connect anywhere.
