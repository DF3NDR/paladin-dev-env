## Decisions Made
- **RunEventStreamService's registries-analog collaborator (the event bus) needed no fallback.** `RunEventBus::new()` is a plain zero-argument constructor declared in the same file, so the example uses it directly.
- **The example stops at construction, never calling `stream()`.** The plan's own threat register (T-36.1-39) forbids awaiting a stream event in a doctest; `Arc::strong_count(&bus) == 2` (one held by the caller, one moved into the service's own `bus` field) is the cheap, synchronous, real property asserted instead.
- **AssistantService's unverified registries construction path turned out to have a real zero-argument constructor.** Reading `crates/paladin-battalion/src/engine/registries.rs` showed `EngineRegistries` derives `Default` and ships `EngineRegistries::new() -> Self { Self::default() }` — no `not-run` fence, and no production constructor needed to be added. The example builds an empty bundle (no `Custom`/`Registered` names pre-registered) since it validates no Workflow body.
- **AssistantService's example makes one real async call (`list`) beyond construction**, per the task's "at most one cheap call" allowance, to prove end-to-end wiring rather than construction alone.

## Deviations from Plan

None - plan executed exactly as written. Both registries/collaborator questions the plan flagged as "unverified" resolved to real, ship-quality construction paths on inspection, so no not-run fallback fence was needed for either task.
