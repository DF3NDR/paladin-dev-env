## Pattern Assignments

### `src/application/services/paladin/paladin_execution_service.rs` — both `FailRun` arms (service, error-handling)

**Analog:** the sibling `FeedToModel` arm in the same `match self.effective_tool_error_mode(...)` block, at both call sites (lines 1637-1653 handoff arm; 1756-1774 regular Arsenal-tool arm).

**Current (defective) shape, both arms:**
```rust
match self.effective_tool_error_mode(&effective_function_call.name) {
    ToolErrorMode::FeedToModel => {
        self.formatter.format_error(&effective_call, &e.to_string())
    }
    ToolErrorMode::FailRun => {
        return Err(PaladinError::ArmamentFailed {
            tool: effective_function_call.name.clone(),
            reason: e.to_string(),               // <-- raw, unsanitized
        });
    }
}
```

**Fix pattern to copy** — do NOT call `self.formatter.format_error(...)` (it returns a full
multi-line "🔧 Tool Execution: …\nResult: FAILED\n…\nYou may retry…" block, wrong shape for a
`reason` field). Instead call the sanitizer directly as an associated function (no `&self`):
```rust
ToolErrorMode::FailRun => {
    return Err(PaladinError::ArmamentFailed {
        tool: effective_function_call.name.clone(),
        reason: crate::infrastructure::adapters::arsenal::tool_result_formatter::ToolResultFormatter::sanitize_tool_text(&e.to_string()),
    });
}
```
Apply the identical change to the second arm (lines 1756-1774), substituting
`effective_call.tool_name.clone()` for the tool name per that arm's existing variable.

**Visibility change (`tool_result_formatter.rs`):**
```rust
// Line 273 — was `fn sanitize_tool_text`, now:
pub(crate) fn sanitize_tool_text(text: &str) -> String {
    let redacted = paladin_llm::redaction::redact_secret_patterns(text);
    paladin_llm::redaction::bounded_excerpt(&redacted, paladin_llm::redaction::RESPONSE_EXCERPT_CHAR_BUDGET)
}
```
`pub(crate)` only — never `pub` — both files are in the same crate (facade already imports
`ToolResultFormatter` at `paladin_execution_service.rs:78`), so `cargo public-api`/`make
api-surface` never lists it; confirmed in RESEARCH.md D-03 feasibility section.

#[test]
fn format_error_redacts_a_secret_in_the_reason_before_bounding() {
    let formatter = ToolResultFormatter::new();
    let call = ArmamentCall::new("fetch_report", HashMap::new());
    let reason = "upstream rejected: Authorization: Bearer sk-live-abcdef0123456789";

against the format_error-instead-of-sanitize_tool_text mistake). Cover both arms — one test per
call site, or one test parameterized/duplicated across the handoff vs. regular-tool paths.

### `tests/cli_isolation_test.rs::test_cli_feature_is_not_default` (test, file-I/O)

**No direct in-repo analog for TOML-manifest-reading tests** — this is new ground, but fully
specified. Use the `toml` crate (already a regular dependency, `Cargo.toml:180`) rather than a
hand-rolled scanner (Don't-Hand-Roll table, RESEARCH.md).

**Pattern (from RESEARCH.md D-15 sketch, Claude's Discretion on exact body):**
```rust
#[test]
fn test_cli_feature_is_not_default() {
    let manifest_path = concat!(env!("CARGO_MANIFEST_DIR"), "/Cargo.toml");
    let manifest_text = std::fs::read_to_string(manifest_path)
        .expect("root Cargo.toml must be readable");
    let manifest: toml::Value = manifest_text.parse()
        .expect("root Cargo.toml must be valid TOML");
    let default_features = manifest
        .get("features")
        .and_then(|f| f.get("default"))
        .and_then(|d| d.as_array())
        .expect("[features] default must be an array");
    let names: Vec<&str> = default_features.iter()
        .filter_map(|v| v.as_str())
        .collect();
    assert!(
        !names.contains(&"cli"),
        "The `cli` feature must not be in [features] default. Saw: {names:?}"
    );
}
```
Keep the panic message's current first sentence; append the parsed `default` list. The other
8 tests in the file are untouched. The `//!` file header gains two sentences explaining why the
guard reads the manifest rather than `cfg`.
