<objective>
Re-run D-06's seventh and heaviest gate — the workspace publish dry run — and close the Local
sweep with an honest verdict tally that distinguishes local passes from the one gate this
devcontainer structurally cannot measure.

Purpose: gate row 6 is the packaging proof behind SC1 and the local analogue of the real publish;
it gets its own plan because `make publish-dry-run` first runs the whole `release-check` chain
(`clean-code` → workspace tests → doc tests → `cargo audit` → `build-release`) and then packages
and verify-builds twelve crates under `target/package/`. That is the disk-hungry, long-running
gate, and the volume this repository lives on is nearly full.

**Free-space threshold (stated, and why):** gate row 6 is attempted only with **at least 40 GiB**
free on `/workspace`. Justification: `release-check` adds a full `--release` build on top of the
existing debug and coverage artifacts, then `cargo publish --workspace --dry-run` packages and
verify-builds twelve crates; a single cold build of this workspace's dependency graph measures
about 16 GB in this repository (the recorded size of a cold worktree `target/`), so the gate needs
headroom of at least twice a cold graph build plus the packaging artifacts. Below that, an ENOSPC
part-way through the chain would have to be read as a red gate under D-14 — which is exactly the
ambiguity this precondition exists to prevent. If the precondition is unmet the executor stops and
the maintainer decides: free space elsewhere, prune specific `target/` subtrees, or accept the
risk knowingly. **The agent never runs `cargo clean`** — it invalidates the maintainer's IDE state
and costs hours.

Output: Local sweep gate row 6, the adjacent-check rows (`make security`, `make api-surface`), and
the closing "Summary and what remains" prose that names the CI-attributed gate explicitly.

Governing constraints: sequential execution on the main checkout with hooks ON; the phase
prohibitions P1-P5 in `37-01-PLAN.md` apply; D-14 is the operating rule (a red gate halts the
phase and nothing is fixed).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| working tree → packaged crate | `cargo publish --dry-run` packages exactly the tracked tree; a dirty or partially-restored tree would package something no reviewer saw |
| dependency graph → `cargo audit` / `cargo deny` | Advisory and licence data is fetched from RustSec and evaluated against the committed allowlists; a suppression without a reason is an unowned risk |
| local pass → release authority | The Local sweep is the evidence basis for the §12 audit section a human signs; an unlabelled CI-attributed gate would read as a local pass it never was |
