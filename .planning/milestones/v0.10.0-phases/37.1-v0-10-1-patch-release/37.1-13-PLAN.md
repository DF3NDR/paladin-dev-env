<objective>
Prove on the registry itself that the release is coherent — every publishable crate at one version,
none yanked — and capture the first observable evidence of the trusted-publisher link.

Purpose: the previous attempt's failure was invisible in the shape people usually look at. A
workflow log can say a lot of encouraging things while three crates out of twelve are actually
published. The index is the only place that answers the question directly, and it answers it
without a credential. This plan also establishes the precondition the orphan decision depends on:
the three previously-orphaned versions are only safe to yank once every crate resolves at the new
version and none is yanked.
Output: a registry table with one row per derived publishable crate, the trusted-publishing proof,
and the pre-yank orphan reading.

Governing constraints: D-00f (derive, never hard-code), D-00g (trusted publishing, no credential),
D-00h (the index read is the proof), D-01 (the yank precondition).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the workflow's log → what is actually on the registry | The previous attempt's partial publish is the reason a log is not accepted as registry proof; the index read is the only direct answer |
| a documented crate count → the derived crate set | Documentation in this repository already carries a stale crate count; deriving from the tree is the control |
| this environment → the registry's write surface | Every read here is unauthenticated; no credential exists, and introducing one would create a standing secret this project deliberately does not have |
