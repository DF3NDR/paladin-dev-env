## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a requirement's literal text → its checkbox | Ticking a requirement whose text never became true makes the requirements file unreliable as a record, which is the only thing it is for |
| a plan that was never executed → the record | Deleting it hides that it existed; executing it now would redo work this phase already did against a superseded target |
| tooling handlers → the state file's front matter | Some handlers rewrite that file and drop keys; the mutation is correct and the collateral damage is real |
| bookkeeping edits → verification freshness | Editing a summary or evidence file after a verification has run makes that verification describe a file that no longer exists in that form |
