# Phase 37.1: v0.10.1 Patch Release Verification Report

**Phase Goal:** v0.10.x is actually released — every publishable crate resolves on crates.io at
one coherent version. Tag `v0.10.0` (on `main` merge commit `1d4a9724`) published only 3 of 12
crates before `publish-crates` failed deterministically at `paladin-battalion`. The correction is
a `0.10.1` patch release through the same pipeline via Trusted Publishing, with the two defects
that broke `v0.10.0` fixed and a gate that would have caught them.

**Verified:** 2026-09-23
**Status:** passed
**Re-verification:** No — initial verification

**Note on method.** This is a release-mechanics phase. Its deliverables are (a) a small set of
tree changes (a new gate script + test, a manifest fix, a shell-script fix + test, Makefile/CI
wiring, version/changelog/migration bumps, and docs/register updates) and (b) remote state (a
pushed tag, a completed release workflow run, crates.io registry entries, two merged PRs, a
bannered GitHub Release). Every claim below was checked directly: tree claims by reading the
files and running the actual gate scripts, test suites and `make` targets locally; remote claims
by live, read-only `git`, `gh` and `curl` queries against GitHub and crates.io — never by
re-reading SUMMARY.md prose or trusting the workflow's own log as the only witness. No mutating
command (commit, push, tag, yank, publish, dispatch, merge, release edit) was run.
