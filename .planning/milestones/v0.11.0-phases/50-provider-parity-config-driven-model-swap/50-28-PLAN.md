<objective>
Settle what plan 50-26 carried. A billed-but-failed call's usage (and, behind the pricing decorator, its cost) now
rides on `LlmError`, but the agent loop converts the error to `PaladinError` and returns, so the platform-run ledger
never sees the bill. This plan settles it, buffered and streamed, and folds it into the run's tallies.

Purpose: the owner's binding UAT-5 instruction for row 74: Treasurer pricing, the ledger and the allowance checks
reflect what the vendor charges, failed but billed calls included. The Treasurer reads only ledger balances (debug
Evidence 00:50), so a charge that never settles never counts.
Design note (2026-10-17 owner scope decision): the bill is carried beside the error inside the execution service, not
on a new `PaladinError` field. Plan 50-29 reports every call's spend to the Battalion engine through an attempt spend
scope, which also covers attempts that end in a non-LLM error or a timeout that drops the attempt future, so no
`PaladinError` shape change is needed anywhere.

Output: a private `CallFailure`, the buffered and streamed settle of billed failures, and their tests.
</objective>
