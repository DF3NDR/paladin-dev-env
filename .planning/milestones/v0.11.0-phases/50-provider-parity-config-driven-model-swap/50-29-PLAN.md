<objective>
Count the spend of a Battalion engine attempt however it ends. Today a failed attempt records
`(TokenUsage::default(), None)`, and an attempt the engine's deadline cuts off is dropped with its partial work, so
the calls the Paladin had already made and been billed for never reach the superstep's settle. Under
`PlatformRunsOnly` that settle is the only one an engine node gets (LEDGR-04), so those charges never count.

Purpose: G-50-5a remainder (b), brought into Phase 50 by the owner on 2026-10-17: billed counts must not be lost for
the Treasurer, whatever error ends the run.
Design note: the owner asked to extend the spend slot to every error path "as needed". A field on each `PaladinError`
variant would change most of the enum, and could never report spend for an attempt the engine's deadline drops, so the
slot is an attempt spend scope instead: an `IncurredSpend` accumulator the engine installs per attempt and the
execution service feeds at every fold. No `PaladinError` shape changes, so no further break needs registering.

Output: `IncurredSpend`, the `spend_scope` module, the engine reading it for failed, timed-out and structured
attempts, and the execution service recording every call.
</objective>

<flagged_assumptions>
- A1-50-29: a successful Paladin attempt keeps `PaladinResult.cost` (the whole run's tally, equal to what it recorded),
  so success accounting is byte-for-byte unchanged; only failed and timed-out attempts and the structured arm read the
  scope. That keeps one source per outcome and rules out a double count.
- A2-50-29: each attempt gets a fresh scope inside `race_attempt`, which runs inside the node's own spawned task, so
  concurrent nodes and retries never share one, the same per-task isolation `RUN_TRACE_EMITTER` relies on.
- A3-50-29: a nested Battalion node's child engine installs its own scopes for its own attempts; the parent's attempt
  scope sees nothing from them, so this plan neither adds nor double-counts a child run's spend (unchanged behaviour).
- A4-50-29: callers outside the engine see no change. A direct `PaladinPort` caller that wants a failed execution's
  spend can install a `SpendScope` itself; the rustdoc shows how.
</flagged_assumptions>
