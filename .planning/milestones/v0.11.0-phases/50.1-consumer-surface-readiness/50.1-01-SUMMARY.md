### Auto-fixed Issues

**1. [Rule 3 - Blocking] Disk exhaustion from `cargo test --offline --workspace --all-features --no-run`**
- **Found during:** Task 1 verification
- **Issue:** the all-features workspace test build wrote about 10 GB of artifacts, filled the volume to 0 bytes free, and made every tool call fail with ENOSPC until space was freed.
- **Fix:** deleted only build-cache files under `target/` (files over 5 MB modified in the preceding hour, then `target/debug/incremental`) and my own scratch files; no source or other session's data was touched. The full `--workspace --all-features --no-run` was not re-run. Its coverage of the glob-import adjacency was replaced by the targeted `paladin-doc-examples` check above, the muster's identity pins, `make check-examples` and the `--all-targets` clippy of `paladin-ai`.
- **Residual risk:** crates other than `paladin-ai` and `paladin-doc-examples` were not compiled with `--all-features --all-targets` against the new prelude names. The change only adds names, and the only glob importers are the files listed above, so the risk is low, but CI's full build is the proof.

**2. [Rule 3 - Blocking] Doc test attributed to `mod.rs`, not `cadence.rs`**
- **Found during:** Task 2
- **Issue:** the plan's verify greps for `src/infrastructure/cadence.rs - infrastructure::cadence (line N) ... ok`. Rustdoc attributes the module-level doc test to `src/infrastructure/mod.rs` because `pub mod cadence;` carries outer docs there, so the line reads `src/infrastructure/mod.rs - infrastructure::cadence (line 82) ... ok`.
- **Fix:** none needed in code; the check was run with the file name as `(mod|cadence).rs`. The test reports `ok`.
