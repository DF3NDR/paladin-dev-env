## Scrub method and credential-handling review

- **Method:** a scratch script (kept in the scratchpad, not committed) ported the semantics of `redact_secret_patterns` (HTTP authorization-scheme token marker in both capitalisations, the vendor-prefixed secret-key marker, the AWS access-key-id marker, the key and token query-value markers at a word boundary, three-segment base64url triples) and added the Google, xAI, GitHub and Slack key shapes, long mixed-case tokens, authorization-style header lines that carry a value, and the literal values of every credential environment variable and of every file under `~/.config/paladin/` (55 literals), compared programmatically with only names ever printed. The scanner was first shown to fire on a planted sample (it reported the literal, the shapes and the header). It was then run on the raw file, on the assembled `50.1-SEED-PROBE.md` and on `50.1-PROBE-CANDIDATES.md`: 0 hits each. The header describes the scrub by concept, so it trips no key-shape check (the 50-17 marker-word lesson).
- **No measured value was edited.** The transcript part is byte-identical to the raw file.
- **Name versus value:** the transcript contains the header names (`Authorization`, `x-api-key`, `x-goog-api-key`, printed as "name only, value never printed") and the credential variable names; the scanner distinguishes those from a header line carrying a value (none exists). Vendor request ids (`req_...`, `chatcmpl-...`, uuid request ids) appear in error bodies; they are not credentials.
- **Manual credential-handling review (security.instructions.md):** the committed transcript and the candidate file carry no key, token, authorization header value, JWT-shaped triple or key-bearing URL (the only query string is the Gemini listing's `pageSize=1000`). Response bodies had already passed `diagnostic_excerpt` in the harness before printing. This review is manual; no static taint analysis gates it (CodeQL is advisory-only, Snyk was removed). The task automated verify's negative key-shape grep also finds nothing.
- Unobserved facts: the header derives only counts, quotes (each asserted to be a substring of the transcript) and comparisons from the transcript. Statements that come from the operator or the runner rather than the probe (exit status 0 and empty stderr, the Gemini key being paid tier, the hidden keys in run 2) are attributed as such.
