<objective>
Close G-2 item (2) for `PaladinBuilder` (51-REVIEW.md WR-01): give every pre-judging gate the adapter's own
provider-level defaults by adding one additive provided method, `LlmPort::check_reasoning`, whose overrides in the
native adapters run the very `in_force` + admission path the adapters run at send time, and make
`PaladinBuilder::build` delegate its effort check to it.

Purpose: D-05 makes `llm.<provider>.reasoning_fallback` a first-class setting with the same precedence as the effort;
today it is inert at build time, so an operator's provider fallback is refused at build with a hint to set it. D-09
promises build-time and send-time answers that cannot drift; this plan makes them the same function.

Output: the trait method (default = today's builder rule), `reasoning::judge` / `reasoning::check`, the shared
fallback hint, overrides on DeepSeek, OpenAI, Anthropic and Gemini, and the builder delegation, each red-first.
The five compat presets and the Pricing / Cadence decorators are plan 51-18; the fallback chain is plan 51-19; the
public-surface register is plan 51-20.

<remedy_decision>
**Chosen: expose the provider defaults (the verifier's first remedy), as one verdict method rather than a data accessor.**
`LlmPort::check_reasoning(&self, model: &str, effort: Option<ReasoningEffort>, fallback: Option<ReasoningFallback>)
-> Result<(), LlmError>`, a provided method.

Rationale:
1. Documenting the limitation (the second remedy) would leave `llm.<provider>.reasoning_fallback` inert for every
   `PaladinBuilder` caller and every chain -- a reduction of D-05, which gives the fallback "the same three levels and
   precedence" as the effort, and of D-09's "build-time check as well as send-time".
2. 51-REVIEW.md WR-01 sketched a data accessor (`reasoning_defaults(model) -> (effort, fallback)`). A data accessor
   cannot express a fallback chain, whose hops each have their own defaults, so the builder would keep judging a
   chain against the intersected profile -- which also over-refuses (hop A `[low, high]`, hop B `[medium, high]`,
   `medium` + `nearest_lower`: the intersection `{high}` refuses, every hop accepts at send time) and drops a
   profile-less hop (G-2 item (3)). A verdict method that `FallbackLlmAdapter` overrides per hop (plan 51-19) removes
   all three divergences with one mechanism.
3. Each adapter's override calls the same `paladin_llm::reasoning::in_force` and the same `judge` (extracted from
   `admit`) over the same `wire_profile` the send-time path uses, so the two answers are one code path, not two
   copies kept in step.

**Reversibility: costly** (flagged, no checkpoint). An additive provided method on the public `LlmPort` trait,
overridden by nine adapters and three decorators; every third-party implementor compiles unchanged and inherits a
default body that is exactly today's builder rule. Undoing it later is a section 9.2 removal row for callers and
overriders -- a coordinated change, not a data migration or a broken persisted format, so not one-way.
</remedy_decision>
