<objective>
Make the release-body builder size-proof. The body travels file -> `jq --rawfile` -> stdin, never argv (D-09). One
shared helper, `scripts/release-body-fit.sh`, measures characters and cuts an over-limit body at a line boundary with a
logged, sentinel-marked footer (D-11). `create-or-reuse-release.sh` calls it before the create call. The regression
harness proves the 131,072-byte argv failure red first, then green (D-10).

Purpose: CIREL-05, under the D-12 verification posture. Plan 52-04 reuses the helper for `finalize-release-body.sh`.
Output: the helper and its harness, the fixed builder, and new create-or-reuse-release harness cases.
</objective>

<interfaces>
Contract this plan creates and plan 52-04 consumes (interface-first; 52-04 must not change these signatures):

- `scripts/release-body-fit.sh`, sourced with `RELEASE_BODY_FIT_LIB_ONLY=1`. Also runnable directly as
  `release-body-fit.sh --in FILE --out FILE --tag TAG [--repo OWNER/NAME]` (the create-time policy; exit 0, 1 failure,
  2 usage).
- `release_body_limit`: prints `PALADIN_RELEASE_BODY_LIMIT` (default `125000`). Anything other than a positive
  decimal integer is `ERROR: PALADIN_RELEASE_BODY_LIMIT must be a positive integer` with return 1.
- `release_body_reserve`: prints `PALADIN_RELEASE_BODY_RESERVE` (default `5000`). It must be a non-negative integer
  smaller than the limit, else a named error with return 1.
- `release_body_length FILE`: prints the Unicode code-point count via `python3`, decoding strict UTF-8. Invalid UTF-8
  is `ERROR: release body is not valid UTF-8` with return 1. `python3` absent is a named error.
- `release_body_fit IN OUT TARGET TAG REPO`: if `len(IN) <= TARGET`, OUT is a byte-for-byte copy and nothing is logged.
  Otherwise:
  - strip an existing footer (from the sentinel line to end of text);
  - cut at the last newline within `TARGET - len(footer) - 16`, or hard-cut at that many code points when no newline
    exists there (never empty);
  - if the kept text leaves a code fence open (lines whose first non-space characters, after at most three spaces, are
    three or more backticks or tildes toggle the state), append a closing fence line of the same characters;
  - append the footer;
  - assert `len(OUT) <= TARGET`;
  - log `release-body-fit: original <N> chars, target <T> chars, final <M> chars` to stderr. Never log body text.
  `TARGET` too small for footer plus one character is a named error.
- Footer (exact; `REPO` empty means the URL is omitted): a blank line, then `<!-- paladin:release-truncated -->`, then
  `_Release notes truncated to fit GitHub's release-body size limit. Full changelog: CHANGELOG.md at <TAG>
  (https://github.com/<REPO>/blob/<TAG>/CHANGELOG.md)._` and a trailing newline.
- `release_body_fit_for_create IN OUT TAG REPO`: limit `L` from `release_body_limit`. If `len(IN) <= L`, OUT is a
  copy. Otherwise call `release_body_fit IN OUT (L - reserve) TAG REPO` and, when `GITHUB_ACTIONS` is `true`, print
  `::warning title=Release body truncated::original <N> chars, final <M> chars, limit <L>`.
- Existing: `_cor_build_payload TAG NAME BODY_FILE PRERELEASE` (create-or-reuse-release.sh lines 88-112),
  `_cor_gh_call` (68-86), the `CREATE_OR_REUSE_RELEASE_LIB_ONLY` seam (245-247). The harness helpers are
  `write_gh_stub`, `run_script` (which sets `GITHUB_REPOSITORY=""`), `assert_silent`, `assert_fire` and
  `assert_call_count`, and the stub writes the POST stdin to `<dir>/captured_payload`.
</interfaces>

<planner_decisions>
- **PD-02-1 (D-11 vs headroom):** the guard *triggers* at the limit, as D-11 states. When it does trigger, it fits to
  `limit - reserve`, which leaves room for the artifact sections `finalize-release-body.sh` appends (RESEARCH Pitfall 6).
  A body at or under the limit is never touched. Plan 52-04 adds the second layer: re-fit at finalize if the composed
  body still exceeds the limit.
- **PD-02-2 (D-10 vs D-11 collision, orchestrator note 4):** the argv case raises `PALADIN_RELEASE_BODY_LIMIT` to
  500000 so its >131,072-byte body is really sent whole. The default-limit truncation case is separate.
- **PD-02-3 (Claude's discretion, D-11):** env var names `PALADIN_RELEASE_BODY_LIMIT` / `PALADIN_RELEASE_BODY_RESERVE`.
  The footer links `CHANGELOG.md` at the tag rather than a heading anchor, because GitHub derives anchors from the
  heading text including the date, which the script does not know (RESEARCH Pattern 5 step 6). The footer text is fixed,
  with no sizes in it, so the finalize re-fit stays idempotent.
- **PD-02-4:** one helper sourced by both release scripts (the D-06 "one implementation" principle), with the
  `check-publish-order.sh` sourcing pattern. A missing helper is a named failure.
</planner_decisions>

<flagged_assumptions>

- A-52-07: `python3` is present on GitHub's `ubuntu-latest` release runners (it is used by existing gates); the helper
