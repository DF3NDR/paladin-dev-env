<planner_decisions>
- **PD-06-1 (D-12, D-00f locked):** the refusal condition is exactly "Treasurer configured AND no engine factory". The case "factory present but `with_treasurer` dropped" is not added as a second refusal (D-00f fixes the contract); it is covered by code review and recorded as an accepted residual in the threat model. `has_engine_factory` cannot tell a real factory from a no-op closure, so AC-N5 stays a judgment check (`/gsd-secure-phase`, code review).
- **PD-06-2 (orchestrator note 3, D-14):** the scan runs whenever the schedule repository exists (run store enabled), regardless of `schedules.enabled`.
- **PD-06-3 (research Pattern 8, Pitfall 10):** the scan is split into `async fn scan_unattributed_schedules(repo: &dyn RunScheduleRepositoryPort) -> ScanOutcome` (ids collected before any failure plus the failing page's cursor position), `fn scan_report(outcome: &ScanOutcome) -> Vec<(log::Level, String)>` (pure, at most one `Warn` and one `Error` line) and `fn report_unattributed_schedules(outcome: &ScanOutcome)` (logs each line). "Exactly one `warn!`" is proven on the formatter's output plus the emitter's one-log-per-line structure. The error line never interpolates the error.
- **PD-06-4 (D-13, research Pattern 7, corrected):** the key-name-only literal `"anonymous"` is `paladin_web::agent_auth::OPEN_ACCESS_PRINCIPAL_ID` (the research note that compared that constant with `"open-access"` is wrong; the constant is `"anonymous"`). Core cannot import `paladin-web`, so the drift test lives in the root crate. The name rejection uses the `[#<index>]` form (like the existing name-validity message), the tenant rejection the `[<name>]` form.
