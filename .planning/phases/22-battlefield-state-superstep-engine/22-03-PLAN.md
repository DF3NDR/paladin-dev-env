<objective>
Turn the tracer's working-but-thin `WaypointPort` into the full ENG-03 contract, and build the one
shared contract test suite (D-09) that all three backends will run unchanged.

Purpose: ENG-FR-17 requires SQLite and Postgres to pass the *identical* suite as InMemory. Writing
that suite once, against the in-memory backend, before either SQL adapter exists is what makes
"identical" enforceable instead of aspirational — and it pins the not-found, ordering and pagination
semantics that Plan 22-06 must reproduce over SQL.

Output: a fully specified `WaypointPort`, a validated `ThreadId`, and a reusable generic contract
suite green against `InMemoryWaypointStore`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied ThreadId -> store | An arbitrary caller string becomes a persistence key and, later, a URL path segment |
| store -> caller | `list_threads` returns every thread the backend holds, with no tenancy filter |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-07 | Information Disclosure | `WaypointPort::list_threads` enumerating all threads | medium | accept | This epic ships no network surface (RESEARCH.md Security Domain rates V4 Access Control as not applicable here). Accepted with an explicit control: the port rustdoc states ThreadId is not an authorization boundary and that any network exposure must add its own authorization layer, so the HTTP epic cannot inherit the gap silently |
| T-22-08 | Tampering | `ThreadId` accepting arbitrary caller input | medium | mitigate | Typed validating constructor rejects empty, whitespace-bearing and over-length values with distinct errors, so a key cannot carry a path separator, a newline for log injection, or an unbounded length into a SQL key column |
| T-22-09 | Denial of Service | unbounded `history` / `list_threads` result sets | low | mitigate | Both methods take a `limit`, documented and contract-tested including the zero case; the SQL backends in Plan 22-06 translate it into a SQL `LIMIT` rather than filtering after a full table read |
</threat_model>
