## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| caller -> `WarEngine::start` / `resume` | A caller supplies a `WarGraph` and reads `RunOutcome`; a `Completed` that is not true is the boundary violation BUG-03 and BUG-04 closed | graph definition in, `RunOutcome` out (node ids only) |
| caller -> `WarGraph::validate` | Untrusted-to-the-engine graph definition; the guard rejects shapes that cannot be honestly executed before any node runs | node ids, edge endpoints |
| stored Waypoint -> `resume` fingerprint check | A persisted `GraphFingerprint` is compared against the live graph; an under-covering fingerprint lets a materially different graph pass | structural hash (blake3 over canonical bytes) |
| `WarGraph` -> canonical bytes -> blake3 | Byte-canonicalization boundary; `Debug` output or map order would silently invalidate or falsely validate stored threads | graph-structure identifiers only; prompt, model, `InputMapping` template and `EngineLimits` excluded (ENG-FR-14) |
| stored Waypoint payload -> `Frontier` scheduling state | New in this phase: the payload carries scheduling state, and a corrupted, hand-edited or foreign-graph payload decides which nodes run | `FrontierSnapshot`: node ids, edge endpoints, canonical edge condition, superstep indices |
| storage backend (SQLite / Postgres / in-memory) -> `parse_payload` | Deserialization of an additive field, guarded by the schema-version check | `#[serde(default)]` field under unchanged `BATTLEFIELD_SCHEMA_VERSION` |
| crates.io -> `Cargo.lock` -> the build | Third-party code crosses into every shipped artifact; the lockfile resolution is the control point | resolved dependency versions |
| repository -> CI runner | `ci.yml` selects the toolchain the MSRV floor is measured against | toolchain version (1.88) |
| advisory register (`.cargo/audit.toml`, `deny.toml`, `SECURITY-EXCEPTIONS.md`) | Governed suppression surface; an addition converts a fixable advisory into accepted risk | none crossed (untouched this phase) |
| GitHub Actions -> the evidence record | CI output becomes a durable project claim; job-level or wrong-head queries read as assurance while proving less | quoted log lines: container health, `pg_isready`, test counts, skip-detection |
| local shell -> GitHub API (`gh`, `GH_TOKEN`) | Authenticated credential used for read-only run queries | token from environment only, never echoed or committed |
| prior evidence -> new evidence | The evidence file is a record under revision; a rewriting append destroys the audit trail | append-only edit |
