   - Compute a memo key from `(ctx.thread, ctx.superstep, ctx.source, a digest of the rendered
     prompt)`. Resolve the model's verdict ONCE per key; every subsequent `evaluate` call carrying
     the same key reuses the stored verdict. Implement the memo as a single-slot cache behind a
     `tokio::sync::Mutex` (the outgoing edges of one source node are evaluated consecutively inside
     one `record_execution` pass, so one slot satisfies the rule and cannot grow unbounded). A
     small bounded map is an acceptable alternative; an unbounded map is not.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process -> third-party LLM API | The rendered `prompt_template` (engine path: live Battlefield state; legacy path: the source node's output) leaves the process. This is the phase's only outward data flow. |
| model response -> routing decision | An untrusted model answer selects which edge fires and which Battalion strategy runs; it is matched against a closed choice/catalog list, never executed or interpolated. |
| workflow author -> `choices` / `prompt_template` | The author controls exactly what is sent and which answers are legal; this is the control point the rustdoc must name. |
