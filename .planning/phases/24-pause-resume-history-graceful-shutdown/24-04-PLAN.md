<objective>
Make `resume_with` trustworthy: total validation before any state change, partial answers that stay
suspended and stay queryable, and an expiry policy that either fails the run loudly or substitutes a
validated default with an audit marker.

Purpose: HITL-02 and HITL-FR-05/FR-06 — the typed-error contract that leaves a thread suspended when
a caller gets a response wrong, and the "partially answered suspension is queryable" clause of
HITL-01.

Output: the complete validation matrix, same-superstep partial-answer Waypoints, and lazy expiry
with both `on_expire` policies.
</objective>

## Flagged assumptions (unresolved edge probes)

The spec-less edge-coverage probe produced one `unclassified` item for HITL-02 that could not be
auto-resolved into an acceptance criterion. It is recorded here rather than silently dropped:

- **HITL-02 / unclassified — "review manually".** The probe generator could not classify this
  requirement into an edge family. The planner's reading is that the residual ambiguity is *response
  ordering within one `resume_with` submission*: whether two responses answering the same
  `parley_id` in a single call are (a) both rejected, (b) last-wins, or (c) first-wins. This plan
  implements **(a) both rejected** — the second is `ParleyAlreadyAnswered` because validation is
  total and the first is accepted into the working set before the second is checked. This is an
  assumption, not a decision carried from CONTEXT.md or PRD 03; surface it at plan review. If the
  developer prefers (b) or (c), it changes only Task 1's duplicate-detection rule.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> `resume_with(thread, responses)` | Caller-supplied JSON values are delivered into a running workflow's state |
| clock -> `expires_at` | Expiry is decided by comparing a persisted instant against `Utc::now()` at resume time |
| author -> `on_expire: ResumeWithDefault(value)` | A pre-authored value stands in for a human decision |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-24-13 | Tampering | A malformed or oversized StateEdit response mutating unintended Battlefield fields | high | mitigate | The response deserialises to a `StateDelta` validated field-by-field against the graph schema; an undeclared field rejects the response with `ResponseShapeInvalid` and applies nothing |
| T-24-14 | Elevation of Privilege | A Choice response outside the offered options steering routing to an unintended branch | high | mitigate | Choice validation accepts only a member of that request's own `choices` list, checked before any write |
| T-24-15 | Spoofing | Answering another thread's parley | high | mitigate | Parley ids are matched only against the loaded thread's outstanding `parleys`; there is no global lookup (test `resume_with_parley_ids_are_scoped_to_the_requested_thread`) |
| T-24-16 | Elevation of Privilege | An expiry default silently approving a gate | high | mitigate | The default is validated by the same shared per-kind validator as a real response, and the substitution is recorded on the persisted response with `responded_by: None` and `defaulted: true` so an audit can see it |
| T-24-17 | Repudiation | A resumed run with no record of who answered | medium | mitigate | `ParleyResponse.responded_by` and `responded_at` are persisted on the Waypoint; a defaulted substitution is distinguishable from a human answer |
| T-24-SC | Tampering | package-manager installs | low | accept | No new package is installed by this plan |
</threat_model>
