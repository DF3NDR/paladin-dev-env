<objective>
Make shutdown lose no work. Observe cancellation mid-superstep, give the in-flight batch one shared
grace window, abort only the stragglers, and hand `resume` a Halted Waypoint that re-runs exactly
the nodes that did not finish.

Purpose: HITL-04 and HITL-FR-13/FR-15, and the phase's primary engineering risk (RESEARCH.md's
Pitfall 1) — the one place where "extend the existing code" is not mechanical.

Output: `engine::shutdown`'s `ShutdownCoordinator`/`RunGuard`, the mid-superstep grace race, and the
two `EngineConfig` fields that drive them.
</objective>

Add a second cancellation observation point inside the superstep, at the moment the spawned node
tasks are being awaited (D-19). The existing superstep-boundary check at ~line 893 stays exactly as
it is; this is an independent second observation, not a replacement.

The superstep dispatch/join loop is strictly sequential today and must become a batch-level race
against one shared grace deadline, not a per-handle timeout. Restructure the join phase: index the
spawned handles by their `dispatch_entries` position, drive them through a `FuturesUnordered`, and
race the whole collection against a single `tokio::time::sleep_until(cancel_observed_at +
shutdown_grace)` branch in a `tokio::select!`. When the sleep branch fires, call
`JoinHandle::abort()` on every handle still outstanding. Do not wrap individual `.await` calls in
`tokio::time::timeout` inside the existing loop: that computes a fresh window per iteration, so a
slow early node consumes grace a later node never gets, and a later node's clock does not even start
until the loop reaches it. Test 5 exists to catch exactly that.

`FuturesUnordered` does not preserve input order, so collect results into a vector indexed by
dispatch position and then run the existing bookkeeping match over that vector in dispatch order.
Every order-sensitive accumulation in the current loop must keep its current semantics:
`node_failure`'s first-wins guard, `goto_targets` push order, `end_requested`, `routing_failure` and
`mustered`. RESEARCH.md's Open Question 1 is settled and needs no further investigation: the
`completed_records.sort_by(|a, b| a.node_id.cmp(&b.node_id))` at superstep.rs:1424 already sorts the
records by node id after the loop, so dispatch-order appending is not load-bearing for the
Waypoint's `completed` list — but it IS load-bearing for the accumulators above, which is why the
re-indexing step is mandatory rather than optional.

For each aborted node: discard its delta, record `NodeOutcomeKind::Skipped` with reason `shutdown`,
re-list its id in the Halted Waypoint's vanguard alongside the normally computed next Vanguard, and
leave its outgoing edges `Pending` in the `FrontierSnapshot` so `resume` re-executes it exactly once
(ENG-FR-12a, acceptance 5). Nodes that finished in time merge normally and their edges resolve.
`Duration::ZERO` aborts immediately.

The mechanism inside `superstep.rs` is your choice; the contract above is locked.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operating system -> SIGTERM/SIGINT -> in-flight runs | An external signal interrupts work that is mid-write |
| aborted task -> Battlefield | A task killed mid-execution must not contribute a partial delta |
| operator env -> engine runtime behaviour | Two new env vars change how long the process lingers before exiting |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-24-30 | Tampering | An aborted node contributing a partial delta to the Battlefield | high | mitigate | Aborted handles' results are discarded before the merge; Test 2 asserts the delta never reaches the Battlefield and the record reads `Skipped` |
| T-24-31 | Tampering | Duplicate side effects from a node re-run after abort | high | mitigate | Skipped nodes' outgoing edges stay `Pending` in the `FrontierSnapshot` so resume re-executes them exactly once; Test 4 asserts a run counter of exactly two across the whole scenario |
| T-24-32 | Denial of Service | A hung node holding the process open past its grace window | high | mitigate | `cancel_and_wait(grace)` returns at the deadline and reports the timeout; `JoinHandle::abort` releases the straggler |
