<objective>
Replace nine independently drifting HTTP-status-to-`LlmError` mapping blocks with one shared
`map_http_status` helper that redacts before it bounds and emits the status-carrying
`LlmError::ProviderError` for every status that has no dedicated variant.

Purpose: FT-FR-01 forbids classifying transience by parsing strings. Today five of the nine adapters
erase a 5xx or an unknown 4xx into `ProcessingError(format!("HTTP {}: …"))`, which is exactly the
erasure the taxonomy cannot see through. One helper also means the redact-then-bound rule is enforced
in one place rather than nine.

Output: `crates/paladin-llm/src/http_status.rs`, nine rewired non-2xx branches, and status assertions
that read a typed field.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider HTTP response body -> `LlmError` message | Remote, attacker-influenceable bytes become an error field that is logged, persisted and (from plan 25-10) written into Battlefield state |
| adapter API key -> error excerpt | A credential held by the adapter is present in the process while the excerpt is built |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-20 | Information Disclosure | credential leaking through a truncated error excerpt | high | mitigate | `map_http_status` redacts through `redaction.rs` **before** bounding, in one place for all nine adapters (D-03, D-34); `excerpt_is_redacted_before_it_is_bounded` computes the wrong-order control and asserts the helper does not match it |
| T-25-21 | Information Disclosure | provider body embedded verbatim in a persisted error | medium | mitigate | Every excerpt is bounded after redaction, so an unbounded provider body never reaches a `NodeError` or a Waypoint; the bound is applied on character boundaries so the result is always a valid `String` |
| T-25-22 | Tampering | provider shaping its error text to influence retry | high | mitigate | Transience is read from the typed `status` field, never from the message (plan 25-02); this plan removes the last paths that encoded a status into text, pinned by the crate-wide negative grep |
| T-25-23 | Spoofing | one adapter drifting from the shared mapping | medium | mitigate | Exactly one mapping helper exists and all nine adapters call it, pinned by a count assertion in the acceptance criteria; RT-06 in Phase 26 then re-verifies three paths rather than rebuilding nine |
| T-25-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package: RESEARCH.md's Package Legitimacy Audit records zero proposed packages, verified by direct `Cargo.toml` read |
</threat_model>
