<objective>
Stop erasing real `LlmError`s into strings. Add one shared conversion helper and route every
first-party site that holds an `LlmError` through it into the structured
`PaladinError::LlmFailure`, so transience, HTTP status and provider survive the crossing into the
core error taxonomy.

Purpose: the retry predicate, the compensation handler and the fallback chain all decide from
transience. Today eight sites throw that information away one line before the engine needs it.

Output: `crates/paladin-battalion/src/llm_failure.rs` and eight migrated construction sites, with
rendered text and retryability provably unchanged.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `LlmError` (port layer) -> `PaladinError` (core taxonomy) | Provider-influenced status, name and message cross into the error type the engine and circuit breaker branch on |
| converted error -> circuit breaker accounting | The breaker's open/close decision reads `is_retryable()` on the converted value |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-25-25 | Denial of Service | circuit breaker behaviour drift after the migration | high | mitigate | `is_retryable()` answers `true` for `LlmFailure` exactly as it did for the legacy variant (plan 25-02), `circuit_breaker.rs` is not edited, and the acceptance criteria assert it is unmodified |
| T-25-26 | Information Disclosure | provider message carried into the core error | medium | mitigate | The message is the source `LlmError`'s own rendering, which for every provider path was already redacted and bounded by `map_http_status` (plan 25-05); this plan adds no new unredacted path (D-34) |
| T-25-27 | Repudiation | log-line drift at the migrated sites | low | mitigate | Rendered text is byte-identical by construction and pinned by `rendered_error_text_at_every_migrated_site_is_unchanged`, so operational log parsing built on these lines keeps working (X-03) |
