<objective>
Land model fallback: a `FallbackLlmAdapter` that composes a chain of plain `LlmPort`s, hops only on
Transient or Unknown errors, refuses to switch providers after a stream has begun, reports exhaustion
as `LlmError::AllProvidersFailed`, emits a trace event and a warning per hop, and records the serving
provider on `PaladinResult`.

Purpose: FT-05 is standalone — it composes existing ports and adds no trait method — but it is what
Phase 26's retry/fallback middleware delegates to, so its shape has to be right the first time.

Output: `crates/paladin-llm/src/fallback.rs`, `TraceEvent::FallbackHop`, `PaladinResult.served_by`
with its full-literal migration, and the fourth §9.2 register row.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider chain -> caller | A response returned to the caller may have been produced by a provider the caller did not name |
| provider stream -> consumer | A partially delivered response could be completed by a different model if the adapter hopped mid-stream |
| `LlmResponse.metadata` -> `PaladinResult.served_by` | An untyped map key becomes a typed public field |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-33 | Tampering | silent provider switch mid-response | high | mitigate | Fall-through happens only before the first chunk; after any `Ok` chunk the error propagates unchanged and no hop occurs (D-25, FT-FR-16), pinned by `streaming_error_after_the_first_chunk_propagates_with_the_prefix` asserting the next provider has call count 0 |
| T-25-34 | Repudiation | the caller not knowing which provider answered | medium | mitigate | Every hop emits a `FallbackHop` trace event and a `tracing::warn!` naming both providers, and the serving provider is recorded on `PaladinResult.served_by` (D-25, D-26, FT-FR-17) |
