<objective>
Turn a node failure into a decision. Land the `Route`, `Absorb` and registered-`Custom` error handlers:
their graph-validation clauses, their runtime dispatch after retries exhaust, the `Route` target's
Vanguard placement and reachability eligibility, and the no-handler path that fails the run with a
structured error rather than a string.

Purpose: FT-04 is what makes Saga-style compensation expressible — "if the booking node fails
permanently, run the cancel-reservation node" — and it is the half of E2E-3 that plan 25-12 asserts
end-to-end.

Output: the handler validation clauses, the dispatch path, and `max_node_visits` accounting that
bounds a compensation cycle.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `NodeError` -> `error_field` -> Battlefield state | Provider- and node-influenced error content is written into author-visible state another node or an LLM call may read |
| registered handler -> engine control flow | An author-supplied handler decides where the run goes next |
| handler-routed target -> visit accounting | A compensation path could consume unbounded scheduling budget |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-45 | Information Disclosure | `error_field` carrying provider-influenced content into state | medium | mitigate | The written value is the structured `NodeError`, whose message was redacted and bounded upstream by `map_http_status` (plan 25-05); `error_field` and Waypoint payloads are author-visible state and inherit M-B-04's raw-content warning, restated in plan 25-14's guide (D-34) |
| T-25-46 | Tampering | `Route` writing into a field whose dispatch corrupts the value | medium | mitigate | The `error_field` must be declared with a dispatch other than `Sum`, rejected at validation with a message explaining why a serialized error object is not summable (D-21), pinned by `route_error_field_must_not_use_sum_dispatch` |
| T-25-47 | Denial of Service | an unbounded compensation cycle | high | mitigate | Handler-routed visits count against `max_node_visits` through the existing accounting with no second counter and no exemption (D-21, FT-FR-15), pinned by `a_compensation_cycle_terminates_with_the_visit_limit` under a timeout guard |
| T-25-48 | Elevation of Privilege | a handler running before the retry policy is honoured | medium | mitigate | A handler is entered only on exhaustion or non-retryability (FT-FR-05), pinned by `a_handler_does_not_run_while_retries_remain` asserting exactly one handler invocation after three attempts |
| T-25-49 | Tampering | a `Route` target that is not a real node, or is a worker template | medium | mitigate | Both are typed validation errors before any node runs (D-21, D-22), and the worker-template message names the alternative rather than only rejecting |
| T-25-50 | Tampering | a handler observing partially merged state | medium | mitigate | The handler receives the same immutable pre-superstep snapshot the node's attempts read (Phase 22 D-12), so it cannot see a half-applied merge |
| T-25-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package: RESEARCH.md's Package Legitimacy Audit records zero proposed packages, verified by direct `Cargo.toml` read |
