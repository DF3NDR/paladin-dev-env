## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| conversation history → the counting path → the prompt budget | Model- and user-authored text decides how much of a conversation reaches the provider |
| provider-declared `max_context_tokens` → the resolved limit | A third-party-derived number influences local trimming |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-37 | Denial of Service | an unbounded conversation exceeding the context window | medium | mitigate | `HistoryTrimmer` bounds the history against a resolved limit with a reserved response budget, degrades to an empty history rather than failing, and never splits an entry (D-15); the trimmer is inert by default so it must be opted into |
| T-26-38 | Tampering | a mis-declared provider `max_context_tokens` silently over-trimming or under-trimming | low | mitigate | The three-step resolution puts the operator's own `model_context_limits` table **first**, and both the resolved value and its source are logged at debug so a wrong provider figure is diagnosable rather than invisible (D-14) |
| T-26-39 | Information Disclosure | a truncated message leaking half a secret into the prompt | low | mitigate | An entry is kept whole or dropped whole — the trimmer never slices message content, which is the same boundary-slicing hazard the redact-then-bound rule addresses elsewhere (D-15, security.instructions.md) |
| T-26-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package; `tiktoken-rs 0.6.0` is already an optional dependency of `paladin-memory` at the version 26-RESEARCH's Package Legitimacy Audit verified |
