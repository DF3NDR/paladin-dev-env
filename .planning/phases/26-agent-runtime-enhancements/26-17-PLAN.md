<objective>
Make `execute_structured<T>` real: implement the object-safe `StructuredExecutorPort` natively on
`PaladinExecutionService` — setting the native `response_format` *and* appending the instruction
block for every model call of a structured run — and add the generic `StructuredExecutorExt` blanket
extension that derives the schema from a Rust type and deserializes the result back into it.

Purpose: this is the point where RT-FR-17's user-facing promise becomes true. The two halves that
make it safe are already built: the bounded driver (plan 26-12) and the wire field (plan 26-06). This
plan wires them together and proves the four PRD §3.5 shapes.

Output: `src/application/services/paladin/structured.rs` with `StructuredExecutorExt`;
`impl StructuredExecutorPort for PaladinExecutionService`; prelude exports.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output → parse → typed value → caller program flow | Fully model-controlled text becomes a typed Rust value that drives program behaviour |
| caller schema → prompt instruction block and provider request | Caller data reaches both the prompt and an outbound request body |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-12 | Denial of Service | an unbounded repair loop | medium | mitigate | The service supplies only an `execute_fn`; the bound lives in the shared `run_structured` driver with `max_repair_attempts` defaulting to 1 (plan 26-12). `the_repair_loop_is_the_shared_driver` asserts the facade contains no second loop. |
| T-26-56 | Tampering | trusting a partial shape check as type validation | medium | mitigate | The rustdoc states that serde deserialization **is** the typed validation and `shape_check` is a pre-filter that improves the repair prompt; `serde_deserialization_is_the_typed_validation` exercises a value the partial check accepts and serde rejects, and asserts it routes to the repair loop rather than panicking (D-27, D-30) |
| T-26-25 | Tampering | correctness depending on a provider's native mode | medium | mitigate | The instruction block is appended on **every** structured model call regardless of `response_format`, so an adapter with no native mode (Anthropic) or a deliberately degraded one (the compat engine) is still constrained by the prompt; `structured_run_also_appends_the_instruction_block` pins it (D-27, D-28) |
| T-26-09 | Information Disclosure | a caller schema logged with a request body | low | mitigate | Schemas are caller-authored and never logged with request bodies (D-41); this plan adds no body logging |
| T-26-SC | Tampering | cargo installs | low | accept | `schemars` was added and audited in plan 26-12; this plan is its first consumer and asserts the graph still holds exactly two versions |
</threat_model>
