<objective>
Make typed agent-to-agent data flow first-class in the engine: a Paladin node may declare an
`output_schema`, and when it does the engine runs it through the structured executor and writes the
**parsed JSON value** — not a string — into its `output_field`. Wire it fail-closed at validation,
and carry the new hash input through a fingerprint version bump.

Purpose: RT-FR-19 is the payoff for the whole structured-output track — it is what turns a graph's
edges from string-passing into typed data flow. The two risks are both about silence: a
misconfigured node that fails at runtime instead of at validation, and a hash input added without a
version bump, which would make old and new fingerprints collide on stored Waypoints.

Output: `NodeSpec::Paladin.output_schema`; `WarEngine::with_structured_executor` and
`with_output_schema` with `TypedSchema<T>`; the validation matrix and its `EngineError` variants; the
structured branch in `superstep.rs`; fingerprint `v6`; `tests/integration/structured_engine_node_test.rs`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output → parsed value → Battlefield state → downstream nodes | Model-controlled data becomes shared workflow state other nodes act on |
| graph author → `output_schema` → fingerprint → stored Waypoints | An author-supplied value becomes part of a durable identity |
