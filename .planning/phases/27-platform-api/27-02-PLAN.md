<objective>
Make run persistence durable and contract-proven: the `runs` SQL table (with the partial unique
index that IS the `409 ThreadBusy` invariant), one shared contract suite, and the SQLite and
Postgres `RunRepositoryPort` adapters that pass it unchanged alongside the InMemory adapter from
27-01.

Purpose: PLAT-FR-01 requires every status transition persisted through a `RunRepositoryPort` with
SQLite + Postgres adapters and a contract suite; PLAT-FR-05's invariant must hold under concurrent
submits and across instances, which only a database constraint can guarantee (D-17).

Output: migrations `002_create_runs_table.sql` (both backends), `run/contract_tests.rs`,
`SqliteRunRepository`, `PostgresRunRepository`, the InMemory adapter brought into conformance, and
`MIGRATION.md` §9.4 rows for the new table.
</objective>

pub trait RunRepositoryPort: Send + Sync {
    async fn insert(&self, run: &Run) -> Result<(), RunRepositoryError>;          // ThreadBusy when the thread has an active run
    async fn get(&self, run_id: &RunId) -> Result<Option<Run>, RunRepositoryError>;
    async fn update_status(&self, run_id: &RunId, from: RunStatus, to: RunStatus, at: DateTime<Utc>)
        -> Result<(), RunRepositoryError>;                                          // CAS; 0 rows => IllegalTransition
    async fn record_outcome(&self, run_id: &RunId, outcome: RunOutcomeRecord) -> Result<(), RunRepositoryError>;
    async fn list(&self, query: RunQuery) -> Result<RunPage, RunRepositoryError>;  // (submitted_at DESC, run_id DESC)
    async fn active_run_for_thread(&self, thread: &ThreadId) -> Result<Option<Run>, RunRepositoryError>;
    async fn request_cancel(&self, run_id: &RunId) -> Result<RunStatus, RunRepositoryError>; // AlreadyTerminal on a terminal run
    async fn is_cancel_requested(&self, thread: &ThreadId) -> Result<bool, RunRepositoryError>;

}

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Facade → SQL backends | Caller-influenced strings (thread ids, assistant ids, JSON input, webhook URLs) become bound parameters and rows. |
| Concurrent workers / replicas → one `runs` table | Two processes may race on the same row or the same thread. |
| Connection strings → error messages | Backend errors embed the database URL, which may carry a password. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-02-01 | Tampering | `runs.status` under concurrent writers | high | mitigate | Every transition is a single CAS `UPDATE … WHERE status = ?from` (D-04); `rows_affected() == 0` → `IllegalTransition`; contract clause + multi-thread stress test. |
| T-27-02-02 | Tampering / DoS | one-active-run-per-thread invariant | high | mitigate | Partial unique index `idx_runs_thread_active` enforced by the database (D-17); `is_unique_violation()` mapped to `ThreadBusy`; ten-concurrent-inserts test on an on-disk SQLite file. |
| T-27-02-03 | Tampering | SQL construction from caller strings | high | mitigate | Only parameterised `sqlx::query`/`query_as`; acceptance grep forbids `format!("SELECT…` style SQL. |
| T-27-02-04 | Information disclosure | connection-string password in `Backend` errors | medium | mitigate | `waypoint::redact::redact_database_url_password` reused on every wrapped error (primary trust boundary, so mitigated at L1). |
| T-27-02-05 | Information disclosure | `webhook.secret` persisted in the `runs` row | medium | accept | The secret must be available at send time (27-13) and the row is only readable through the authenticated API, which projects `WebhookSpec` with the secret redacted (27-01's manual `Debug` + the DTO never echoes it); rationale: no key store exists in this milestone (ADR-0041 scope). |
