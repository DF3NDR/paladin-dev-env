```rust
#[async_trait]
pub trait RunQueuePort: Send + Sync {
    async fn enqueue(&self, run: QueuedRun) -> Result<(), QueueError>;
    async fn dequeue(&self, lease: Duration) -> Result<Option<LeasedRun>, QueueError>;
    async fn extend_lease(&self, token: &LeaseToken, by: Duration) -> Result<(), QueueError>;
    async fn ack(&self, token: LeaseToken) -> Result<(), QueueError>;
    async fn nack(&self, token: LeaseToken, requeue_delay: Duration) -> Result<(), QueueError>;
    async fn depth(&self) -> Result<u64, QueueError>;
}
// QueuedRun { run_id: RunId, thread_id: ThreadId, attempt: u32, enqueued_at: DateTime<Utc> }
// LeasedRun { queued: QueuedRun, token: LeaseToken }  ; LeaseToken(String) opaque
// QueueError (#[non_exhaustive]): LeaseExpired { token }, UnknownLease { token }, Backend { message }, Serialization { message }
```

    - Lease invisibility: after one `dequeue(200 ms)`, an immediate second `dequeue` returns `None`;
      after 250 ms the same `run_id` is returned again with `attempt + 1` (redelivery).
    - `extend_lease(token, 300 ms)` at t=150 ms keeps the message hidden at t=250 ms and visible at
      t=500 ms.

    - `nack(token, 100 ms)`: hidden at t=50 ms, visible at t=150 ms, `attempt` incremented.
    - `ack`/`extend_lease`/`nack` with an expired token → `LeaseExpired`; with a never-issued token →
      `UnknownLease`; neither call alters any other message.
    - `depth()` = ready + leased; two enqueues, one dequeue → 2; after ack → 1.
    - Concurrency (D-52, `#[tokio::test(flavor = "multi_thread")]`, `tokio::time::timeout` guard):
      eight workers each looping `dequeue(5 s)` → `ack` over 200 enqueued messages deliver every
      `run_id` exactly once (a `HashSet` of acked ids has 200 entries, no duplicates) and the
      queue is empty at the end.
    - Real short timers (`tokio::time::sleep`), not a paused clock: the InMemory adapter uses
      `std::time::Instant`/`tokio::time::Instant` and the Redis adapter uses server time, so the

    key_prefix: String /* default "paladin:run_queue" */ }` with a `Debug` impl that redacts the URL
    password, and `RedisRunQueue { conn: Arc<RwLock<ConnectionManager>>, prefix, claim: redis::Script,
    …}`. Keys: `{prefix}:ready` — a ZSET whose members are the serialized `QueuedRun` JSON and whose
    score is the visibility time in milliseconds (server `TIME`); `{prefix}:leases` — a HASH mapping
    lease token → member, and `{prefix}:lease_expiry` — a ZSET of token → expiry ms so
    `extend_lease`/`ack`/`nack` can distinguish `LeaseExpired` (token present in the expiry ZSET with
    a past score, or known-recently-expired) from `UnknownLease`. Define the claim script as `pub const
    RUN_QUEUE_CLAIM_LUA: &str` performing atomically: `ZRANGEBYSCORE ready -inf now LIMIT 0 1`; if a
    member exists, decode its `attempt`, re-encode with `attempt + 1`, `ZADD ready (now + lease) member'`
    (removing the old member), generate the token argument the caller passes in (UUID v7 string,
    generated in Rust), `HSET leases token member'`, `ZADD lease_expiry (now + lease) token`, and return
    `member'`; else return nil. `extend_lease`: a second script that checks the token's expiry score is
    still in the future, then `ZADD` both sets forward by `by`; `ack`: script that removes the member from
    `ready` and the token from both lease structures if the token is live; `nack(delay)`: script that
    moves the member's score to `now + delay` and drops the token. Use the server's `TIME` inside every
    script so two replicas never disagree on "now". `depth` = `ZCARD ready`. Map every `RedisError` to
    `QueueError::Backend { message }` with the connection URL redacted; JSON errors to `Serialization`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worker processes ↔ Redis | Queue messages (run pointers) and lease tokens cross a network boundary; multiple replicas contend for the same keys. |
| Config → Redis URL | The connection URL may embed a password. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-03-01 | Tampering | claim-and-lease across replicas | high | mitigate | Single atomic Lua `EVAL` for claim, extend, ack and nack using server `TIME`; contract clause `concurrent_workers_each_message_exactly_once` run with two adapter instances. |
| T-27-03-02 | Spoofing | lease tokens | medium | mitigate | Tokens are UUID v7 strings generated per claim and validated against `{prefix}:leases`/`lease_expiry` inside the script; unknown/expired tokens are typed errors that touch nothing (primary boundary, mitigated). |
| T-27-03-03 | Information disclosure | Redis URL password in `Backend` errors / `Debug` | medium | mitigate | `RedisRunQueueConfig` custom `Debug` redacts; every error message passes through the redaction helper before construction. |
| T-27-03-04 | Denial of service | unbounded queue depth | low | accept | Depth is bounded by the number of rows the `runs` table admits (one active run per thread, D-17) and by API auth + rate limiting (27-15); no separate cap is introduced this phase. |
| T-27-03-05 | Repudiation | Tier-2 suite reported green without running | medium | mitigate | CI `SKIP:` detector + declared-vs-selected test count on the `redis-queue` job (the Snyk lesson in `security.instructions.md`). |
</threat_model>
