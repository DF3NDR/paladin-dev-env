<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin HTTP caller → cron/timezone/input strings | Parsed by `croner`/`chrono-tz`; stored and later executed unattended. |
| Multiple replicas → one `run_schedules` table | Tick ownership is contended. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-11-01 | Tampering / DoS | duplicate firing across replicas or restarts | high | mitigate | Conditional-update tick claim (D-37) + persisted `next_tick`; `two_services_one_tick_exactly_one_fire` and `schedule_restart_exactly_once`. |
| T-27-11-02 | Denial of service | pathological cron (`* * * * * *` every second) | medium | mitigate | Parsing is bounded by `croner`; the busy-thread invariant and `FixedThread` skip counting bound concurrent runs; a per-schedule minimum interval is not an FR — documented as an operator concern in 27-16. |
| T-27-11-03 | Tampering | unbounded catch-up after downtime | medium | mitigate | `OnMissed::Skip` default; `RunOnce` fires at most one run per missed window (PRD policy). |
| T-27-11-04 | Information disclosure | schedule `input`/`webhook.secret` rows | low | accept | Same posture as `runs` rows (T-27-02-05): admin-authored, authenticated reads, DTO redacts secrets. |
</threat_model>
