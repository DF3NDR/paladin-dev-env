<objective>
Close verification gap 2: the Postgres run-repository timestamp round-trip. Nanosecond-precision
`chrono::DateTime<Utc>` fixtures are compared for exact equality against values read back from a
microsecond-resolution `TIMESTAMPTZ`, so three `run::postgres` contract tests fail in the live CI
`postgres-integration` job (contract_tests.rs:88, :126, :165) while every other Postgres suite in the
same job passes.

Purpose: PLAT-01 / PLAT-FR-01. "Every status transition is persisted" is only demonstrated if the
persisted row round-trips every field it claims to carry — including the three timestamps that a
caller reads back to reconstruct a run's history.

Output: an explicit, documented microsecond precision contract (`storage_timestamp`) applied at every
Postgres timestamp bind, a `contract_timestamp` fixture helper so the shared suite's assertions stay
exact equality rather than being weakened, and a dedicated round-trip precision test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Application `Run` value → `runs` table | Rust-side timestamps cross into a store with a different native resolution. |
| Stored row → API response / pagination cursor | Persisted timestamps are echoed to callers and encoded into opaque cursors. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-20-01 | Tampering | silent, driver-defined timestamp mutation on write | medium | mitigate | `storage_timestamp` normalises before the bind, so the stored value is decided by this codebase, not by whether the driver or server rounds; a dedicated test asserts truncation and rejects rounding. |
| T-27-20-02 | Repudiation | a run's recorded start/finish time disagreeing with what the caller submitted | medium | mitigate | The contract suite asserts exact equality for all three fields on every backend; fixtures are stamped at the persisted resolution rather than the assertion being loosened. |
| T-27-20-03 | Information disclosure | pagination cursor overlap/gap under equal timestamps | low | mitigate | The `(submitted_at DESC, run_id DESC)` keyset and the existing tie-exercising pagination clause remain unchanged and are re-run on both backends. |
| T-27-20-04 | Denial of service | a weakened assertion masking a broken adapter | medium | accept | Accepted only in the sense that no automated gate can prove an assertion was not weakened; the plan's prohibition plus the explicit `assert_eq!` grep criterion is the control. |
</threat_model>
