## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.eval.yaml` file → harness process | A scenario file is untrusted structured input parsed by a test harness that then runs a graph. |
| Scenario `graph_doc` path → filesystem | A file path from a scenario document is opened by the harness. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-28-05-01 | Elevation of privilege | Scenario content as a code-execution vector | high | mitigate | The format carries only structured parameters; `custom(fn)` is Rust-API-only and never deserialized; `#[serde(deny_unknown_fields)]` closes the document shape; nothing in the harness shells out or loads code from a scenario (OBS-FR-12). |
| T-28-05-02 | Tampering | A scenario written for a newer format silently misparsing | medium | mitigate | `schema_version` checked before use with a typed `UnsupportedSchemaVersion { found }`; a golden JSON Schema documents the accepted shape (X-04). |
| T-28-05-03 | Information disclosure | Captured request log carrying prompt text into failure output | low | accept | The log is test-harness-local and exists precisely to render a failure; scenarios are scripted with fixture prompts, not production data. Documented in `requests()`'s rustdoc. |
| T-28-05-04 | Tampering | Supply-chain risk from the two new dependencies | medium | mitigate | `glob` 0.3.4 and `libtest-mimic` 0.8.2 both cleared the package-legitimacy audit with an `OK` verdict, are MIT/Apache-2.0 already in `deny.toml`'s allowlist, and clear MSRV 1.88 with headroom; `make security` runs at the phase close-out. |
