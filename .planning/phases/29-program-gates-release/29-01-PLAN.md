<objective>
Prove — not assert — that a v0.9 operator's configuration boots this v0.10 binary with v0.9
behavior. Freeze the v0.9 configuration files from the `v0.9.0` tag with checkable provenance, then
write one root integration test that loads the v0.9-shaped file, asserts every v0.10 config surface
resolves to its own inert `Default`, composes the real server routers from that `Settings`, and
asserts the v0.9 route set answers v0.9 status codes while every route family new in v0.10 answers
`501`.

Purpose: SHIP-02's first half, per D-06/D-07/D-09. Phase 27 designed every platform config struct to
default off and every new route to answer `501` when unwired precisely so this test could pass by
construction (27-DISCUSSION-LOG line 216); this plan is where that design claim becomes a gate.

Output: two frozen fixtures with a provenance record, a `v0_9_config_boot` test target, and the
`[[test]]` registration that makes it runnable by name.

**Recorded deviation from D-06's literal wording (RESEARCH Open Question 1, option (b)).** D-06 asks
for `git show v0.9.0:config.example.yml` committed verbatim as *the* fixture the test loads. That file
does not parse through `Settings::load_from_file` at v0.9.0 OR at HEAD — `LlmProviderConfig::api_key`
is a required `String` and the `ollama:` block has never carried one (verified by execution, RESEARCH
Pitfall 1). This is pre-existing and cross-cutting, not introduced here. Resolution: freeze BOTH
files. `v0.9.0-config.example.yml` is kept verbatim as documentation evidence of what a v0.9 operator
actually has; `v0.9.0-config.test.yml` — frozen from the same tag, and at that tag it is HEAD's file
minus exactly the `trace:` and `web_server:` sections added in Phase 28, so it is authentically
v0.9-shaped — is the file the test loads, following the `test_load_from_file_regression` precedent.
Neither is hand-trimmed.

**Recorded deviation from D-09's literal wording.** D-09 states both compat tests are ordinary
`cargo test --workspace` targets gated by the `test` job. Verified false for this one: CI's `test` job
runs `cargo test --workspace --lib --bins` and `--doc` only (`.github/workflows/ci.yml:438-441`) — no
root integration target — and `web-server` is not a default feature, so the target needs
`required-features = ["web-server"]` and is skipped by both the `test` job and the
`integration-tests` job's `--features integration-tests` sweep. D-09's intent (no NEW CI job) is
honored in plan 29-05, which adds a step to the EXISTING `e2e-platform-api` job — already
`--features web-server`, already carrying a zero-tests-selected guard.
</objective>
