<objective>
Make two mechanical gates say what they already claim. The `semver` job's allowlist check compares
sorted unique CRATE NAMES, so nine rows and nine entries pass even if a row and an entry name
different types under the same crate — SHIP-01 says "matching exactly", so the comparison is tightened
to `crate | type` pairs, both directions, no wildcards. And `make publish-dry-run` is today a loop
that swallows every failure with `|| true`, addresses a package by a directory name that can never
resolve, omits `paladin-herald`, and points the reader at a file that does not exist — it is rewritten
to the one command that actually works.

Purpose: SHIP-01 (D-04) and SHIP-04 (D-20). Both are prerequisites for honest evidence later in the
phase: the row-level gate is what makes §9.2's "matches the allowlist exactly" a durable claim rather
than a point-in-time observation, and a `publish-dry-run` target that cannot fail is not evidence of
anything.

Output: a tightened CI step, a working Makefile target, and a release-checklist section that matches
the twelve-crate reality.

This plan has no `type="tracer"` task: it modifies two independent single-file gates with no layered
path to trace through, and a synthetic "thin slice" would add ceremony without information. The
tracer for this phase is plan 29-01's boot test.
</objective>
