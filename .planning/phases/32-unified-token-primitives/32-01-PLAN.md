<objective>
Collapse the first of this phase's two duplications: the counting contract. `TokenCounterPort`
gains a defaulted exactness signal (D-06), `TiktokenCounter` overrides it to `true` while
`HeuristicTokenCounter` inherits the `false` default (D-07), and `Commissary` stops asking its
caller for an exactness flag — it reads the port instead, with the cached field gone (D-08). The
consolidated one-way checkpoint that opens this plan covers both this constructor break (D-08) and
the legacy-pair removal plan 32-03 performs (D-09), so no later plan in the phase needs its own
stop.

Purpose: today a caller passes `Commissary::new` a boolean asserting which concrete counter it
injected. That is a second, mutable source of truth for a fact the counter already knows, and
nothing prevents the two from disagreeing — a caller that mis-declares an approximate counter as
exact makes every `Stockpile` consumer under-budget its own margin against a real provider window.
Moving the signal onto the port removes the possibility of disagreement rather than documenting it.

Output: `TokenCounterPort::is_exact` with a doc-tested `false` default; an exactness test on each
adapter; a `Commissary` with one fewer field and one fewer constructor argument whose
`Stockpile.exact_tally` is read live from the injected port; and the mdBook Commissary page rewritten
against the new signature.
</objective>
