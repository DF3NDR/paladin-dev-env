<objective>
Close the phase's release bookkeeping so v0.10.0 stays releasable: empirical semver-lint discovery
with the mandatory minor release-type flag and the feature-gated second pass (D-14), one MIGRATION.md
section 9.2 row per crate-and-type pair a lint actually fired for with its matching allowlist entry in
the same commit (D-15), the three CHANGELOG bullets (D-16), the reader-facing Token primitives
subsections on the upgrading and migration-guide pages (D-12), and the recorded phase gate evidence.

Purpose: every break this phase shipped is invisible to a downstream upgrader unless it is written
down, and the row-level set-equality gate turns "written down" into something CI enforces rather than
something review has to notice. Two traps make this non-mechanical. A discovery run without the minor
release-type flag reports zero checks and exits 0 — which reads as "nothing broke" when it means
"nothing was evaluated". And the legacy counting pair sits behind a cargo feature that CI's
default-features run cannot see at all, so its removal produces no CI output and must be discovered by
a second, feature-enabled run.

Output: six recorded discovery runs, a section 9.2 register and an allowlist that are set-equal at the
row level, per-crate lint tables wherever a default-features run needs one, three CHANGELOG bullets,
two migration subsections, and a SUMMARY carrying the complete PRIM-05 gate evidence.
</objective>
