<objective>
Open the crate seam and drive the first production `Commissary::dispense` call through the real RAG
path. Two commits: an enabling, code-free manifest/doc commit for the new `paladin-memory` →
`paladin-llm` production edge (D-01, D-03), then the tracer — one retrieval wired end to end from
`SanctumPort::search` through the new `ration` seam (D-14), through `Commissary::dispense` over
synthetic capabilities (D-04, D-06), out through a new result struct (D-12) and a new error enum
(D-13), and all the way into the facade's system-prompt injection path, with every existing
consumer migrated in the same commit so the workspace is green at every commit.

The legacy inline byte-length truncation helper and its silent drop are deleted here; the marker
and observability surface (COMM-02) lands in 33-02, the property/edge proof in 33-03, the F4
integration evidence in 33-04.

D-02 is settled and is NOT reopened by any task here: rationing does not move up into the facade
application layer (that would leave `paladin-memory`'s own retrieval either unbounded or silently
truncating, and the success criterion names `RagRetrievalService` itself), and `Commissary` does
not move into `paladin-ports`/`paladin-core` (Phase 32 locked the resolver in `paladin-llm`, and
relocating it would be a second §9.2 break with no caller asking for it).

Purpose: `Commissary` has had no production caller since ADR-0049; this is the caller, and it is
where the last silent token-truncation path in the tree is removed (COMM-01).
Output: a rationed RAG path with a shed record, plus the crate edge that makes it reachable.
</objective>
