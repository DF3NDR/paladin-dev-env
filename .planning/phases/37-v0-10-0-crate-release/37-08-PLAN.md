Three steps, strictly in this order.

**Step 1 — Merge the PR with the merge-commit method.** Not squash, not rebase. This repository
has all three methods enabled and the ruleset does not constrain the choice, so the method is
yours to get right: the tag is cut on the merge commit, and 204 plans' SUMMARYs and audits cite
SHAs that must stay reachable from `main` (D-04). All required status contexts must be green on
the post-tick head first; there is no bypass actor on the `main` ruleset, so a green PR is the
only path.

```
gh pr merge <PR-number> --merge
```

Then capture the merge commit SHA:

```
gh pr view <PR-number> --json mergeCommit --jq '.mergeCommit.oid'
```

**Step 2 — Wait for `ci.yml` to conclude success on that merge commit.** Roughly 60-90 minutes.
Do not tag before it finishes. The release pipeline's pre-publish consistency gate queries for a
recorded `success`-concluded `ci.yml` run on the tagged SHA itself; tagging early makes that gate
report a CI mismatch, and the documented recovery is to re-run the same release run once CI
catches up — avoidable noise on release day.

```
gh run list --workflow ci.yml --branch main --json headSha,status,conclusion
```

**Step 3 — Create and push the annotated tag on the merge commit.**

```
git fetch origin
git tag -a v0.10.0 <merge-commit-sha> -m "v0.10.0 Durable Agent Execution Runtime"
git push origin v0.10.0
```

The tag must point at the merge commit itself, not at any other ancestor of `main` — the pipeline
verifies the tagged commit is contained in `main`, and this phase's own verification asserts the
stronger fact that the tagged commit *is* the merge commit.

**Then the phase stops.** No watcher is parked (D-12). `release.yml` takes tens of minutes. Resume
the phase when this exact condition holds:

> tag `v0.10.0` exists on `origin` and points at a commit contained in `main`

checkable with:

```
git fetch --tags origin && git rev-parse v0.10.0^{commit} && git merge-base --is-ancestor v0.10.0^{commit} origin/main
```

On resume, plan 37-09 re-verifies that condition first, creates `chore/37-close` from the tagged
