  <action>
Derive, query, assert, then record — in that order, so no step can be satisfied by assumption.

1. **Derive** the publishable-crate list live: `cargo metadata --no-deps --format-version 1`,
   selecting packages whose `publish` field is unrestricted (a `publish = false` crate reports a
   non-null, empty registry list — that is how `paladin-doc-examples` is excluded). Record the
   derived names and the derived **count** verbatim in the section's opening line. Do not write a
   literal crate list or count anywhere in the loop.
2. **Query** the sparse index once per derived name, building the path from the name's length
   (one- and two-character names use their length as the prefix directory, three-character names
   use `3/<first char>`, four-or-more use `<first two>/<chars three and four>`), and always sending
   the `User-Agent` header — crates.io rejects requests without one, a documented incident-time
   trap. For each crate select the record whose version is `0.10.0` and capture `name`, `vers`,
   `cksum` and `yanked`.
3. **Assert** three things, each explicitly:
   - the number of rows produced equals the derived count from step 1;
   - the derived count is greater than zero (a `cargo metadata` filter that silently matches
     nothing must fail here, not pass quietly);
   - every row reads `yanked` false.
   A crate that 404s, or returns no `0.10.0` record, produces a missing row and therefore fails
   the count assertion. **The loop finishing without an error is not the proof** — the count
   equality is.
4. **Cross-check** the row set against the `publish-crates` per-crate outcome table plan 37-09
   transcribed: every crate the job reported as published-now or already-at-this-version must have
   a registry row, and any discrepancy is recorded as a finding and stops the plan.
5. Record the table under `## Registry verification (D-08)` with columns for crate, version,
   checksum, `yanked`, and the index path queried, plus a closing line giving the derived count,
   the row count, and the assertion result. Commit on `chore/37-close` with the plain-git form.
  </action>

    - The table has exactly one row per derived crate, each with a non-empty checksum and `yanked` false at version `0.10.0`
    - The closing line states the derived count, the row count, and that they are equal, and that the derived count is greater than zero
