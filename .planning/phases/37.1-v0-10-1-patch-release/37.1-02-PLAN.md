<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `cargo metadata` output → the gate's view of the dependency graph | The metadata view is the only admissible source; hand-parsing manifests would miss workspace inheritance, aliased packages and future manifest syntax |
| `scripts/publish-crates.sh`'s `CRATES` array → the gate's view of the publish order | A second copy of the order inside the gate would drift silently and defeat the gate's entire purpose |
| committed fixture → the claim "the gate would have caught `v0.10.0`" | A hand-written fixture would make the claim unfalsifiable; the fixture is captured from a worktree of the tagged commit |

## STRIDE Threat Register (ASVS L1; block on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37.1-05 | Spoofing | A gate that reports success without analysing anything | high | mitigate | A missing or unreadable metadata file is a named failure, never an empty-input pass; an unset or empty `CRATES` array after sourcing is a named failure; the success line reports the number of crates and edges actually checked. |
| T-37.1-06 | Tampering | Silent drift between the gate's crate set and the real publish order | high | mitigate | The gate asserts set-equality between `CRATES` and the metadata-derived publishable set in both directions, and an acceptance criterion greps the gate script for any hard-coded crate-name list. |
| T-37.1-07 | Repudiation | The red-on-`1d4a9724` claim | high | mitigate | The fixture is captured by `cargo metadata` inside a worktree of the tagged commit; Task 3 records the commit, the command and the removal, and the committed test asserts the failure names all three crates. |
| T-37.1-08 | Information Disclosure | A gate reaching the network during CI | medium | mitigate | The gate has no network call at all; its header states this, and the regression harness drives it entirely through the JSON-fixture seam. |
| T-37.1-SC | Tampering | Package-manager installs | low | accept | No package is installed by this plan; the gate uses only the already-pinned toolchain and `jq`. See RESEARCH.md § Package Legitimacy Audit for the phase-wide negative. |
