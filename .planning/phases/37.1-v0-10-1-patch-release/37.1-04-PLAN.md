<objective>
Fix the defect that stopped the `v0.10.0` publish at position four, and let the gate prove it.

Purpose: `paladin-battalion` declares two workspace dev-dependencies with version requirements
pointing at crates that publish later in the order. `cargo publish` resolves a versioned
dev-dependency against the live registry even when build verification is skipped, so the real
release run failed deterministically there after three crates had already been published. Dropping
the version requirement makes Cargo omit those entries from the published manifest entirely — no
requirement, no lookup, no ordering constraint. The gate from plan 37.1-02 is already red on this
exact edge, so the fix is verified by watching a real gate turn green.
Output: two edited dependency lines with extended rationale comments, a green gate on the live
tree, and the recorded evidence for both.

Governing constraints: D-08 stage 1 — the build wave, where the agent fixes what is inside the six
success criteria. D-00d — the workspace-wide observation is recorded, not acted on.

**Ordering note for later plans.** The per-crate `cargo package` check in this plan is valid
*because it runs before the version bump*. Once plan 37.1-06 bumps the workspace to the patch
version, a per-crate package or publish check against the live index cannot succeed for any crate
whose siblings are not yet published at that version — which is precisely why the new gate is a
static ordering assertion rather than a live per-crate rehearsal. Later plans must not re-run this
task's package command and read its failure as a regression.
</objective>
