<objective>
Put the release candidate in front of CI and the maintainer, then stop cleanly.

Purpose: one branch, one pull request, one merge commit, one tag. Opening the pull request is also
the only way to get the one gate this environment cannot measure — the coverage floor — and the
only way the new publish-order gate gets exercised pre-merge, which is the whole reason it was
wired into a job that runs on pull requests. After that, waiting is not work: the phase stops with
a written resume condition instead of holding a session open.
Output: the branch pushed, the pull request opened with a curated body, and a resume file naming
the exact condition under which the next plan may start.

**This plan is not autonomous.** It contains a conditional blocking checkpoint (a credential that
cannot perform the write) and ends in a hard stop.

Governing constraints: D-07 (one pull request, curated body), D-00b (the agent never merges),
D-00i (waiting is a hard stop with a resume file), D-08 stage 2 (record red, fix nothing),
D-00e (the coverage floor is measured by the pull-request run).

`/gsd-execute-phase` orchestrator. Do not dispatch plan 37.1-09 on a timer, and do not spawn an

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → the protected default branch | The agent pushes only to its own branch and opens a pull request; every path by which code reaches the default branch runs through the maintainer |
| a pull request's settings → an unattended merge | Auto-merge, an approval, or a merge-on-green setting would turn a green run into a merge with no human act |
| waiting → a parked process | A watcher left running is an agent holding a session open against an outcome it cannot influence, and it is exactly what the resume-file rule exists to prevent |
| a read-only credential → an improvised workaround | A failed write must surface as a hand-over, not be routed around |
