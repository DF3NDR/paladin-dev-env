<objective>
Turn the pull request's run into evidence, then put the sign-off in front of the maintainer.

Purpose: the sign-off has to cover more than a local sweep. The coverage floor is measured only
here, and the new publish-order gate's whole value depends on it having actually executed on a
pull request rather than merely existing in a file. Both are read from the real run and written
down. Then the box — minted unticked in plan 37.1-07 — is presented for the only act that can tick
it.
Output: a CI-run table for the recorded head SHA, the coverage figure, the publish-order step's
execution proof, updated re-seal rows, and a blocking checkpoint at the sign-off.

**This plan is not autonomous.** It ends at a blocking human checkpoint and carries a conditional
halt on any red check.

Governing constraints: D-00a (only the maintainer ticks), D-00e (the coverage floor is this run's
to measure), D-08 stage 2 (record red, halt, fix nothing), D-09/D-10 (the box's evidence basis and
the fixed order of events).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a pull request's aggregate status → the actual per-job record | An aggregate can read green while a job that matters never ran; only per-run, per-job conclusions are admissible |
| a gate that exists → a gate that ran | The previous tag failed because a gate that looked like coverage was structurally blind; "it is in the file" is not the same claim as "it executed on this pull request" |
| agent → sign-off state | The tick is the gate on an irreversible act and is a human-only edit |
| a red check → a retry | Re-running a failed check to get a different answer converts evidence into noise |

## STRIDE Threat Register (ASVS L1; block on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37.1-36 | Elevation of Privilege | An agent ticking the sign-off box | high | mitigate | The checkpoint presents the exact edit and stops; a prohibition forbids authoring the edit; an acceptance criterion asserts the file's ticked-box count is unchanged from the base commit after the agent's own commits. |
| T-37.1-37 | Spoofing | A gate recorded as covering the pull request without having executed on it | high | mitigate | Task 1 records the publish-order step by name from the job's log as its own evidence row, separate from the job's conclusion. |
| T-37.1-38 | Spoofing | An expected coverage figure recorded as measured | high | mitigate | The figure is read from the run's log; an unreadable figure is recorded as unreadable rather than as a pass; a prohibition forbids recording an expected number. |
| T-37.1-39 | Repudiation | Evidence describing a different commit than the one reviewed | high | mitigate | Task 1 confirms the head SHA still matches the resume file before recording, and stops on a mismatch; runs are queried by SHA rather than by branch. |
| T-37.1-40 | Tampering | A red check retried until green | high | mitigate | A prohibition forbids re-running, re-dispatching or cancelling any run; a red check is recorded verbatim and the plan halts. |
| T-37.1-SC | Tampering | Package-manager installs | low | accept | No package is installed. See RESEARCH.md § Package Legitimacy Audit. |
