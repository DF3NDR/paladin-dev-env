<objective>
Open the post-tag wave: prove the tag sits where the evidence says, move onto the close-out branch,
and record what the release actually did.

Purpose: this phase stays open across the merge precisely so the release is verified by observation
rather than by promise. The previous attempt's whole failure mode was a pipeline that reported a
partial success in a way nobody read carefully enough. So the tag's identity is proven by equality
rather than ancestry, and publish health is read from the publish job's own per-crate table rather
than from a workflow-level conclusion that mixes in unrelated matrix jobs.
Output: the tag-equality proof, the `chore/37.1-close` branch carrying the deferred artifacts, and
the release run's per-crate outcome table.

**This plan is not autonomous.** A red release run is a hard stop.

Governing constraints: D-00c (merge commit, annotated tag after green), D-00i (resume condition),
D-00j (read-only diagnosis, hard stop), D-12 (the close-out branch).

1. Fetch the remote including tags, then resolve the tag to its commit.
2. **Containment:** confirm the tagged commit is contained in the default branch.
3. **Equality — the check that matters.** Resolve the pull request's merge commit from the remote

   and message.

   merge commit, and record whether the tag was pushed after that run concluded success. This is
   the documented precondition; record what actually happened either way rather than assuming it
   held.

   exist yet, and Task 2 creates it.
8. If the equality check fails, or the merge commit has one parent, or the tag is lightweight,
   **stop** and record it. The release that shipped is not the one this evidence describes, and
   reconciling that is the maintainer's decision, not a fix this phase makes.

| Boundary | Description |
|----------|-------------|
| the tag → the released artifact's identity | The tag's commit is what was published; a tag on any other ancestor would mean the evidence describes a different tree than the one on the registry |
| the workflow's overall conclusion → publish health | The overall conclusion mixes unrelated matrix jobs with publishing; only the publish job's own table is admissible |
| the close-out branch → the protected default branch | Post-tag records reach the default branch through a small documentation-only pull request; the ruleset is never bypassed and the tagged commit is never altered |
| agent → post-tag remediation | Re-dispatch, complete-forward, publish and yank are the maintainer's; the agent's authority ends at read-only diagnosis |
