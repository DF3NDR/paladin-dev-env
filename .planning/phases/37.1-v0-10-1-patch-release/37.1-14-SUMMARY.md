# Phase 37.1 Plan 14: Orphan Disposition and Release-Object Banner Summary

**Three orphaned v0.10.0 crates confirmed yanked and registered one row each; the v0.10.0 GitHub Release bannered, flipped to pre-release, and its 43,373-byte body proven byte-identical below the notice by an independent post-edit diff.**

## Performance

  earlier turns of this engagement and are recorded in `37.1-CI-EVIDENCE.md`)

## Accomplishments

- **Task 1 (checkpoint, resolved by maintainer's prior act).** The yank checkpoint's own gate —
  every publishable crate reading `0.10.1` present and not-yanked — was satisfied and recorded
  by plan 37.1-12 Task 3 and plan 37.1-13's count-asserted table before the maintainer acted.
  The maintainer had already run all three `cargo yank --version 0.10.0 <crate>` commands
  out-of-band with their own credential, reported verbatim as "all three yanked." Per the
  orchestrator's explicit instruction, the checkpoint was not re-presented as a live prompt in
  this session — it was recorded as already resolved, in the correct order.
- **Task 2 (register rows).** Re-read `index.crates.io` for all three orphans
  (`paladin-ai-core`, `paladin-ports`, `paladin-herald`) at `0.10.0`: all three `yanked: true`,
  matching the maintainer's reply exactly. Appended one register row per crate (never a
  summarising fourth row) to `docs/src/appendix/release-recovery.md` §5's yank register, reason
  text identical for all three per D-01: "Not defective — orphaned partial publish of `v0.10.0`,
  superseded by `0.10.1`." Owner `Am0rfu5`, date `2026-09-21` (the date of the out-of-band act).
- **Task 3 (checkpoint, "Run it").** The maintainer's verbatim reply was "Run it." The original
  release body was fetched to a file before anything was presented (43,373 bytes); a short dated
  notice was drafted separately (737 bytes, 12 lines); the two were concatenated, notice first,
  never editing the original in place. The orchestrator then ran
  `gh release edit v0.10.0 --prerelease --notes-file target/37.1-14/v0100-body-new.md` (exit 0)
  and verified read-only: `isPrerelease: true`, body 43,945 characters, `releases/latest` ->
  `v0.10.1`.
- **Task 4 (this session — independent verification and record).** Ran a fresh, independent
  read (`gh release view v0.10.0 --json isPrerelease,tagName,body`,
  `gh api repos/DF3NDR/paladin-dev-env/releases/latest --jq .tag_name`, `git rev-parse
  v0.10.0^{commit}`), separate from the orchestrator's own earlier capture. Result:
  `isPrerelease: true`; `tagName: v0.10.0`; `releases/latest` tag = `v0.10.1`; the tag still
  resolves to `1d4a9724cc219b85856a23012543458d62559e47` — unchanged. Sliced the freshly-read
  body's first 12 lines (the notice's own line count) and diffed the remainder directly against
  the pre-edit original file (`target/37.1-14/v0100-body-original.md`): `diff` exit 0, zero
  lines differ. Recorded all of this, plus the Task 3 narrative, in `37.1-CI-EVIDENCE.md`.
- **No agent yank, un-yank, publish, or release-object edit was run by any agent's own
  initiative.** The one write in this plan (`gh release edit`) was run only because the
  maintainer said "Run it" at the Task 3 checkpoint; every other command across all four tasks,
  including this task's own verification, is a read-only, unauthenticated query.
