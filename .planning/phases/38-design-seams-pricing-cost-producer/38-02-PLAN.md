<objective>
Prove the phase's architecture end-to-end on its thinnest path, then pin the cost arithmetic.

Task 1 is the phase's single tracer: an operator-style price table → the `PricingLlmAdapter`
decorator at the `LlmPort` boundary (D-09) → a priced terminal stream chunk (D-10) →
`PaladinExecutionService`'s streamed-completion producer building `ExecutionMetadata` (D-12) →
`Herald::finalize_stream` rendering `0.0225 USD` (D-04). It creates the domain types in
`paladin-core` (`Cost`, `CurrencyCode`, `PriceRow`, `PriceTable`, `cost_of_call`) with the real
D-02/D-06 formula, the streaming carriers on the two `#[non_exhaustive]` port types, the D-08
warn-once rule, the D-03 display-edge conversion and the D-12 rustdoc rewrite. Task 2 drives the
cost function and the run-level `CostTally` through every axis, rounding and boundary case.

Purpose: if the cost type cannot cross `paladin-core` → `paladin-ports` → `paladin-llm` → the
facade's execution service → a herald without an architectural change, every later plan is wasted.
This slice touches no struct literal anywhere (both port types it extends are `#[non_exhaustive]`
and built through constructors), so it lands before the heavy carrier migrations in 38-04/06/07.

Output: `cost.rs`, `pricing.rs`, the streamed agent-loop `ExecutionMetadata` producer,
`finalize_stream_output`, currency-aware markdown cost rendering, and the herald rustdoc now
stating the field is produced by the Treasurer.

**Expansion owners (not deferrals):** non-streaming `generate()` pricing lands in 38-04 with
`LlmResponse.cost`; config parsing and production wiring in 38-03; JSON/table heralds in 38-05;
engine carriers in 38-06/38-07; the engine-side producer in 38-08.

**Reversibility:** the `Cost` amount unit is D-02 (one-way — Phase 39 persists it). The operator
chose i64 nano-units explicitly in `/gsd-discuss-phase` (38-DISCUSSION-LOG.md, Price units Q2), so
per `references/planner-reversibility.md` the rating is recorded on Task 1 and not re-asked.

**1. `crates/paladin-core/src/platform/container/cost.rs` (new; add `pub mod cost;` after `content_list` in `mod.rs`).** Module docs state: amounts are `i64` nano-units (1e-9) of one operator currency (D-02, D-00b — no FX, no multi-currency hooks); prices are nano-units per 1M tokens (D-01); a call is rounded once, half-up; no floating-point type appears in this module. Define:
- `CostError` (`thiserror`): `InvalidCurrencyCode(String)` rendered `currency code must be exactly three ASCII uppercase letters (got {0:?})`; `NegativePrice { axis: &'static str, nanos_per_million: i64 }`.
- `CurrencyCode` — newtype over a private `String`; `CurrencyCode::new(&str) -> Result<Self, CostError>` accepts exactly three bytes each in `b'A'..=b'Z'` (D-04); `as_str()`; `Display`; serde through `#[serde(try_from = "String", into = "String")]` with `TryFrom<String>` and `From<CurrencyCode> for String`, so deserializing an invalid code is an error. Derive `Debug, Clone, PartialEq, Eq, Hash`. No `Default`.
- `Cost` — private `nanos: i64`, `currency: CurrencyCode`; `Cost::new(nanos, currency)`, `nanos()`, `currency()`; derive `Debug, Clone, PartialEq, Eq, Serialize, Deserialize`; deliberately NO `Default` (a zero with a fabricated currency contradicts D-00c). `checked_add(&self, &Cost) -> Option<Cost>` returns `None` on a currency mismatch, else the `saturating_add` sum. `impl Add`/`AddAssign` saturate and keep the left operand's currency (rustdoc: aggregate across calls with `CostTally` or the `Option` sum, which refuse a mismatch). `impl std::iter::Sum<Cost> for Option<Cost>`: empty iterator → `None`, any mismatch → `None`, else `Some(saturating sum)`.
- `PriceRow` — private `prompt: i64`, `completion: i64`, `cache_read: Option<i64>`, `cache_write: Option<i64>`, `reasoning: Option<i64>`, all nano-units per 1M tokens; `PriceRow::new(prompt, completion) -> Result<Self, CostError>` and `with_cache_read`/`with_cache_write`/`with_reasoning(self, i64) -> Result<Self, CostError>` reject a negative value with `CostError::NegativePrice` naming the axis (`"prompt"`, `"completion"`, `"cache_read"`, `"cache_write"`, `"reasoning"`); zero is valid (D-07 free tier); getters for each axis. Derive `Debug, Clone, PartialEq, Eq`.
- `pub fn cost_of_call(usage: &TokenUsage, row: &PriceRow, currency: &CurrencyCode) -> Cost` — the pure D-06 function: clamp first so billed tokens never exceed the reported parent (`cache_read' = min(cache_read or 0, prompt)`, `cache_write' = min(cache_write or 0, prompt − cache_read')`, `reasoning' = min(reasoning or 0, completion)`); base prompt `= prompt − cache_read' − cache_write'`, base completion `= completion − reasoning'`; each of the five products is `u32` tokens widened to `i128` times the axis price widened to `i128`, where an omitted cache price uses the prompt price and an omitted reasoning price uses the completion price; sum the five `i128` products, then divide by `1_000_000` with half-up rounding exactly once (`(sum + 500_000) / 1_000_000` — the sum is non-negative), then convert to `i64` saturating at `i64::MAX` (D-02).
- `PriceTable` — private `currency: CurrencyCode`, `rows: BTreeMap<String, PriceRow>`; `new(currency)`, `with_row(self, model: impl Into<String>, row: PriceRow) -> Self`, `currency()`, `row(&str) -> Option<&PriceRow>`, `is_empty()`, `len()`, and `price(&self, model: &str, usage: &TokenUsage) -> Option<Cost>` — an exact, case-sensitive bare-model-name lookup (D-05, no normalization); a present row always yields `Some` (D-06); an absent row yields `None`. Derive `Debug, Clone, PartialEq`.
