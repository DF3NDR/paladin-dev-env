<objective>
Turn the ledger on in production: the worker hands each per-run engine the ledger and the run's
persisted attempt (D-07), agent-kind runs carry their Platform run id to the agent loop, and the
server builds the ledger from `RunStoreConfig` for the run API, the worker and HTTP agents.

Purpose: LEDGR-04's "ledger fills in ordinary operation" (D-08) and LEDGR-03's "lease redelivery,
resume … never charge twice" only become true when production code supplies the right key; this plan
proves both through the worker and an HTTP end-to-end test.

Output: `RunWorkerPool::with_treasury_ledger`, `build_treasury_ledger`, the server boot wiring, and
the end-to-end test.
</objective>

| Boundary | Description |
|----------|-------------|
| operator config/env → ledger database | `APP_RUN_STORE_*` pick the database; a Postgres URL may carry a password |
| queue redelivery → settlement key | a redelivered lease re-executes supersteps and must produce new keys, while duplicate deliveries of one settlement must not |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-39-03 | Repudiation (double charge / missed re-spend) | worker attempt capture | high | mitigate | attempt = `bump_attempt`'s returned value on redelivery, `run.attempt` otherwise; `redelivered_running_run_settles_under_the_bumped_attempt`; store-side idempotency from 39-02/03 |
