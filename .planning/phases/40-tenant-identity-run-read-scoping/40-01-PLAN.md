  <decision>Approve the identity-carrier shape, the submission-port retype and the persisted run-attribution columns below (implements D-01, D-04, D-09), or redirect them, before any of them is written.</decision>
  <context>
Why this gate exists: 40-CONTEXT.md was gathered in `--auto` mode -- every gray area took the recommended option and no operator answered. Three decisions are rated **one-way**: D-01 (`Principal` is a published `paladin-web` type with public fields; a required field breaks every external constructor), D-04 (a published `paladin-ports` trait signature and two published structs change type), D-09 (persisted columns; reshaping later needs a data migration). D-05 (required `tenant` config key) and D-11 (tenant visibility unit with an Admin bypass) are rated **costly** and land in the same tracer without a gate.

Proposed design:
- **D-01:** `Principal { pub id: String, pub role: UserRole, pub tenant_id: TenantId }`, required, no `Option`. `TenantId` is a new `paladin-core` newtype in `principal.rs`: non-empty, no whitespace (an untrimmed value is rejected, never trimmed), printable ASCII only, at most 128 bytes (`TENANT_ID_MAX_LEN`; `ThreadId` allows 256 -- 128 keeps the new index key short), validated on deserialize too. Planner addition for X-10.3: mark `Principal` `#[non_exhaustive]` and add `Principal::new(id, role, tenant_id)` -- `Principal` has no `Default`, so every external literal breaks either way, and option (a) (the `LlmRequest`/`GarrisonEntry` precedent in MIGRATION.md 9.2) makes the next field free. Bearer principals take a deployment-level tenant from a new `AgentAuthConfig.bearer_tenant: Option<TenantId>` (a verified bearer token while it is `None` does not authenticate -- fail closed); open-access keeps `role = Admin` and gets the sentinel tenant `open-access`.
- **D-04:** `PrincipalRef { api_key_id: String, tenant_id: TenantId, role: UserRole }` replaces `(String, UserRole)` on `SubmitRun.requested_by`, `ForkRun.requested_by` and `RunSubmissionPort::cancel(.., requested_by)`; `None` keeps meaning "internal caller, skip the role check".
- **D-09:** `008_add_run_attribution_columns.sql` in BOTH `migrations/sqlite/` and `migrations/postgres/`: `ALTER TABLE runs ADD COLUMN tenant_id TEXT NULL`, `ALTER TABLE runs ADD COLUMN api_key_id TEXT NULL`, `CREATE INDEX IF NOT EXISTS idx_runs_tenant_submitted ON runs(tenant_id, submitted_at DESC, run_id DESC)` (non-unique, so `idx_runs_thread_active` stays the only unique index `002`'s header requires). `NULL` means "no principal recorded"; role is never persisted; the ledger's sentinel string is never written to `runs`. `RUN_SCHEMA_VERSION` stays `v1` (X-04: additive).
  </context>
