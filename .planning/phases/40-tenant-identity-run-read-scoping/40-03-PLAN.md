<objective>
Harden the boot rule the tracer introduced into the house config shape: one `AuthConfig::validate()`
that fails closed on every malformed key/tenant/bearer entry with a message naming the entry, and
document the mapping for operators.

Purpose: TENANT-01's "operator config maps each API key to a tenant" is only trustworthy if the
mapping is unambiguous -- a duplicated key value would make `lookup_api_key` resolve an arbitrary
principal (and so an arbitrary tenant), and a duplicated name would merge two keys' attribution.

Output: `AuthConfig::validate`, its boot wiring and tests, and the deployment-topology docs.
</objective>
