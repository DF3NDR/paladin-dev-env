**Resolution.** `resolve(&self, currency)` now: rejects a global `warn_at > 100` (`treasurer.allowance.warn_at must be an integer percent between 0 and 100 (got 101)`); builds `AllowancePolicy::new(currency.clone(), self.warn_at)`; iterates `tenants` then `api_keys` in `BTreeMap` order; validates each map key with `TenantId::new` (error `treasurer.allowance.tenants: "<key>" is not a valid tenant id: <TenantIdError>` / `treasurer.allowance.api_keys: "<key>" is not a valid API key name: ...`); parses `period` and `amount` as in 41-01 and, when present, `lifetime` with the same decimal grammar and the same positive-only rule; rejects an entry `warn_at > 100`; builds `ScopeAllowance::new(period_secs, amount_nanos)` plus `with_lifetime`/`with_warn_at`. A `webhook` with an empty `url` is rejected (`treasurer.allowance.webhook.url must be a non-empty http(s) URL`); scheme and address checks belong to the SSRF guard at wiring time (41-08). `period` and `amount` stay required on every entry -- a lifetime-only entry is not expressible (Task 1 item 8 of 41-01; document it).

**Cross-check.** `pub fn validate_against(&self, known_tenants: &BTreeSet<String>, known_api_keys: &BTreeSet<String>, run_store_disabled: bool) -> Result<(), String>`: empty allowance -> `Ok`; non-empty with `run_store_disabled` -> `treasurer.allowance has entries but run_store.backend is disabled -- allowances are enforced against the spend ledger, which needs a run store (set run_store.backend)`; each `api_keys.<name>` absent from `known_api_keys` -> `treasurer.allowance.api_keys.<name> names no key in http.auth.api_keys -- a removed key must also lose its allowance entry; its surviving schedules stay gated by their tenant's allowance (C12)`; each `tenants.<id>` absent from `known_tenants` -> `treasurer.allowance.tenants.<id> names a tenant no http.auth.api_keys entry or http.auth.bearer_token.tenant maps to`.
