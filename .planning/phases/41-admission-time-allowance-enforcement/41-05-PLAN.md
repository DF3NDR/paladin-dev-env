<objective>
Bring schedule-fired runs under allowances (D-08, the operator's deliberate departure): persist the
creator on the schedule row, attribute and admit every fired run against that creator, record an
allowance-refused tick as a counted skip, and keep the role check behaviour exactly as it is today
(a written decision, C13).

Purpose: a schedule created by a key that later exhausts its allowance must not keep spending on its
behalf -- the tick is the one admission path with no HTTP caller.

Output: migration `010` on both backends, `RunSchedule.created_by`, `CreateRunSchedule.created_by`,
`SubmitRun.attributed_to`, `SkipReason::AllowanceExhausted`, contract clauses, registers, a
WINDOWS.md row and docs.

Scope note (checker scope_sanity): 23 files, but no task touches more than ten -- Task 1 (7 files:
core field, migration `010` on both backends, three adapters, contract clauses) ends at a green gate
on the core and storage suites; Task 2 (10 files) stamps the creator at `POST /v1/schedules` and
admits fired runs; Task 3 carries only registers, docs and the generated API baseline. It stays one
plan rather than a persistence/fire-site plan pair because the one-way migration `010` and its only
consumers form one reviewable unit, and splitting it would renumber 41-06..41-09 and every
cross-reference to them.
</objective>
