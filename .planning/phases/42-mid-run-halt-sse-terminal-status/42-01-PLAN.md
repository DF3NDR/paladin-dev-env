Why this gate exists: 42-RESEARCH.md section "CONTEXT Gaps the Planner Must Resolve" verified seventeen places where the code contradicts or leaves open a CONTEXT decision. D-06 is rated one-way, D-05 and D-12 costly; G5 adds a second one-way schema change the operator did not word. The operator chose every D-NN; this gate confirms HOW each is built. Items cite the gap that shapes them.

Proposed design:
1. **Types and names (Discretion; G4, G6, G17).** `paladin-core` `allowance.rs` gains `HaltReason` -- `#[serde(tag = "reason", rename_all = "snake_case")]`, `#[non_exhaustive]`, variants `AllowanceExhausted(AllowanceRefusal)` and `LedgerUnavailable`, deriving `Eq` (so `AllowanceRefusal` gains `Eq`, additive). The discriminator is named `reason`, NOT `kind`, because the Phase 41 429 `details` object already uses `kind` for the limit kind (G6). `paladin-ports` gains the output port `SpendGuard { async fn check(&self, thread: &ThreadId) -> SpendDecision }` with `#[non_exhaustive] SpendDecision { Continue, Halt(HaltReason) }`, placed beside `cancellation_probe.rs` (D-04). `paladin-battalion` gains `#[non_exhaustive] HaltCause { CancelRequested, Token, Spend(HaltReason) }` on `RunOutcome::Halted { waypoint, cause }` (D-05). `StopReason` gains `AllowanceHalted(AllowanceRefusal)` with wire label `allowance_halted`, `is_limit() == true`, `is_successful() == false` (D-12; `StopReason` is already `#[non_exhaustive]`).
2. **One wire object (D-06, D-14, D-16, G6).** `HaltReason::wire_json()` is the only builder of the caller-facing object: `{"reason":"allowance_exhausted","scope","kind","balance","ceiling","window_start","window_end"}` -- the Phase 41 429 `details` keys plus `reason`, built from one shared `AllowanceRefusal::details_json()` that `ApiError::allowance_exhausted` is refactored to call -- or `{"reason":"ledger_unavailable"}`. `GET /runs/{id}`, `GET /runs`, the SSE `done` (all three paths), the caller webhook key and the agent response all call it. The `runs.halt_reason` column stores the structured serde form (integer nanos plus currency), never display strings (D-00h).
3. **Migrations (D-00i, D-06, D-18, G5) -- one-way.** `013_add_run_halt_reason.sql` (both backends) adds only `runs.halt_reason` (`TEXT NULL` on SQLite, `JSONB NULL` on PostgreSQL, matching `runs.output`). The notice rung is a SEPARATE pair, `014_add_treasury_notice_kind.sql`: `treasury_notices.notice_kind TEXT NOT NULL DEFAULT 'warning' CHECK (notice_kind IN ('warning','halt'))`, and `idx_treasury_notices_once` dropped and recreated with `notice_kind` appended; `notices_for_run` returns only warning rows. (RESEARCH sketched both changes in one `013`; splitting keeps D-06's named file single-purpose and lets the notice change land with its own plan.)
4. **Engine cause and terminal status (D-05, G4).** `RunFinishStatus` stays a `Copy` unit enum, gains `Cancelled` and becomes `#[non_exhaustive]`; the reason rides a new `TraceEvent::RunFinished.halt_reason: Option<HaltReason>` (`#[serde(default, skip_serializing_if = "Option::is_none")]`, the `cost` precedent), so stored `run_traces` rows read back unchanged. Boundary priority: probe cancel, then token, then the spend guard; cancel wins over spend at the same boundary.
5. **Same-instance cancel and drain (G1, D-15).** The worker attaches a per-run `PerRunCancelProbe` answering `db.is_cancelled(t) || (local_child_token.is_cancelled() && !shutdown_token.is_cancelled())`, so a same-instance caller cancel reaches the engine as `CancelRequested`. `map_outcome` keeps re-querying `is_cancel_requested` + `shutting_down` for the residual `Token` cause. A drain emits no `done`: `RunEventBusSink` drops `RunFinished { Halted }` without a `halt_reason` while the coordinator's shutdown token is cancelled.
6. **Status-write order (G14).** For `Halted` and `Cancelled` transitions the worker calls `record_outcome` before `update_status`, so a degraded poller never sees `Halted` without its reason. `replay_stream` emits the run row's `terminal_payload` when a replayed `RunFinished` maps (G10).
7. **Resume (D-07, G7, G13).** `RunResponse` gains additive `final_waypoint_id` and `halt_reason`, so the fork recipe works from `GET /runs/{id}` alone. The cosmetic skipped superstep number on resume is NOT fixed; tests assert vanguard, Battlefield and "completed supersteps are not re-dispatched", never absolute superstep numbers.
8. **Guard behaviour (D-01, D-02, D-03, G11).** One `balance` read per applicable ceiling at every boundary, no debounce, no cached `Continue`; the per-run guard memoises its FIRST `Halt` (shared with child-run clones) so a child halt cannot be silently passed by the parent after a window roll. A failed read for a principal with a ceiling halts with `ledger_unavailable` and logs at `error` (scope kind, tenant id, backend error text; never a key value). A principal with no ceiling never reads the ledger. `requested_by: None` gets no guard.
9. **Wiring order (G3).** `build_run_api` builds the notice store and the `Treasurer` before the worker pool, holds `Arc<Treasurer>` and coerces it to `Arc<dyn AllowanceAdmissionPort>` for the submission service and agent state; `RunWorkerPool::with_treasurer(Arc<Treasurer>)`.
10. **Derived budget (D-09, D-11, G8, G12, G16; A5).** `Treasurer::with_pricing(Arc<PriceTable>)`; one shared `Treasurer::evaluate` serves admission, the guard and derivation (D-17 one function per rule; admission's short-circuit on the first exhausted ceiling is preserved). `max_tokens = floor(min(ceiling - balance) * 1_000_000 / dearest)` in `i128`, `dearest` = the largest of all FIVE `PriceRow` axes with `cost_of_call`'s defaults, saturating to `u32`; a free model (dearest 0) gets no budget; a zero figure is a refusal (429 with the binding ceiling's figures). The HTTP agent routes derive at admission through a new DEFAULTED port method `AllowanceAdmissionPort::admit_for_model(subject, run_id, model)` (default delegates to `admit`, so no implementor breaks); the worker RE-derives at dispatch for agent-kind runs (no persisted figure), and a zero or unreadable figure at dispatch records `Halted` without calling the LLM (`allowance_exhausted` or `ledger_unavailable`); a model that lost its price row between admission and dispatch records `Failed` with a typed error naming the model, also without calling the LLM (a configuration incoherence, not a resume point). When the derived budget halts the loop, the `halt_reason` reports the binding ceiling with `balance` equal to the ceiling (a conservative bound, documented). The shared boot-time `PaladinExecutionService` (worker agent-kind path and every engine node) installs `TokenBudget` in Treasurer-only mode (operator figure forced off) so engine nodes are never capped; per-agent HTTP services install it with the operator's `agent_runtime.token_budget` plus the derived figure, tightest wins, a tie goes to the Treasurer; `configuration.md` documents that the operator budget now takes effect on the HTTP agent routes.
11. **Unpriced model (D-10, Open Question 7).** A principal with a ceiling calling an agent whose model has no `treasurer.pricing` row is refused with `422` and code `model_unpriced`, `details: { "model": <name> }`, no `Retry-After` (a configuration incoherence, not quota exhaustion) -- on the HTTP agent routes and on `POST /runs` for agent-kind assistants (`RunSubmissionError::ModelUnpriced`).
12. **Streamed calls (G2, Open Question 2).** A true streamed `execute/stream` call is one provider call with no `after_model`, so it is admission-only (D-10 and the zero-budget refusal still apply) and is recorded in WINDOWS.md ("a single streamed call is not cut mid-flight; overshoot is that one call"). Its `done` stays byte-identical (`{ "done": true, "usage" }`). The buffered fallback of `execute/stream` and `POST /agents/{id}/jobs` carry the derived budget (jobs is already admitted since 41-04; this phase adds the budget, Discretion). Consequence for D-12 ("the agent stream's terminal `done` carries the same object"): under this proposal it holds for the buffered fallback -- whose `done` IS the serialized `ExecuteResponse`, so it carries `stop_reason: "allowance_halted"` and `halt_reason` -- and NOT for a true stream, because the server never halts a true stream; ADR-0057 and the G2 WINDOWS.md row record that scope. Option-b below extends D-12's stream clause to the true stream.
13. **Operator notices (D-17, D-18, G5; Pitfall 9).** The boundary check also detects a `warn_at` crossing and claims the once-per-window warning notice through the Phase 41 store, emitting the one `TraceEvent::AllowanceWarning` through the run's own trace emitter and the operator `allowance_warning` webhook. A spend halt claims a `notice_kind = 'halt'` notice and enqueues one operator delivery with the new `RunEventKind::AllowanceHalted` (`allowance_halted`), reusing the twelve-key payload with `event` set and `warn_at` = the ceiling's configured threshold (no thirteenth key). `ledger_unavailable` emits no operator notice. The guard memoises "notice already claimed or lost" per ceiling and window so the store write happens once per run, never once per boundary.
14. **Caller legs (D-19).** The caller's `Halted` run webhook payload gains an optional `halt_reason` key (signed once over the stored bytes, unchanged); `HeraldTraceSink` folds `RunFinished.halt_reason` into one herald line rendered by the markdown, JSON and table heralds.
15. **Registers and windows (D-21, G9, G15).** `ExecuteResponse` (a frozen v0.9 schema) gains `halt_reason` behind a new sanctioned golden exception; WINDOWS.md gains rows for D-08 (agent-kind runs have no checkpoint), D-01 (over-admission race accepted), G2 (streamed call) and G15 (unpriced engine nodes are unmetered).

It proves it can fail by scanning a planted temporary tree first.

Option-b additionally adds an informational `halt_reason` object to that streamed `done` when the terminal chunk's usage crossed the derived figure (no behavioural halt -- the call already finished), so a streaming client learns the allowance is now spent without a follow-up read; non-halt streams stay byte-identical.
