<objective>
Make the halt's typed reason durable and visible: persist it on the run row (migration 013), serve
it on `GET /runs/{id}` and `GET /runs` beside the fork point, and carry it on the caller's `halted`
webhook -- all from one wire builder.

Task 1 lands the storage half (the one-way column, the core field, the port field, three adapters
and the shared contract clauses). Task 2 makes the worker write the reason before the status flips
(G14), carries it on the caller webhook (D-19), and serves it plus `final_waypoint_id` (G7) on the
run DTO, refactoring the 429 builder onto the shared `details_json` so the two objects cannot drift.
Task 3 registers the surface and documents the new fields.

Purpose: after this plan a caller can see WHY a run halted and WHERE to fork from with one read,
and every later leg (SSE degraded path, replay) reads the reason from the row (D-06, D-16).

Output: migration 013 pair, `Run.halt_reason`, `RunOutcomeRecord.halt_reason`, three adapters,
contract clauses, `RunResponse.halt_reason` / `final_waypoint_id`, `WebhookPayload.halt_reason`.
</objective>
