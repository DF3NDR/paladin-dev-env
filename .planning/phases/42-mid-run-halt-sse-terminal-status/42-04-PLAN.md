<objective>
Harden the boundary check against every edge ALLOW-03 names and prove the halt is resumable: a
halted engine run is resumed by forking from its Halted Waypoint once the allowance is replenished
or the window resets, continuing from that checkpoint rather than re-executing.

Task 1 proves the guard's contract in isolation and in a nested child run: the exact-ceiling
boundary, a read at every boundary (D-02), fail-closed `ledger_unavailable` (D-03), inertness
without a ceiling, the memoised first halt shared with child runs (G11), and no guard for an
unattributed run. Task 2 proves resume end to end through the real HTTP routes (D-07): halt ->
`GET /runs/{id}` -> fork refused `429` with `Retry-After` -> store clock past the window -> fork
accepted -> `Completed` without re-running completed supersteps; and the same for a
`ledger_unavailable` halt after the ledger recovers. It documents the resume recipe.

Purpose: ROADMAP success criterion 2 ("a halted run resumes and completes once the allowance is
replenished or the window resets, continuing from its last checkpoint") on the engine path.

Output: guard and engine tests, two end-to-end resume tests, the `platform-api.md` resume recipe,
the 9.6 recipe entry and an updated `settlement.rs` module doc.
</objective>
