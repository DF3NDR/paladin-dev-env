<objective>
Tell the operator about mid-run allowance pressure as it happens: a long run warns at its first
boundary past the threshold (D-17), and a spend halt notifies the operator once per window (D-18) --
both through the Phase 41 notice store and operator webhook, never a second channel.

Split from the original 42-09 at plan-check revision 1 (scope_sanity), as the checker proposed: 42-10
landed the store's halt rung and the `allowance_halted` event; this plan makes the boundary guard use
them. Task 1 gives the Treasurer and the guard their notice legs (shared crossing collection, halt
claim, operator notify, per-run claim memo, an emitter-carrying constructor) with unit tests. Task 2
attaches the guard with the run's own emitter in the worker and proves the whole path end to end.
Task 3 registers and documents the operator-facing behaviour.

Purpose: D-17 ("a long run no longer waits for the next admission to warn") and D-18 ("a spend halt
notifies the operator once per window"), sharing admission's evaluate-and-claim step (one function
per rule).

Output: the guard's notice legs, the worker attachment, an integrated end-to-end proof, registers.
</objective>
