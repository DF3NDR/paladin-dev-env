<objective>
Make Redis unavailability a degradation, never an outage and never a hole in pacing (PACE-05,
D-05): a composite `ResilientCadence` in `paladin-storage` owns the outage latch, falls back to the
in-process gate with a stricter multiplier, warns once per outage, probes the primary on a back-off
and recovers automatically -- all testable with an injected failing port and no Redis.

Purpose: ROADMAP success criterion 5 -- "When Redis is unavailable, pacing degrades to conservative
per-process pacing with a trace warning; a run is never left unpaced -- covered by a test."

**Open Question 5 resolution:** the "trace warning" is a `log::warn!` under the D-07 log/trace
target `paladin::cadence` (the `PRICING_LOG_TARGET` precedent), plus `log::trace!` per gated call
(43-01). No new `TraceEvent` variant is added: `TraceEvent` is a persisted, SSE-published schema
matched in about a dozen files, the decorator has no node id, and D-07 names a log/trace target --
not a run-trace event. Recorded in ADR-0058.

Output: `ResilientCadence`, `InMemoryCadence::with_multiplier`, the unreachable-Redis tests, the
never-unpaced end-to-end test, the registered surface. (The lock half of fail-open, D-13, arrives
with the lock methods in 43-10; wiring `backend: redis` to this composite is 43-09.)
</objective>

**`InMemoryCadence::with_multiplier(self, multiplier: f64) -> Self`**: every delay this instance records (explicit or computed) is multiplied by `multiplier` with `Duration::mul_f64` and clamped at `CADENCE_DELAY_CEILING`; a non-finite multiplier or one below 1.0 is treated as 1.0 and documented (config validation rejects such values before they reach here, 43-01). Module docs: why the latch lives in an adapter and not the decorator (the decorator stays oblivious; the behaviour is testable without Redis); the D-05 rules; the probe back-off (a dead Redis must not add a timeout to every LLM call, Pitfall 10); the max rule on recovery; flagged assumptions A1-A3 of this plan. `pub const DEFAULT_PROBE_INTERVAL: Duration` = 5 s. `ResilientCadence { primary: Arc<dyn CadencePort>, fallback: InMemoryCadence, probe_interval, state: std::sync::Mutex<Latch>, probing: AtomicBool, transitions: AtomicU64 }` with `Latch { degraded: bool, last_probe: Option<tokio::time::Instant> }`; manual `Debug` (degraded flag and transition count only). `new(primary, fallback)`, `with_probe_interval`, `is_degraded()`, `degraded_transitions()`.

For each `CadencePort` method: if healthy, call the primary; `Ok` -> for `gate` return the reading with the larger wait (and larger streak) of the primary's and the fallback's, for `record_success` also clear the fallback's streak for that key, else return it; `Err(e)` -> latch (on the healthy-to-degraded edge only: increment `transitions` and `log::warn!(target: CADENCE_LOG_TARGET, "pacing degraded to per-process: shared pacing backend unavailable ({e}); delays x{multiplier} until it recovers")` -- the error text is already URL-free) and serve the call from the fallback. If degraded: when `probe_interval` has elapsed since `last_probe` and the `probing` flag is claimed with `compare_exchange`, try the primary once (set `last_probe` first); success clears the latch with one `log::info!(target: CADENCE_LOG_TARGET, "pacing recovered: shared pacing backend reachable again")` and returns the max-rule result; failure keeps the latch silently; otherwise serve from the fallback without touching the primary. While degraded, `record_rate_limited` and `record_success` write only the fallback. Poisoned locks are recovered with `PoisonError::into_inner`. The composite never returns `Err` to its caller.
