<objective>
Use the stampede lock where the duplicate spend happens: the `WarEngine`'s cache-miss-to-put
window (D-11). On a miss with a cadence handle attached, one dispatch acquires the lock and
executes; the others wait, re-read, and serve the hit; a crashed or failed holder hands over within
one poll or, at worst, the TTL; cancellation is honoured; the lock never fails a node.

Purpose: ROADMAP success criterion 4 -- "A distributed stampede lock (set-if-absent with expiry,
fencing token, delete-only-if-owner) stops concurrent workers from issuing the same cached request
twice."

Scope note: `WarEngine::with_cadence` is a library builder like `with_node_cache`; the server
attaches no node cache today (43-09), so it attaches no lock either. The dependency direction holds:
`paladin-battalion` depends on the `CadencePort` trait in `paladin-ports` only, never on an adapter
crate (dev-dependencies excepted for tests).

Output: `WarEngine::with_cadence`, the lock loop, the stampede tests, the registered surface.
</objective>
