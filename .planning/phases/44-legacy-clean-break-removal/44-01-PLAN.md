<objective>
Prove the phase's architecture end-to-end on its thinnest real path before anything is removed:
`BattalionConfig.aegis` (core) -> `validate_aegis` -> the Commander -> `CampaignExecutionService` ->
one crate-private per-attempt runner (`aegis_attempt.rs`) -> `PaladinPort::execute` under a
per-attempt `tokio::time::timeout` -> a structured `NodeError` -> `BattalionError::Node` back out of
`Commander::execute`. Campaign is the tracer pattern because it never read the legacy
`retry_policy` / `error_strategy` (research Finding 3), so moving it changes no legacy retry or
continue semantics; Formation (44-04), Phalanx (44-05), the Conclave and the Commander (44-07) reuse
the same runner.

Task 1 is the phase's single tracer. Task 2 expands it: the full `validate_aegis` rule set, the
runner's retry/timeout edge matrix, and the `BattalionConfig.aegis` contract rustdoc that every
later plan implements against (interface-first).

Purpose: LEGACY-02 says "Aegis timeouts are the only timeout path" -- that is only true once one
runner owns the per-attempt bound, the retry predicate, the backoff and the typed failure record.
If a Paladin attempt cannot cross core -> runner -> service -> Commander under an Aegis bound
without an architectural change, every later plan is wasted.

Output: `BattalionConfig.aegis` / `with_aegis` / `validate_aegis`, `aegis_attempt.rs`, Campaign on
the runner with its whole-run wrapper deleted, the end-to-end Commander test.

**Layers joining later (not deferrals):** the herald layer joins in 44-06 behind the one-way D-06
checkpoint (`node_errors` retype); the CLI and examples in 44-08; the register in 44-11. The legacy
fields stay compiled (unread by Campaign) until 44-10 deletes them.
</objective>

**Runner (`crates/paladin-battalion/src/aegis_attempt.rs`, new).** Module rustdoc: this is the one per-attempt runner for the legacy Battalion patterns (Formation, Phalanx, Campaign, the Conclave); it owns the only `tokio::time::timeout` those patterns use; the bound is per attempt (D-02); retry gating goes through `engine::retry::should_retry` and backoff through `backoff_delay` / `wait_backoff` (D-12, one backoff implementation); failures are classified by `PaladinError::transience()` and recorded with `llm_failure::to_node_error_source`, never by reading message text. Declare it in `lib.rs` as a crate-private module (`mod aegis_attempt;` -- no `pub`, so no public surface and no `make api-surface` change), and add one bullet under the lib.rs `## Utilities` doc list describing it in prose (plain text, not an intra-doc link to a private item). On success return `AttemptOutcome { result, attempts: attempt }`. Log retries with `log::warn!` naming the Paladin, the failed attempt number, the transience and the delay -- never the input, the output or the error's message body.
