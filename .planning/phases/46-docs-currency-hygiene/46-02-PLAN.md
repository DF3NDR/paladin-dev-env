<reconcile_procedure>
Reconcile-only procedure (identical in plans 46-02, 46-03, 46-04; D-14, D-16, D-17):

1. Resolve the phase: `node .claude/gsd-core/bin/gsd-tools.cjs query init.phase-op <N>` returns the archived
   `phase_dir` under `.planning/milestones/v0.10.0-phases/` (verified for all eight phases). Do not move or copy
   anything (D-16).
2. Skeleton (workflow Step 2): build the task list mechanically, not by reading whole PLAN files -- for each
   `<N>-NN-PLAN.md` take `wave:` and `requirements:` from the frontmatter and, for each task element, its type,
   name and automated-verify (or verify) text. A throw-away script in the session scratchpad is fine; it is
   never committed. Cross-check the task count against `cat <dir>/<N>-*-PLAN.md | grep -c '<[t]ask '`.
3. Evidence (workflow Steps 2d-3): read `<N>-VERIFICATION.md` (truth table, requirement coverage, human items) and
   each SUMMARY's frontmatter and "Verification" / "Deviations" sections. For each row decide Status:
   `✅ green` when the command was re-run on HEAD in this session and passed, or the VERIFICATION seal records it
   passed and its test target still resolves on HEAD (grep the test fn / file); `⚠ superseded` when a later phase
   renamed or removed the target (name the phase and the current equivalent test if one exists -- translate
   `-p paladin-core` to the package name `-p paladin-ai-core`, and Phase 48's `Node<T>` to `Entity<T>` renames);
   `checkpoint` for a `checkpoint:*` task (a plan-time decision, not a test, cited to its SUMMARY outcome);
   `❌ gap` when no automated command and no sign-off exists. Re-run on HEAD at least one command per requirement
   id whose command runs offline in the sandbox within a few minutes (`cargo test --offline -p <package> --lib
   <filter>`, `cargo test --offline --test <target>`, `make <gate>`, `grep`); commands needing Docker, live API
   keys, `cargo-llvm-cov`, `mdbook` or a network are marked "CI evidence" and cite the CI run or VERIFICATION
   line instead.
4. Decide frontmatter (workflow Step 6, State A): `status: validated`; `nyquist_compliant: true` only when every
   requirement id has at least one green automated row and every row is green, superseded-with-equivalent, or a
   checkpoint, with manual-only rows backed by a cited sign-off artifact (UAT pass) -- otherwise `false`;
   `wave_0_complete: true` only when every Wave 0 file the file lists exists on HEAD (or its named successor);
   add `validated: <execution date>` and `reconciled: "<execution date> by Phase 46 plan 46-0N, reconcile-only
   (D-14/D-16): map rebuilt from the archived PLAN/SUMMARY/VERIFICATION; no test written"`. Keep the two
   existing comment lines in the frontmatter.
5. Body: replace every seeded placeholder row of the Per-Task Verification Map with the real rows (columns
   unchanged: Task ID, Plan, Wave, Requirement, Threat Ref, Secure Behavior, Test Type, Automated Command, File
   Exists, Status); correct the Test Infrastructure table's commands to HEAD package names; update the Wave 0 and
   Manual-Only sections and the Validation Sign-Off checkboxes to what is true; append
   `## Validation Audit <execution date>` with the table `| Metric | Count |` rows "Gaps found", "Resolved"
   (always 0), "Escalated"; append `## Gaps` listing every `❌ gap` / un-equivalent `⚠ superseded` row by task id
   with its reason, or the single line "None."
6. Skip workflow Step 4 (AskUserQuestion) and Step 5 (gsd-nyquist-auditor). Commit only the VALIDATION.md file
   (workflow Step 7's `node .claude/gsd-core/bin/gsd-tools.cjs query commit "docs(phase-<N>): reconcile Nyquist
   validation (Phase 46 plan 46-0N, D-14)" --files <file>`).
7. Record in the plan SUMMARY: the resulting `status:` and `nyquist_compliant:` lines, the gap count, and every
   command re-run with its exit status (D-17).
</reconcile_procedure>
