<objective>
Make a stored v0.10 `BattalionConfig` / `ConclaveConfig` document that still carries a removed key fail loudly at
load, naming the key and its `aegis.*` replacement (D-23, option B), so a run that was bounded in v0.10 can never
load as silently unbounded in v0.11.

Purpose: the folded todo `2026-10-11-reject-removed-v0-10-battalion-config-keys.md`; CURR-23 because the refusal
is part of what the v0.10 -> v0.11 guide must say (its M-B-06 row). Design per RESEARCH F5 / "D-23 design" and the
prototype verified in a scratch crate: `#[serde(try_from = "<private wire struct>")]` with the wire types and the
message text in a new `battalion/legacy_keys.rs`, so the public struct shapes, `Serialize` and the Rust surface do
not change, and the legacy guard's rules 5/6 stay green. This lands before the section 10 freeze (plans 46-10 and
46-11 move these rows verbatim), so the row text is written once against shipped behaviour.

Reversibility: costly (CONTEXT D-23) -- a load-time refusal is operator-visible behaviour on a published type;
relaxing it later is another section 10.1 row. Flagged, not gated (the owner chose option B in CONTEXT).

Output: the refusal, its tests, the CLI regression test, ADR-0059's amendment, the M-B-06 / register / DR-8 text,
CHANGELOG entries, and the todo moved to `completed/`.
</objective>
