<objective>
Pin the one-way door of this phase -- the persisted JSON wire shape -- end to end before anything is
renamed: v0.10 bytes on disk -> `FileCitadel` (the infrastructure adapter) -> `CitadelPort` ->
`PaladinState` -> the `Paladin` entity alias -> the base wrapper, and back out to disk. The same
captured bytes for `Paladin`, `PaladinState`, `ContentItem` and `PromptItem` then become the
regression harness every rename commit (48-04, 48-05) must keep green.

Task 1 is the phase's single tracer: it captures the four Wave 0 fixtures from the unmodified tree
and proves the thinnest real path (the Citadel snapshot through the real adapter). Task 2 expands it
to all four persisted shapes through the public core types.

Purpose: ENTITY-01 promises that every JSON persisted before the rename still deserializes, "proven
by a fixture test against pre-rename JSON" (ROADMAP success criterion 1). That proof is only worth
anything if the fixtures are the real v0.10 bytes -- so they must be captured before the first
rename commit (48-VALIDATION.md Wave 0), and the harness must already pass on the pre-rename tree so
that a later failure can only mean a wire regression.

Output: four fixture files, `crates/paladin-core/tests/entity_serde_compat.rs` (the first
integration test of `paladin-core`; `crates/paladin-core/tests/` is auto-discovered, no `[[test]]`
entry), and one adapter test in `file_citadel.rs`.

**Layers joining later (not deferrals):** the field rename and the alias edge cases join in 48-05,
which updates this harness's round-trip assertion to the renamed keys; the registers in 48-07; the
repository guard in 48-08.
</objective>
