<objective>
Pin the one-way door of this phase -- the persisted JSON wire shape -- end to end before anything is
renamed: v0.10 bytes on disk -> `FileCitadel` (infrastructure adapter, `paladin-memory`) -> `CitadelPort`
-> `PaladinState` -> the `Paladin` entity alias -> the base wrapper, and back out to disk. The same
captured bytes for `Paladin`, `PaladinState`, `ContentItem`, `PromptItem` and the version record then
become the regression harness that every later commit (48-03 version family, 48-04 citadel unification
and type rename, 48-05 field rename) must keep green.

Task 1 is the phase's single tracer: it captures the five Wave 0 fixtures from the unmodified tree and
proves the thinnest real path (a Citadel snapshot through the real adapter). Task 2 expands it to all
five persisted shapes through the public core types.

Purpose: ENTITY-01 promises that every JSON persisted before the rename still deserializes, "proven by a
fixture test against pre-rename JSON" (D-03); D-09 adds the same promise for the version record and
D-10 for a Citadel snapshot after the placeholder `PaladinData` is unified with the real one. Each
promise is only worth anything if the fixtures are the real v0.10 bytes -- so they are captured before
the first rename commit (48-VALIDATION.md Wave 0), and the harness passes on the pre-rename tree so that
a later failure can only mean a wire regression.

Output: five fixture files, `crates/paladin-core/tests/entity_serde_compat.rs` (the first integration
test of `paladin-ai-core`; `crates/paladin-core/tests/` is auto-discovered, no `[[test]]` entry), and one
adapter test in `file_citadel.rs`.

**Layers joining later (not deferrals):** 48-03 renames the version keys and updates the version case;
48-04 unifies the citadel placeholder and adds the v0.10-status case; 48-05 renames the payload and
wrapper fields and adds the alias edge cases; 48-07 registers; 48-08 guards.
</objective>

<decisions>
Decisions this plan implements or evidences (full record: 48-CONTEXT.md, ADR-0060 from 48-02):

- **D-03:** serde compatibility by read-alias, not by version bump; pre-rename JSON keeps loading. This
  plan captures the evidence D-03 is judged against (the four shapes D-03 names).
- **D-09:** the version record gains `node_id` / `node_data` read-aliases in 48-03; the fifth fixture,

  v0.10 bytes that alias is proven against.
- **D-10:** the Citadel snapshot fixture is captured over the citadel module's placeholder `PaladinData`,
  exactly as v0.10 writes it, so 48-04 can prove the unified type reads it.
- **D-00d:** `paladin-core` takes no new dependency; the harness uses only `serde_json` and std.
- **Tracer choice (TRACER_MODE):** a rename cannot be sliced thinner than one atomic commit, so the tracer
  is the riskiest promise instead -- persisted state crossing disk -> adapter -> port -> domain.
  Rehearsed in 48-RESEARCH.md (fixtures captured on the unmodified tree, compat test green on the
  renamed tree).
</decisions>
