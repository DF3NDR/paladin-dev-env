<decisions>
The full Phase 48 decision set. D-01..D-07 are 48-CONTEXT.md's recommendations, accepted as-is by
`/gsd-plan-phase 48` on 2026-10-13 under 48-CONTEXT.md's own rule ("`/gsd-plan-phase 48` to accept
them as-is"); they are locked. D-08..D-14 are planner resolutions of 48-RESEARCH.md's open questions,
following the research recommendation each time. Note on numbering: 48-RESEARCH.md labels the serde
alias lifetime "D-12" and the module names "D-11/D-13"; this plan set uses the numbering below, which
is what ADR-0060 and 48-CONTEXT.md record.

- **D-01 (locked) -- `Entity<T>`, payload field `data`, public path `paladin_core::base::entity::Entity`.**
  Generic on purpose: the base layer predates the Medieval Military theme. Reversibility: costly.
- **D-02 (locked) -- clean break, no deprecated alias.** The old wrapper and its module are removed
  outright; ADR-0060 records a Phase-48-only X-03 supersession in the ADR-0059 shape; MIGRATION.md 9.7
  stays empty. Why not the alias (48-RESEARCH.md Pitfall 9, verified): a `#[deprecated]` type alias
  keeps only the type name and module path resolvable; the payload field rename cannot be aliased in
  Rust, so every payload access, every struct literal naming the old field and the `ContentItem` /
  `PromptItem` field still fail to compile downstream, and each surviving use raises a deprecation
  warning that fails the downstream's own `-D warnings` build -- the alternative does not deliver its
  stated benefit, while making 9.7 non-empty for the first time. Reversibility: one-way once v0.11.0
  is published (Phase 47) -- `paladin-ai-core` 0.10.1 on crates.io exports the old name.
- **D-03 (locked) -- serde compatibility by alias, no `schema_version` on the wrapper.** Reads accept
  the old or new key, a document with both keys is rejected (`duplicate field`), one with neither is
  rejected (`missing field`), new writes emit only the new key. Reversibility: one-way for downgrade
  -- a v0.10 binary cannot read JSON written by v0.11.
- **D-04 (locked) -- the `version: bool` flag keeps its name and gains a rustdoc contract, not a
  feature.** Honoured only by a caller routing writes through `EntityVersionService` (today
  `ContentItem` via the root crate's `ContentItemService`); platform-wide revisioning stays deferred.
- **D-05 (locked) -- remove all five dormant base items, none retained.** Real symbols: the `field`
  module's `Field`; the `collection` module's `CollectionType` and `Item`; the comment-only `element`
  module; `FieldVersionService` and its family; `CollectionVersionService` and its family (the type
  ENTITY-04 calls `CollectionVersioningService` is named `CollectionVersionService`; only its module is
  `collection_versioning_service`).
- **D-06 (locked) -- sequencing:** after Phase 44, before Phases 46 and 47, in its own PR; the duplicate
  `Paladin` alias in the citadel module is removed here.
- **D-07 (locked) -- the graph side is frozen and the old names stay gone,** pinned by a repository-scan
  guard in the `tests/legacy_removal_guard.rs` shape; the vocabulary rule is named in the ADR and in the
  `CLAUDE.md` / `.github/copilot-instructions.md` naming tables.
- **D-08 (planner) -- `ContentItem.node` and `PromptItem.node` become `entity`, with
  `#[serde(alias = "node")]`.** They are entity-sense fields; leaving them keeps "node" on two public
  fields and 82 `item.node.node` chains, contradicting the phase goal. No new forward-compatibility
  door beyond D-03: the inner payload key already changes. Reversibility: costly.
- **D-09 (planner) -- the version family follows the rename.** Module `entity_version_service`;
  `EntityVersion`, `EntityVersionMetadata`, `EntityVersionRepository`, `EntityVersionService`,
  `InMemoryEntityVersionRepository`; variant `VersioningError::EntityNotFound`; fields `entity_id` /
  `entity_data` on `EntityVersion`, `entity_id` on `VersionHistory` and `VersionComparison`,
  `VersioningConfig.max_versions_per_entity`; `#[serde(alias = "node_id")]` and
  `#[serde(alias = "node_data")]` on `EntityVersion` (the module's only serializable type -- the same
  data-compatibility principle as D-03 for any downstream repository that persisted v0.10 versions).
  `VersionHistory`, `VersionComparison`, `VersioningConfig`, `ChangeType`, `HashAlgorithm` and
  `VersioningError` keep their names. The `node_id` rename is confined to the four files that carry the
  entity sense (graph-sense `node_id` has 1,151 occurrences). Reversibility: costly.
- **D-10 (planner) -- the citadel module loses only its alias.** Delete its `Paladin` alias and write
  `Entity<PaladinData>` at its use sites; do not unify its placeholder `PaladinData` / `PaladinStatus`
  with the real ones (a second public break on `PaladinState.paladin`'s type, recorded as a Considered
  Option). No wire change. Reversibility: reversible.
- **D-11 (planner) -- alias lifetimes.** Under the clean break no deprecated Rust alias exists, so its
  lifetime is moot. The serde data-compatibility aliases are kept for the whole 0.x line; removing them
  needs its own ADR. Reversibility: reversible.
- **D-12 (planner) -- one ADR.** ADR-0060 covers both the X-03 supersession and the vocabulary rule
  (ADR-0059 rejected splitting a supersession from its design). Reversibility: reversible.
- **D-13 (planner) -- layout.** `Entity<T>` lives in a private module `base/entity/wrapper.rs` (a git
  move of the old wrapper file) re-exported as `pub use wrapper::Entity;` -- a `base/entity/entity.rs`
  declared `mod entity;` inside `entity/mod.rs` fails `clippy::module_inception` (verified in
  research). Reversibility: reversible (private module).
- **D-14 (planner) -- the register lands once, measured.** The 9.2 rows, the allowlist entries and the
  two new crate-wide allow lines (`trait_missing`, `module_missing` in `crates/paladin-core/Cargo.toml`)
  land in one commit in plan 48-07, from one D-27 diagnostic on the final tree (the Phase 44 shape:
  removals 44-03..44-10, register 44-11). CI's `semver` job is expected red on the intermediate commits
  48-03..48-06 and green from 48-07; the PR merges as a whole. Reversibility: reversible.
</decisions>
