<objective>
Clear the base service layer before the wide rename: remove the five dormant base items (D-05,
ENTITY-04) and rename the version family to `EntityVersion*` (D-09, ENTITY-03), carrying the root
crate's `ContentItemService` -- the only consumer -- and the public-API baseline with it.

Purpose: the two removed version services import `ChangeType`, `HashAlgorithm` and `VersioningError`
from the old version module, so they must go before that module is renamed; and the version family is
the only place this phase moves facade-surface lines, so the baseline is refreshed here, once
(48-RESEARCH.md Pitfall 1: the `Entity` rename itself changes zero facade lines). Both tasks shrink
what the Stage A and Stage B scripts (48-04, 48-05) have to touch.

Output: five files deleted, `entity_version_service.rs` (git move), `content_service.rs` and two
functional tests updated, `.project/current-exports.txt` regenerated, CHANGELOG `### Changed` bullets.

The wrapper type is still the old one in this plan (Stage A, 48-04, renames it); the register rows,
allowlist entries and the two new allow lines land in 48-07 (D-14), so CI's `semver` job is expected
red on this plan's commits.
</objective>
