<objective>
Stage A of the two-stage rename (48-RESEARCH.md Pattern 1): rename the base wrapper type and module
to `Entity<T>` at `paladin_core::base::entity::Entity` across the whole workspace in one green commit,
delete the citadel module's duplicate `Paladin` alias, then give `Entity<T>` its revisioning-contract
rustdoc and finish the entity-sense prose the script cannot reach.

Purpose: ENTITY-01's first clause (the type and its path), D-02 (clean break -- nothing keeps the old
name resolvable), ENTITY-03's one-`Paladin`-alias clause (D-10) and ENTITY-04's rustdoc contract
(D-04). Stage A is hazard-free by design: it renames a type and a module path only, so the wire is
untouched and the 48-01 harness must pass unchanged -- which is how this plan proves it. The payload
field keeps its old name until Stage B (48-05), the plan with all the field-rename hazards.

Output: `wrapper.rs` (git move), the rewired `base/entity/mod.rs`, ~119 rewritten files, the citadel
alias gone, the `Entity` rustdoc, the `base` module doc and the prose sweep.
</objective>

<decisions>
- **D-01 (locked):** `Entity<T>` at `paladin_core::base::entity::Entity`, generic name on purpose.
- **D-02 (locked):** clean break -- no alias, no re-export of the old module, no `#[deprecated]` item.
- **D-13 (planner):** the type lives in a private `wrapper` module re-exported from `base::entity`
  (`base/entity/entity.rs` under `mod entity;` fails `clippy::module_inception`, verified in research).
- **D-10 (planner):** the citadel module loses only its alias; its placeholder `PaladinData` /
  `PaladinStatus` stay as they are and its three use sites write `Entity<PaladinData>`.
- **D-04 (locked):** the `version` flag gets a rustdoc contract, not a feature.
- Reversibility (D-01/D-02): costly within this phase -- a reverse script undoes it before the v0.11.0
  tag; the published contract changes only at Phase 47. Recorded on Task 1; no checkpoint, the
  decision is locked (planner-reversibility "Gating a decision already made").
</decisions>
