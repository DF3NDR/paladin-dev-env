<objective>
Stage B of the two-stage rename (48-RESEARCH.md Pattern 1): rename the entity payload field `node` to
`data` (D-03) and the `ContentItem` / `PromptItem` wrapper field `node` to `entity` (D-08), each with
`#[serde(alias = "node")]`, across the whole workspace in one green commit -- then pin every alias
edge case and the `# Serialization` contract.

Purpose: ENTITY-01's field clause and its fixture proof in final form, and ENTITY-05's guarantee that
the graph sense is untouched where the two senses sit side by side. This is the plan with all the
hazards research found (struct-update `..` bases, `ContentItem` double hops, graph-sense `.node` in the
engine and eval crates, feature-gated test code), so it opens with a byte snapshot of every graph-sense
line and closes by diffing it.

Output: the renamed field and wrapper fields with aliases, ~107 rewritten files, the compat harness in
its final shape, six new tests, the `# Serialization` rustdoc.
</objective>

<decisions>
- **D-03 (locked):** serde compatibility by alias; old key or new key loads, both is rejected,
  neither is rejected, writes emit only the new key; no `schema_version` on the wrapper.
- **D-08 (planner):** `ContentItem.node` / `PromptItem.node` become `entity` with the same alias -- no
  new forward-compatibility door beyond D-03 (the inner payload key already changes).
- **D-11 (planner):** the aliases are kept for the whole 0.x line; removal needs its own ADR.
- **Reversibility (D-03): one-way** once any deployment runs v0.11 -- snapshots and `ContentItem` JSON
  it writes carry `data` / `entity`, which a v0.10 binary or any reader keyed on the old name cannot
  read; returning to the old key would need a reverse alias or a rewrite of stored state. The decision
  is locked (accepted at `/gsd-plan-phase 48` under 48-CONTEXT.md's own rule, recorded in ADR-0060), so
  per planner-reversibility "Gating a decision already made" no checkpoint re-asks it; the rating is
  recorded on Task 1 and the operator-facing consequence is written into MIGRATION.md 9.1 / 9.4 by
  48-07.
</decisions>
