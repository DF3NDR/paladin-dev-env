<objective>
Start closing G-50-5a (WINDOWS row 74) where the money is lost today: Grok reports reasoning tokens beside
`completion_tokens`, and the compat engine applies OpenAI's inclusive reading to every preset. Every Grok reasoning
call therefore drops its reasoning tokens from `total_tokens`, breaks `reasoning <= completion`, and is priced by
`cost_of_call` at about half what xAI bills. This plan folds them in and makes the vendor's own total the check on
the mapping: parsed, compared, and any disagreement surfaced, never discarded. D-02 stays kept, per the owner.

instruction for row 74: Treasurer pricing, the ledger and the allowance checks must reflect what the vendor charges.

`ReasoningBesideCompletion`; the compat engine reconciling on both paths; a tracer test through `PricingLlmAdapter`;
the flipped compat test and a Grok conformance usage fixture; docs, changelogs and a MIGRATION 9.1 row. The four
bespoke adapters follow in plan 50-23, the live measurement of the Grok semantics in plan 50-22 (applied in plan 50-24), and billed-but-failed
calls in plans 50-25 to 50-31.

<flagged_assumptions>
- A1-50-21 (owner: "keep D-02; a vendor-total field is a public-surface change"): no `vendor_total_tokens`
  field is added to `paladin-core`'s `TokenUsage`. That type is a constructible, non-`#[non_exhaustive]` struct
  shipped in v0.10.1, so a field would break every struct literal. Its `Add`/`Sum` would also have no meaningful
  merge for a total that some calls report and others do not. And once every billed category is folded, the field
  would equal `total_tokens` on every agreeing call. The disagreement is surfaced through the established
  ADR-0061 visibility channel (warn once plus a `paladin.*` metadata key that 50-18 already carries to
  `PaladinResult.run_metadata` and the streamed terminal chunk). The only new public item is the key constant
  (additive, `paladin-llm`).
- A2-50-21 (debug blind spot): xAI's reasoning-exclusive `completion_tokens` is secondary-sourced. The sources are
  the Google Vertex AI "Reasoning for Grok models" partner page (663 + 50 + 124 = 837) and the Glama grok-api doc
  (50 + 200 + 150 = 400). docs.x.ai answered 403 through the proxy on 2026-10-17, and the 2026-10-15 probe captured
  field names only. This plan ships fixture-based tests, not a claim of verification. Plan 50-22 measures it live and
  plan 50-24 applies the verdict. If Grok were in fact inclusive, the reconciliation itself would flag every Grok
  reasoning call (`total:vendor=<p+c>,mapped=<p+c+r>`), so a wrong declaration cannot stay silent.
- A3-50-21: no metrics dependency exists in `paladin-llm`; "warn/metric" (UAT missing item 2) is met by the warn
  plus the metadata key, which OTel and run consumers already read.
- A4-50-21: the merge rule 50-18 established holds the last value for every `paladin.*` key other than the two
  union keys, so a run's `run_metadata` keeps the last call that recorded a disagreement.
- A5-50-21: the T-38-05 clamp in `cost_of_call` stays as the last line of defence against a malformed response.
  After this plan a mapped Grok usage never reaches it with `reasoning > completion`, and any mapper that does is
  now flagged at the adapter boundary, so the clamp is no longer silent. Only its rustdoc changes.
</flagged_assumptions>
