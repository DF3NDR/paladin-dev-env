<objective>
Make a billed-but-failed call carry its bill. Every adapter runs the shared guard before mapping usage, so a call the
vendor charged for and the guard classifies as empty or refused returns no `TokenUsage` and no cost. The classic case
is a reasoning model spending its whole `max_tokens` budget on hidden reasoning (DeepSeek's fixture shows 63,000
tokens). This plan carries that usage, typed, on the error, and has `PricingLlmAdapter` price it. Plan 50-25 then
settles it in the agent loop and the Battalion engine.

Purpose: G-50-5a UAT missing item 3 and the owner's binding instruction that the Treasurer can settle billed-but-failed
calls. The error type change is the only way to carry the figures out of `LlmPort::generate`, so the break is
registered in the same commit as the code (D-00b).
Reversibility (costly): `LlmError` is a published error type consumers match on. The change lands before the v0.11.0
tag with full registration, as D-09 and D-11 did for this phase's other error and response changes.

Output: `BilledUsage` and the two struct variants with constructors and accessors, an atomic migration of every
construction and match site, `response_guards::bill`, billing on both paths of every adapter, pricing of billed errors,
one conformance case, and the registration.
</objective>

<flagged_assumptions>
- A1-50-24: struct variants with `#[non_exhaustive]` plus constructors follow the in-tree `RateLimitExceeded`
  precedent, so a later field on either variant is free. `Refusal` is new in this unreleased cycle, so only
  `EmptyCompletion`'s tuple-to-struct change breaks v0.10.1 code. `billed` is boxed to keep `LlmError` small (clippy
  `large_enum_variant`).
- A2-50-24: only `EmptyCompletion` and `Refusal` carry usage. They are the guard's outcomes for a response the vendor
  returned (HTTP 200) and billed. Transport and status errors never carry a billed body. `with_billed_usage` on any
  other variant returns it unchanged, documented as such.
- A3-50-24: the billed model is the vendor-reported served model when the body names one (the same model
  `PricingLlmAdapter` prices a success against), else the request model. On the stream it is the request model, as
  the Phase 31 stream pricing contract already does.
- A4-50-24: a `hop_on_refusal` fallback chain that hops past a billed refusal does not carry that hop's usage onto
  the next hop's success. `AllProvidersFailed.attempts` holds strings, and `LlmResponse` has no slot for a second
  model's spend. Plan 50-25 records this as an open WINDOWS row with its closing condition; the opt-in is off by
  default (D-10).
