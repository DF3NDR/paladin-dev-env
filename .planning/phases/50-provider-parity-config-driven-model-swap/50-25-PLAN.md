<objective>
Finish G-50-5a: settle what plan 50-24 carried. A billed-but-failed call's priced usage now rides on `LlmError`, but
the agent loop converts the error to `PaladinError` and returns, and the Battalion engine records a failed attempt as
spending nothing. So neither the platform-run ledger nor the engine's superstep settle sees the bill. This plan
carries the spend across the `paladin-core` boundary, settles it in the agent loop (buffered and streamed), counts it
as the engine attempt's spend, and then closes WINDOWS row 74 with every uncovered remainder ledgered.

Purpose: the owner's binding UAT-5 instruction for row 74: Treasurer pricing, the ledger and the allowance checks
reflect what the vendor charges, failed but billed calls included. The Treasurer reads only ledger balances (debug
Evidence 00:50), so a charge that never settles never counts.
Reversibility (costly): `PaladinError::LlmFailure` is a published variant; the new field lands before the v0.11.0
tag with full registration, as 50-18 did for `PaladinResult.run_metadata`.

Output: `IncurredSpend`, the `spend` field with accessors, `to_paladin_error` carrying billed spend, the agent-loop
and stream settle, the engine attempt accounting, the atomic literal migration, the registration, docs, changelogs,
ADR-0061, row 74 fixed and the remainder rows appended.
