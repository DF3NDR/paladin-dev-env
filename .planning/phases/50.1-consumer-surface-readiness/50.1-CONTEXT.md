# Phase 50.1: Consumer-Surface Readiness for v0.11.0 - Context

**Gathered:** 2026-10-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Close the six consumer-surface gaps web3sec's pre-measured bump found before the `v0.11.0` tag,
each as one additive export, one registered break, a test, a docs row or a seed: the Aegis family
nameable through the `paladin` facade (SURFACE-01); one `new(api_key, model)` shape across the nine
`*Config` types with `with_timeout_seconds` and `with_base_url` on the shared knob builders
(SURFACE-02); the consumer-surface muster extended to everything in handoff Appendix B with a red
proof (SURFACE-03); four §9.8 "Library consumers" gaps closed (SURFACE-04); a facade-reachable
pacing-only composition path (SURFACE-05); and seeded profiles for the consumer's models, widened by
owner decision to the current general-purpose range of all seven probed vendors (SURFACE-06).
Executes after Phase 50 (sealed `a1128fc1`) and before Phase 51. No new capabilities: nothing here
touches `LlmRequest`, `ReasoningEffort`, Phase 50's billing work, live `/models` discovery or
web3sec's own code.

</domain>

### Facade Aegis exports (SURFACE-01, handoff D-A)

- **D-01:** **Whole modules.** `aegis`, `node_error`, `transience`, `battlefield` and `waypoint` are
  added as `pub use paladin_core::platform::container::<module>;` lines in the hand-picked list in
  `src/core/platform/mod.rs`, so every item the §9.8 recipes need resolves at
  `paladin::core::platform::container::{aegis, node_error, …}` with paths that mirror `paladin_core`
  one-to-one. Rejected: selected items only (every later consumer need is another export and
  CHANGELOG line); hybrid (a mixed pattern the next consumer has to learn). `battlefield` (13 pub
  items) and `waypoint` (15) come along whole; that is accepted.
  — **Reversibility:** costly — a public module path on the facade; removing it later is a
  registered break with §9.2 rows.
- **D-02:** **Prelude too.** `Aegis`, `ErrorHandlerSpec`, `TimeoutPolicy`, `StateDelta`, `NodeError`,
  `NodeErrorSource`, `TimeoutKind`, `NodeId` and `Transience` join `paladin::prelude`
  (`src/prelude.rs`), beside `BattalionResult` and `Armament` which are already there, so a consumer
  reading `BattalionResult.node_errors` from the prelude gets the element types from the same
  import. Additive; one `make api-surface-update` and CHANGELOG entry covers D-01 and D-02.
- **D-03:** **Migrate all 17 in-tree examples** that import these types from `paladin_core` directly
  (`grep -rl "paladin_core::platform::container::\(aegis\|node_error\|battlefield\|waypoint\|transience\)" examples/`)
  to `paladin::` paths in this phase, in one mechanical commit. They then double as compile proof
  that the facade path is complete and stop teaching consumers the dependency this phase removes.
  Rejected: only the two the handoff names; leaving examples to Phase 46.
- **D-04:** The muster pins both the `with_aegis(Aegis { on_error: Some(ErrorHandlerSpec::Absorb {
  fallback_delta: StateDelta::new() }), timeout: Some(TimeoutPolicy { run_timeout: Some(d),
  idle_timeout: None }), ..Aegis::default() })` construction and a `node_errors[i].{node_id, attempt,
  transience, source}` read with a `match` on `NodeErrorSource::Timeout(..)` and the message-bearing
  variants, through `paladin::` paths only (the muster already imports from `paladin`,
  `paladin_ports` and `paladin_memory` and never from `paladin_core`; keep it so). §9.8 DR-1, DR-2,
  DR-8 and DR-9 name the import path.

### Constructor shape (SURFACE-02, handoff D-B) — the registered break

- **D-05:** **Target shape: `new(api_key, model)` plus builders** on every type that takes a key and
  has a default model. `base_url` leaves `new` and defaults to the vendor's endpoint constant (as
  `OpenAIConfig::new` already does), reachable through a new `with_base_url` builder;
  `timeout_seconds` is reachable through a new `with_timeout_seconds` builder. Both builders are
  generated by `config_knob_builders!` for all nine types (D-00d), matching `LlmProviderConfig`'s
  builder set in `crates/paladin-llm/src/config/llm.rs`. `from_env()` is unchanged. Rejected: a shared
  `ProviderConfig` builder type (a second concept to document, and Phase 51 would extend both).
  — **Reversibility:** one-way — a published constructor signature on nine `paladin-ai-llm` types,
  registered as a clean break (no alias) in §9.2, the allowlist and a §9.8 DR row; undoing it is a
  second consumer break on the same nine types.
- **D-06:** **`OpenAIConfig` gains a `model: String` field** so it fits `new(api_key, model)` like the
  other key-bearing types. The field is the adapter's **default model**: it feeds the declared
  capabilities / context-window seed chain and the `model_registry` the way `AnthropicConfig.model`
  and `DeepSeekConfig.model` already do. The per-request `LlmRequest.model` still decides what goes on
  the wire. The field is additive on a `#[non_exhaustive]` struct and rides the same §9.2 row as the
  `new` change. Research verifies how the OpenAI adapter resolves its adapter-wide window today and
  what `from_env()` seeds the field from (the seeded OpenAI default model, per Phase 50 D-08).
  Rejected: OpenAI stays `new(api_key)` as a documented exception.
- **D-07:** **`AnthropicConfig::new` drops the required `max_tokens` argument.** `new(api_key, model)`
  sets `max_tokens` from the model's seeded maximum output (the compiled default when the model is
  unseeded), and `with_max_tokens` (already generated in the `plain_max_tokens` macro form) overrides
  it. The wire field stays mandatory; only its source changes. Rejected: keeping a three-argument
  Anthropic exception.
- **D-08:** **Endpoint-only exceptions, unchanged `new`:** `OllamaConfig::new(base_url, model)` (no
  key is meaningful) and `OpenAiCompatibleConfig::new(api_key, base_url, model, capabilities)` (no
  vendor default endpoint exists and the capabilities preset is required). Both still gain
  `with_timeout_seconds` (and `with_base_url`, which for them is a plain setter over the argument
  they already took). Rejected: making compat `new(api_key, model, capabilities)` with a build-time
  failure when `base_url` is unset.
- **D-09:** **Registration and migration, all in the same commits as the code:** `.cargo/semver-checks-allowlist.toml`
  entries with measured lints for `paladin-ai-llm`; MIGRATION §9.2 rows per type; a new §9.8 DR row;
  DR-12's sentence "harmonising them is a separate, deferred owner todo … not part of v0.11.0"
  amended to point at this phase; `make api-surface-update`; CHANGELOG; the muster's
  `DeepSeekConfig::new` / `AnthropicConfig::new` pins in the new shape with `with_timeout_seconds`
  (Appendix B item 5); every in-tree call site migrated (the in-crate adapter tests and
  `lib.rs` doctests, `config/bridge.rs` and its `From<&LlmProviderConfig>` impls, the provider
  factory, `tests/integration/*`, `tests/unit/llm/*`, `examples/llm_provider_selection.rs`,
  `crates/paladin-llm/examples/live_vendor_smoke.rs`, `src/infrastructure/cadence.rs`); the
  `paladin-llm` doctests show the new shape. The harmonise todo moves to `completed/` with
  `resolves_phase: 50.1` when SURFACE-02 seals.

### Muster gate and exhaustiveness (SURFACE-03, handoff D-C)

## Existing Code Insights

### Reusable Assets
- `config_knob_builders!` already generates four builders for all nine types from one place, with the
  `plain_max_tokens` form for Anthropic's required `u32`; `with_base_url` and `with_timeout_seconds`
  are two more arms of the same macro.
- `OpenAIConfig::new(api_key)` already defaults `base_url` to the vendor constant — the pattern every
  other key-bearing type adopts under D-05.
- `LlmProviderConfig::with_timeout_seconds` (`config/llm.rs`) is the rustdoc and shape to mirror.
- `paladin_llm::cadence::with_cadence` exists with exactly the signature SURFACE-05 wants; D-13 is a
  `pub use`.
- The 50-04 probe binary with `--probe` / `--dry-run` and the 50-17 checkpoint/scrub procedure are
  reused unchanged for D-14.
- `49-MUSTER-RED-EVIDENCE.md` is the red-proof template.

### Established Patterns
- The facade's `src/core/platform/mod.rs` is a hand-picked `pub use` list (so `battalion` can be
  extended with `maneuver`/`parser` shims); adding five module lines follows the file's own pattern.
- The muster imports from `paladin`, `paladin_ports` and `paladin_memory` only, pins full literals
  without `..`, and is compile-time only; D-04's pins follow that.
- CI already compiles the muster via `cargo clippy --workspace --all-targets --all-features` and runs
  it via `cargo test -p paladin-ai` in the crate matrix (`llm-anthropic`/`llm-deepseek` are default
  features); D-10 adds a named step, not new coverage.
