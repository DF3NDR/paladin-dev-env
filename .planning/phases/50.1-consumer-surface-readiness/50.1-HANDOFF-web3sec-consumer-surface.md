## 2. Background

**How web3sec consumes Paladin.**

- Path dependencies on the submodule: `paladin-ai` (lib `paladin`, features `llm-anthropic`, `llm-deepseek`),
  `paladin-ports` and `paladin-memory`.
- It builds `AnthropicAdapter` / `DeepSeekAdapter` directly from `*Config` values and calls `LlmPort::generate`.
- It wraps adapters in three of its own `LlmPort` decorators: a usage tally, a usage recorder and a
  per-provider usage-cap breaker.
- It rations prompts with `Commissary::from_port` / `Commissary::new`.
- It runs a three-specialist Phalanx through `PhalanxExecutionService` with continue-on-error semantics and a
  2,000 s bound.
- It uses `MCPClient` over stdio and streamable HTTP.
- Its committed pin is `35fd839`, older than v0.10.0. It moves **once**, directly to the `v0.11.0` tag.

**What the pre-measurement showed (Appendix A).**

- Every error mapped to a registered row. That was the good news.
- But three recipes could not be followed through the facade (SURFACE-01).
- One recipe forces a "construct then assign a public field" pattern (SURFACE-02).
- The guard test missed most of what broke (SURFACE-03).
- The consumer guide omits the most consequential silent change for a direct-adapter consumer: adapters no
  longer retry 429 (SURFACE-04).

**Why now, as 50.1.**

- These are cheapest before the tag. After it, every item becomes a v0.11.1 or a second consumer break.
- SURFACE-02 touches the same nine `*Config` types Phase 51 will extend with a `reasoning_effort` field.
  Doing it first gives Phase 51 a settled constructor shape.
- web3sec starts its own adaptation once 50.1 seals, and reports back before Phase 46 finalises the guide (§7).

## 3. Requirements

### 3.1 SURFACE-01 — Aegis family reachable from the facade (additive)

**Problem (verified at `8488f11e`).**

- The facade's `src/core/platform/mod.rs` declares a local `pub mod container` that re-exports a hand-picked
  list of `paladin_core::platform::container` modules (`allowance`, `arsenal`, `cost`, `paladin`, `prompt`,
  `token_usage`, …).
- That list **omits** `aegis`, `node_error`, `battlefield`, `waypoint` and `transience`.
- No other `pub use` in `src/` re-exports any of their items.
- The §9.8 recipes need them all:

  | Row | Needs | Defined at |
  |---|---|---|
  | DR-1 | `aegis.on_error = Some(ErrorHandlerSpec::Absorb { fallback_delta: StateDelta::new() })` | `aegis.rs:262`; `StateDelta` at `battlefield.rs:222` |
  | DR-8 | `with_aegis(Aegis { timeout: Some(TimeoutPolicy { run_timeout, idle_timeout }), on_error, .. })` | `aegis.rs:43`, `:243` |
  | DR-2 | read `BattalionResult.node_errors: Vec<node_error::NodeError { node_id, attempt, transience, source }>` | `node_error.rs:152`, `NodeErrorSource` `:72`, `TimeoutKind` `:40`; `NodeId` at `waypoint.rs:295`; `Transience` at `transience.rs:32` |
  | DR-9 | match the timeout that surfaces as `NodeErrorSource::Timeout(..)` | — |

- Paladin's own examples import these from `paladin_core` directly, e.g. `examples/commander_auto.rs:17`,
  `examples/campaign_workflow.rs:34`.
- web3sec's measured adaptation had to add `paladin-ai-core = { path = "paladin/crates/paladin-core" }`. That was
  28 of its 112 errors (the `NodeError` reshaping in one file) plus the Aegis construction sites.

**Ask.** Make every item above nameable through `paladin::` (for example
`paladin::core::platform::container::{aegis, node_error, …}`). Whether to re-export whole modules or selected
items is your call (§4 D-A).

**Acceptance.**

- DR-1, DR-2, DR-8 and DR-9's recipes compile using only `paladin::` paths (no `paladin_core::`).
- The muster pins both a `with_aegis(Aegis { on_error: Some(ErrorHandlerSpec::Absorb { .. }), timeout: Some(TimeoutPolicy { .. }), .. })`
  construction and a read of `node_errors[i].{node_id, attempt, transience, source}`, through the facade.
- §9.8 DR-1 / DR-2 / DR-8 / DR-9 name the import path.
- Additive; `make api-surface-update` + CHANGELOG.

### 3.2 SURFACE-02 — One `*Config::new` shape and `with_timeout_seconds` (registered break + additive)

**Problem (verified).**

- Todo `.planning/todos/pending/2026-10-16-harmonise-llm-config-new-signatures.md` records that the nine `new(..)`
  signatures drifted:
  - `OpenAIConfig::new(api_key)`
  - `AnthropicConfig::new(api_key, base_url, model, max_tokens)`
  - `DeepSeek` / `Gemini` / `Kimi` / `Qwen` / `Grok`: `new(api_key, base_url, model)`
  - `OllamaConfig::new(base_url, model)`
  - `OpenAiCompatibleConfig`: a longer list
- Separately, `config_knob_builders!` (`crates/paladin-llm/src/registry/mod.rs:158`) generates `with_max_tokens`,
  `with_max_retries`, `with_context_window` and `with_model_overrides` for all nine, but **not**
  `with_timeout_seconds`.
- That builder exists only on `LlmProviderConfig` (`crates/paladin-llm/src/config/llm.rs:125`).
- Since the types became `#[non_exhaustive]` (DR-12), a consumer that sets a timeout must write
  `let mut c = DeepSeekConfig::new(..); c.timeout_seconds = 600;`. web3sec has 9 such sites.

**Ask.**

- **Owner decision (2026-10-18): this rides v0.11.0, as Phase 50.1, not a later API-hygiene phase.**
- (a) Settle one constructor shape across the nine types and register the break, following the todo's own
  resolution list:
  - `.cargo/semver-checks-allowlist.toml`
  - MIGRATION §9.2 rows
  - a §9.8 DR row
  - `make api-surface-update`
  - muster pins
- (b) Add `with_timeout_seconds` (and `with_base_url` if the chosen shape drops `base_url` from `new`) to the
  shared knob builders.
- Follow your clean-break policy: no deprecated aliases (ADR-0060).

**Acceptance.**

- All nine types construct with the same `new(..)` shape (endpoint-only providers excepted per the todo).
- Every knob, including the timeout, is settable through a `with_*` builder.
- `from_env()` is unchanged.
- The break is registered in all the places the todo lists.
- `crates/paladin-llm` doctests show the new shape.

web3sec's preference is `new(api_key, model)` plus builders, matching `LlmProviderConfig`'s builder set. Its cost
is identical either way: 9 call sites.

### 3.4 SURFACE-04 — Close four gaps in MIGRATION §9.8 "Library consumers" (docs)

Verified in `MIGRATION.md` §9.8 (from line 974) at `8488f11e`:

1. **Pre-v0.10.0 starting points.**
   - The section assumes a `v0.10.1` start. A consumer starting earlier (web3sec at `35fd839`) must also apply
     these §9.2 rows:
     - P31: `TokenUsage` fields and the `from_total` removal; `PaladinResult.token_count` → `usage`;
       `StreamingResponse` `#[non_exhaustive]`
     - P32: `Commissary::new` / `from_port` dropping `is_exact_counter`; `TokenCounter` / `TokenCounterFactory`
       removal
     - P33: `RagRetrievalService` return type
   - 31 of web3sec's 112 errors came from these rows. Add a pointer list.
2. **429 behaviour (M-B-05) is missing from the consumer behaviour list.**
   - The consumer section has zero mentions of 429 or Cadence.
   - Since Paladin P43, the Anthropic, DeepSeek, OpenAI, Gemini and compat adapters no longer retry a 429
     internally. A consumer that builds adapters directly gets **no pacing** unless it composes Cadence. It has
     silently lost 429 resilience.
   - Add the row and the recipe:

     ```rust
     paladin::infrastructure::cadence::build_cadence(&CadenceConfig::default())
     paladin::infrastructure::cadence::compose_llm(..)
     ```
   - Also note that a spend-cap 429 is now `UsageLimitExceeded`.
3. **Decorator forwarding.**
   - The `LlmPort::model_profile` rustdoc already says a decorator **must forward** it.
   - A consumer upgrading with its own `LlmPort` wrappers won't read trait docs, and the default `None` compiles
     silently. Add one line to the §9.8 behaviour list.
4. **Commissary budgets grow silently.**
   - Adapter-wide `get_capabilities().max_context_tokens` now follows the default model's seed when
     `context_window` is unset: Anthropic 200,000 → 1,000,000; DeepSeek 64,000 → 1,048,576
     (`anthropic/adapter.rs` and `deepseek/adapter.rs` `declared_capabilities`).
   - So `Commissary::from_port` rations about 5× / 16× more prompt.
   - §9.8 says windows "come from a dated registry" but not this consequence. Add it, with the two remedies:
     set `context_window`, or use `Commissary::for_model`.

**Acceptance.** All four appear in §9.8; Phase 46's migration guide inherits them.

### 3.5 SURFACE-05 — Pacing-only composition for direct-adapter consumers (additive; Should)

Doc-tested.

**Acceptance.** One doc test wraps an `Arc<dyn LlmPort>` in Cadence through `paladin::` with no `PriceTable`.
