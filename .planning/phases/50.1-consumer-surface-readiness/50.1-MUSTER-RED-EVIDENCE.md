# Phase 50.1 -- Consumer-surface muster: proven-red evidence

> SURFACE-03 requires the muster pins for the Aegis family (D-04, Appendix B items 1-2) to be recorded red
> against the pre-phase library tree before they are made green (D-12). A pin that was never observed to fail
> proves nothing. This file records the scripted run and its transcript. The pins were written first; the five
> facade module lines and the nine prelude names did not exist yet. No library source is mutated: the library
> tree at the recorded commit is the "mutation". This file is the only artifact of the red run.

Tree: 18a019ec5794f7ba864dd693b0f19ed6e6101e45 (git tree object `40df30d649718b29d165ef07999058ba8d76e1d8`)

Every cargo invocation ran with `CARGO_INCREMENTAL=0` and `--offline`.

A run counts as proof only when all of these hold (checked by counts and presence, never by diagnostic order):

1. the pins are present in `tests/consumer_surface_muster.rs` (otherwise the script aborts with `PINS-NOT-PRESENT`);
2. `cargo check --offline --test consumer_surface_muster` exits non-zero;
3. exactly one `^error: could not compile` line appears and it names ```paladin-ai` (test "consumer_surface_muster")``,
   which shows that no library crate failed first;
4. at least one `--> tests/consumer_surface_muster.rs:` location is reported (and, here, an `E0432` or `E0433`
   unresolved-import error, the class SURFACE-01 closes).

## Experiment 1 -- D-04 Aegis pins against the pre-phase library tree

The D-04 pins (`aegis_construction_pin`, `node_error_read_pin`, `prelude_aegis_names_agree` and the five
`use paladin::core::platform::container::{aegis, battlefield, node_error, transience, waypoint}` imports) are
added to the muster while `src/core/platform/mod.rs` and `src/prelude.rs` are still the pre-phase files. The
natural failure is an unresolved import of each of the five modules plus the nine missing prelude names.

Script (`red_proof_aegis.sh`, kept in the session scratchpad outside the repository and never committed):

```bash
#!/usr/bin/env bash
# Phase 50.1 plan 01, Experiment 1: run the D-04 Aegis pins against the pre-phase library tree
# (no facade module line for aegis, battlefield, node_error, transience or waypoint) and prove
# ONLY the consumer-surface muster fails.
# Usage: red_proof_aegis.sh <repository-root> <log-dir>
set -uo pipefail
REPO="${1:?usage: red_proof_aegis.sh <repo-root> <log-dir>}"
RED_DIR="${2:?usage: red_proof_aegis.sh <repo-root> <log-dir>}"
cd "$REPO" || exit 2
mkdir -p "$RED_DIR"
LOG="$RED_DIR/aegis.log"
export CARGO_INCREMENTAL=0

# 1. Baseline guard: refuse to start on a dirty library tree.
if [ -n "$(git status --porcelain -- crates src)" ]; then
  echo "DIRTY-BASELINE"
  exit 2
fi

# 2. Pins-present guard: the red run is only meaningful with the D-04 pins in place.
for pin in 'with_aegis(Aegis {' 'NodeErrorSource::Timeout(' '.node_errors' 'paladin::core::platform::container::aegis'; do
  grep -qF -- "$pin" tests/consumer_surface_muster.rs || { echo "PINS-NOT-PRESENT:$pin"; exit 3; }
done

# 3. The check.
cargo check --offline --test consumer_surface_muster >"$LOG" 2>&1
rc=$?
echo "cargo-check-rc=$rc"

# 4. Verdict by counts and presence only, never by diagnostic order.
why=""
[ "$rc" -ne 0 ] || why="$why rc-was-zero"
[ "$(grep -c '^error: could not compile' "$LOG")" -eq 1 ] || why="$why could-not-compile-count-not-1"
grep '^error: could not compile' "$LOG" | grep -qF '`paladin-ai` (test "consumer_surface_muster")' \
  || why="$why could-not-compile-line-does-not-name-muster"
grep -q -- '--> tests/consumer_surface_muster.rs:' "$LOG" || why="$why no-muster-location"
grep -Eq 'error\[E043[23]\]' "$LOG" || why="$why no-E0432-or-E0433"
if [ -z "$why" ]; then
  echo "RED-PROVEN"
  exit 0
fi
echo "NOT-PROVEN:$why"
exit 1
```

## Experiment 2 -- a new FinishReason variant against the D-11 exhaustive pin

Plan 50.1-03 adds `finish_reason_is_exhaustive` and `arsenal_error_is_exhaustive` to the muster: a full `match` on
every variant of `FinishReason` and of `ArsenalError`, with no wildcard arm (D-11). Neither enum is
`#[non_exhaustive]`, so a consumer's own exhaustive match is a supported shape and a new variant is a registered
break. The mutation adds one unit variant, `MusterProbe`, to `FinishReason` in
`crates/paladin-ports/src/output/llm_port.rs`. The compiler names exactly one library site that needs an arm:
`finish_label` in `crates/paladin-llm/src/response_guards.rs` (the plan's threshold is three, so `ArsenalError` is not
mutated). The script patches that one site so the library still builds, then checks the muster.

Tree: HEAD 799ed08a448d8f0b1c41d245b2cc6eca45218eed (git tree object `b7726065559af4c1ce49b0f779e35a07d585232a`),
with the two new pins present in the working copy of `tests/consumer_surface_muster.rs` (not yet committed when the
script ran; `crates` and `src` were clean, which the script's baseline guard enforces).

Every cargo invocation ran with `CARGO_INCREMENTAL=0` and `--offline`.

Script (`red_proof_finish_reason.sh`, kept in the session scratchpad outside the repository and never committed):

```bash
#!/usr/bin/env bash
# Phase 50.1 plan 03, Experiment 2: add one unit variant to FinishReason, patch the one library
# site the compiler names so the library still builds, and prove ONLY the consumer-surface muster
# fails (at the D-11 exhaustive pin).
# Usage: red_proof_finish_reason.sh <repository-root> <log-dir>
set -uo pipefail
REPO="${1:?usage: red_proof_finish_reason.sh <repo-root> <log-dir>}"
RED_DIR="${2:?usage: red_proof_finish_reason.sh <repo-root> <log-dir>}"
cd "$REPO" || exit 2
mkdir -p "$RED_DIR"
LIBLOG="$RED_DIR/finish_reason_lib.log"
LOG="$RED_DIR/finish_reason.log"
export CARGO_INCREMENTAL=0
ENUM_FILE=crates/paladin-ports/src/output/llm_port.rs
SITE_FILE=crates/paladin-llm/src/response_guards.rs

# 1. Baseline guard: refuse to start on a dirty library tree.
if [ -n "$(git status --porcelain -- crates src)" ]; then
  echo "DIRTY-BASELINE"
  exit 2
fi

# 2. Pins-present guard: the red run is only meaningful with the D-11 pin in place.
grep -qF 'fn finish_reason_is_exhaustive' tests/consumer_surface_muster.rs \
  || { echo "PINS-NOT-PRESENT"; exit 3; }

# 3. Restore on success, failure and interrupt, installed before the first edit.
trap 'git checkout -- crates src' EXIT

# 4. The mutation (a new variant) and the one library-site patch the compiler names.
perl -0pi -e 's/(    Error\(String\),\n)\}/$1    \/\/\/ Experiment 2 probe variant (never committed).\n    MusterProbe,\n}/' "$ENUM_FILE"
perl -0pi -e 's/(        FinishReason::Error\(_\) => "error",\n)/$1        FinishReason::MusterProbe => "probe",\n/' "$SITE_FILE"

# 5. Mutation-applied guard: a pattern that stops matching must abort, never go vacuously green.
if ! grep -q '^    MusterProbe,$' "$ENUM_FILE" || ! grep -q 'FinishReason::MusterProbe => "probe",' "$SITE_FILE"; then
  echo "MUTATION-NOT-APPLIED"
  exit 3
fi
echo "patched-files:"
git diff --name-only -- crates src

# 6. The library must still build with the mutation (so only the muster can fail).
cargo check --offline --workspace --lib >"$LIBLOG" 2>&1
librc=$?
echo "cargo-check-workspace-lib-rc=$librc"
[ "$librc" -eq 0 ] || { echo "NOT-PROVEN: library-does-not-build"; exit 1; }

# 7. The check.
cargo check --offline --test consumer_surface_muster >"$LOG" 2>&1
rc=$?
echo "cargo-check-rc=$rc"

# 8. Verdict by counts and presence only, never by diagnostic order.
why=""
[ "$rc" -ne 0 ] || why="$why rc-was-zero"
[ "$(grep -c '^error: could not compile' "$LOG")" -eq 1 ] || why="$why could-not-compile-count-not-1"
grep '^error: could not compile' "$LOG" | grep -qF '`paladin-ai` (test "consumer_surface_muster")' \
  || why="$why could-not-compile-line-does-not-name-muster"
grep -q -- '--> tests/consumer_surface_muster.rs:' "$LOG" || why="$why no-muster-location"
grep -Eq 'error\[E0004\]' "$LOG" || why="$why no-E0004-non-exhaustive"
if [ -z "$why" ]; then
  echo "RED-PROVEN"
  exit 0
fi
echo "NOT-PROVEN:$why"
exit 1
```
