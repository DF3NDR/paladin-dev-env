# Phase 50.1 -- Consumer-surface muster: proven-red evidence

> SURFACE-03 requires the muster pins for the Aegis family (D-04, Appendix B items 1-2) to be recorded red
> against the pre-phase library tree before they are made green (D-12). A pin that was never observed to fail
> proves nothing. This file records the scripted run and its transcript. The pins were written first; the five
> facade module lines and the nine prelude names did not exist yet. No library source is mutated: the library
> tree at the recorded commit is the "mutation". This file is the only artifact of the red run.

Tree: 18a019ec5794f7ba864dd693b0f19ed6e6101e45 (git tree object `40df30d649718b29d165ef07999058ba8d76e1d8`)

Every cargo invocation ran with `CARGO_INCREMENTAL=0` and `--offline`.

A run counts as proof only when all of these hold (checked by counts and presence, never by diagnostic order):

1. the pins are present in `tests/consumer_surface_muster.rs` (otherwise the script aborts with `PINS-NOT-PRESENT`);
2. `cargo check --offline --test consumer_surface_muster` exits non-zero;
3. exactly one `^error: could not compile` line appears and it names ```paladin-ai` (test "consumer_surface_muster")``,
   which shows that no library crate failed first;
4. at least one `--> tests/consumer_surface_muster.rs:` location is reported (and, here, an `E0432` or `E0433`
   unresolved-import error, the class SURFACE-01 closes).

## Experiment 1 -- D-04 Aegis pins against the pre-phase library tree

The D-04 pins (`aegis_construction_pin`, `node_error_read_pin`, `prelude_aegis_names_agree` and the five
`use paladin::core::platform::container::{aegis, battlefield, node_error, transience, waypoint}` imports) are
added to the muster while `src/core/platform/mod.rs` and `src/prelude.rs` are still the pre-phase files. The
natural failure is an unresolved import of each of the five modules plus the nine missing prelude names.

Script (`red_proof_aegis.sh`, kept in the session scratchpad outside the repository and never committed):

```bash
#!/usr/bin/env bash
# Phase 50.1 plan 01, Experiment 1: run the D-04 Aegis pins against the pre-phase library tree
# (no facade module line for aegis, battlefield, node_error, transience or waypoint) and prove
# ONLY the consumer-surface muster fails.
# Usage: red_proof_aegis.sh <repository-root> <log-dir>
set -uo pipefail
REPO="${1:?usage: red_proof_aegis.sh <repo-root> <log-dir>}"
RED_DIR="${2:?usage: red_proof_aegis.sh <repo-root> <log-dir>}"
cd "$REPO" || exit 2
mkdir -p "$RED_DIR"
LOG="$RED_DIR/aegis.log"
export CARGO_INCREMENTAL=0

# 1. Baseline guard: refuse to start on a dirty library tree.
if [ -n "$(git status --porcelain -- crates src)" ]; then
  echo "DIRTY-BASELINE"
  exit 2
fi

# 2. Pins-present guard: the red run is only meaningful with the D-04 pins in place.
for pin in 'with_aegis(Aegis {' 'NodeErrorSource::Timeout(' '.node_errors' 'paladin::core::platform::container::aegis'; do
  grep -qF -- "$pin" tests/consumer_surface_muster.rs || { echo "PINS-NOT-PRESENT:$pin"; exit 3; }
done

# 3. The check.
cargo check --offline --test consumer_surface_muster >"$LOG" 2>&1
rc=$?
echo "cargo-check-rc=$rc"

# 4. Verdict by counts and presence only, never by diagnostic order.
why=""
[ "$rc" -ne 0 ] || why="$why rc-was-zero"
[ "$(grep -c '^error: could not compile' "$LOG")" -eq 1 ] || why="$why could-not-compile-count-not-1"
grep '^error: could not compile' "$LOG" | grep -qF '`paladin-ai` (test "consumer_surface_muster")' \
  || why="$why could-not-compile-line-does-not-name-muster"
grep -q -- '--> tests/consumer_surface_muster.rs:' "$LOG" || why="$why no-muster-location"
grep -Eq 'error\[E043[23]\]' "$LOG" || why="$why no-E0432-or-E0433"
if [ -z "$why" ]; then
  echo "RED-PROVEN"
  exit 0
fi
echo "NOT-PROVEN:$why"
exit 1
```
