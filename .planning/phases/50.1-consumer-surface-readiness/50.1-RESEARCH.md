## Summary

Phase 50.1 is six small, mostly mechanical changes to the consumer surface, plus one human-in-the-loop data task. Nothing in it needs a new library. The facade work (SURFACE-01 and SURFACE-05) is literally `pub use` lines; the muster work (SURFACE-03) is a compile-only test file whose baseline compiles offline in about a minute; the docs work (SURFACE-04) is edits to one section of `MIGRATION.md`. The two heavy items are SURFACE-02 (a registered constructor break across seven types and roughly 190 textual call sites in about 40 files) and SURFACE-06 (a live probe the operator must run, then a seed commit whose ripple touches a docs drift test, the probe harness's own self-test and adapter model lists).

Reading the tree turned up **two premises in CONTEXT.md that are not true of the code** and a handful of traps that will cost a plan a re-do if missed. (1) D-06 says `OpenAIConfig.model` "feeds the declared capabilities / context-window seed chain … the way `AnthropicConfig.model` and `DeepSeekConfig.model` already do". They do not: nothing in either adapter reads `config.model` (grep: zero hits); the adapter-wide window comes from the compile-time `ANTHROPIC_DEFAULT_MODEL` / `DEEPSEEK_DEFAULT_MODEL` constants, and OpenAI's adapter-wide window is a hard-coded `128000`, not a seed lookup. (2) D-19 / handoff §3.4 call the pre-v0.10.0 rows "P31, P32, P33"; those strings do not appear in `MIGRATION.md`: they are phase numbers. The pointer list must cite the §9.2 rows by type name. Beyond these: D-07 as written makes `AnthropicConfig::new("k", "claude-haiku-5-5")` default to `max_tokens = 128_000` while `from_env()` stays at 4,096 (Anthropic documents that `max_tokens` does not count toward OTPM, so the rate-limit worry is moot, but the asymmetry and a 31x jump are still worth an owner confirmation); the §9.8 spend-cap sentence must not claim more than owner reading R-2 allows; and the D-15 candidate list includes ids the 50-17 run already showed the harness cannot measure (`kimi-k2.7-code*`, `qwen3-max`).

**Primary recommendation:** Plan it as four plans in three waves: (A) additive facade exports + examples + the Aegis muster pins and red proof; (B) the operator probe checkpoint (autonomous: false), started in wave 1 so operator latency never gates code; (C) the SURFACE-02 break done as a macro commit then one compile-green commit per provider, each carrying its call sites and its muster pin; (D, after B and C) remaining muster pins, CI job, MIGRATION/CHANGELOG, seeds. Measure semver-checks before writing any allowlist text, because the arity change may fire no lint and then the register-only precedent applies.

### Pattern 1: Whole-module facade re-export (SURFACE-01)
**What:** Five lines in the hand-picked list of `pub mod container` in `src/core/platform/mod.rs`. All five are unconditional `pub mod` in `paladin-core` (`container/mod.rs` lines 1, 7, 29, 54, 64). [VERIFIED: codebase]
**Why safe:** ADR-0018's "no shim re-exports" concerns old paths of relocated types; these types never moved, and the file already re-exports 39 sibling modules the same way.

### Pattern 2: Two new arms in `config_knob_builders!` (SURFACE-02)
**What:** Add to the `@common` arm (so the plain and `plain_max_tokens` forms both get them). All nine structs have `pub base_url: String` and `pub timeout_seconds: u64` (counted per file). [VERIFIED: grep]
```rust
/// Set the endpoint the adapter sends to, replacing the vendor default `new` chose.
///
/// The credential header goes wherever this points, so it must be an endpoint you trust;
/// redirects are never followed. The value is checked (`http`/`https`) when the adapter is built.
#[must_use]
pub fn with_base_url(mut self, base_url: impl Into<String>) -> Self {
    self.base_url = base_url.into();
    self
}

/// Set the request timeout in seconds, replacing the default `new` chose (300 s for a seeded
/// reasoning model, the provider's own default otherwise; Phase 50 D-13). An explicit value
/// always wins; call it after `new`.
#[must_use]
pub fn with_timeout_seconds(mut self, timeout_seconds: u64) -> Self {
    self.timeout_seconds = timeout_seconds;
    self
}
```
`impl Into<String>` for `with_base_url` mirrors `LlmProviderConfig::with_base_url` (`config/llm.rs:~93`); `with_timeout_seconds(u64)` mirrors its `with_timeout_seconds(u64)`. Keep `new(api_key: String, model: String)` as concrete `String` (the shape every existing constructor uses; switching to `impl Into<String>` would also change fn-pointer coercions the muster pins elsewhere). [ASSUMED: `String` vs `impl Into<String>` on `new` is Claude's discretion per CONTEXT; this is the recommendation]

### Pattern 4: Muster pin conventions (SURFACE-03)
Compile-only, never executed, imports only `paladin`, `paladin_ports`, `paladin_memory`, full literals without `..` where the consumer builds the struct. Match shape depends on `#[non_exhaustive]`, which I read per type:

| Type | `#[non_exhaustive]`? | Pin shape |
|------|----------------------|-----------|
| `FinishReason` (Stop, Length, ContentFilter, FunctionCall, Error(String)) | no | full `match`, no wildcard |
| `ArsenalError` (ToolNotFound, InvalidArguments, Timeout, ProtocolError, TransportError, AuthFailed) | no | full `match`, no wildcard |
| `Transience` (Transient, Permanent, Unknown) | no (documented as deliberate) | full `match` is allowed |
| `NodeErrorSource`, `TimeoutKind`, `ErrorHandlerSpec` | **yes** | `match` needs a `_` arm; constructing a variant is still allowed |
| `LlmError`, `LlmError::RateLimitExceeded`, `EmptyCompletion`, `Refusal` | **yes** | `_` arm / `{ .. }` patterns; build with `LlmError::rate_limited(None)` |
| `Aegis`, `TimeoutPolicy`, `NodeError`, `Armament` | no | struct literals work; `Aegis { .., ..Aegis::default() }` is valid |
| `LlmError::UsageLimitExceeded { provider, regain_hint }` | variant is not `#[non_exhaustive]` itself (enum is) | name both fields |

### Anti-Patterns to Avoid
- **Deprecated alias for the old `new`**: forbidden (ADR-0060, D-00b).
- **A second builder mechanism or a `ProviderConfig` type** (D-00d, D-05).
- **Wiring `config.model` into `declared_capabilities`** to "make D-06 true": silent window change (see C1).
- **Editing a muster pin to `..Default::default()` to turn it green** (muster header rule).
- **Seeding a model from its listing row alone** (half-measured entry; D-00f). Seeding from the new transcript with a per-field evidence comment, like the existing rows, is the pattern.
- **Putting `check-consumer-surface` in `check-gates`** (rejected, D-10).

## Common Pitfalls

### Pitfall 1: Treating `config.model` as load-bearing
**What goes wrong:** the plan implements D-06 literally (window follows `config.model`) and silently moves OpenAI's adapter-wide window 128,000 to 400,000 for every direct-adapter consumer, 3x more Commissary budget, which is the exact surprise SURFACE-04 is documenting for Anthropic/DeepSeek.
**Why:** C1 above. **Avoid:** store the field, print it, validate non-empty, leave `declared_capabilities` alone, and document in the §9.2 row that the field names the default model and changes no limit. **Warning sign:** a diff touching `declared_capabilities(None)` in `openai/adapter.rs`.
The bridge's `OPENAI_ENV` comment ("`OpenAIConfig` carries no model") and the test `openai_model_argument_only_selects_the_timeout_profile_and_is_shape_checked` (`bridge.rs:~1015`) must be rewritten; `OPENAI_DEFAULTS.model` becomes `Some(OPENAI_DEFAULT_MODEL)`, `OPENAI_ENV.model` stays `None`. About a dozen in-crate full struct literals in `openai/adapter.rs` tests (lines ~1239 to ~3115) plus the bridge literal need `model:`.

### Pitfall 2: `AnthropicConfig::new` max_tokens asymmetry (D-07)
**What goes wrong:** with `claude-haiku-5-5` seeded at `max_output_tokens = 128_000`, `new(key, "claude-haiku-5-5")` sends `max_tokens: 128000` on every request that sets none, while `from_env()` (unchanged, D-05) uses `ANTHROPIC_DEFAULT_MAX_TOKENS = 4096`. Two constructors of one type then disagree by 31x. SURFACE-06 widens it: seeding `claude-opus-4-8` flips `new(.., "claude-opus-4-8")` from 4,096 (unseeded fallback) to 128,000.
**Rate-limit worry resolved:** Anthropic's rate-limit page states OTPM "is evaluated in real time as output tokens are produced... The `max_tokens` parameter does not factor into OTPM rate limit calculations, so there is no rate limit downside to setting a higher `max_tokens` value." [CITED: platform.claude.com/docs/en/api/rate-limits]. Cost is per generated token, so a high ceiling alone does not raise spend.
**Still open:** whether the owner wants the asymmetry; whether a non-streaming request with a 128k ceiling is accepted by the REST endpoint unchanged [ASSUMED: the SDKs, not the API, are known to guard long non-streaming requests; unverified]. See Open Question 1; recommend a one-line owner confirmation at plan time, default to D-07 as locked.
**Implementation:** add `pub(crate) fn seeded_max_output(table, model) -> Option<u32>` (cfg-gated like `seeded_window`) and `new` uses `seeded_max_output(seeded::ANTHROPIC, &model).unwrap_or(ANTHROPIC_DEFAULT_MAX_TOKENS)`. Entries that leave `max_output_tokens` `None` (Kimi pattern: "no maximum output is documented") fall to the compiled default, which is why the helper returns `Option`.

### Pitfall 3: Argument-order hazard introduced by the harmonised shape
`OllamaConfig::new(base_url, model)` and the other seven `new(api_key, model)` are all `(String, String)`. A consumer porting from Ollama to DeepSeek, or a mechanical migration script, can pass `(url, model)` into `(api_key, model)` and it compiles. `validate()` only checks that the key is non-empty and the URL starts with `http`; a URL passed as a key is accepted and fails later as a 401. **Avoid:** rustdoc on every `new` names the first argument; the §9.8 DR row states Ollama's first argument is the endpoint; migration of in-tree call sites is by compiler error, not regex (old arities of 3 and 4 and OpenAI's 1 all fail to compile, so a stale call cannot slip through silently). A newtype is out of scope.

The 0.50.0 catalog does contain `method_parameter_count_changed`, so a lint may well fire for the arity changes (it did not for Commissary). [VERIFIED: `strings` on the binary; precedents in `.cargo/semver-checks-allowlist.toml` and MIGRATION Phase 32 note] **Procedure (D-00b):** temporarily remove the lint table in `crates/paladin-llm/Cargo.toml`, run `cargo semver-checks check-release --package paladin-llm --baseline-version 0.10.1 --release-type minor` with default features **and** with all nine adapter features (`paladin-llm`'s default features are only `openai` and `mock`, so a default run sees `OpenAIConfig` and hides the other eight configs), restore the table byte-for-byte, record the fired lints. ### Applicable ASVS Categories
| ASVS Category | Applies | Standard Control |
|---------------|---------|------------------|
| V2 Authentication | no change | API key handling is unchanged; `new(api_key, ..)` keeps taking the key by value |

### Known Threat Patterns
| Pattern | STRIDE | Standard mitigation |
|---------|--------|---------------------|
| Key leaked into the committed probe transcript | Information disclosure | harness prints bodies through `diagnostic_excerpt`; operator skims; scrub with `redact_secret_patterns` semantics plus Google/xAI key shapes and literal env values; negative-grep verify; stop and ask for a rerun on any hit (never edit a measured value) |
| Credential forwarded to an attacker host via redirect after `with_base_url` | Information disclosure / Spoofing | unchanged redirect policy `none`; do not add a code path that builds a client without it |
| Key passed in the `base_url` slot (arg-order mix-up, Pitfall 3) | Information disclosure | rustdoc names the argument; a `base_url` is never logged with a key; `Debug` redaction unchanged |
| Unprofiled or mis-profiled seed turning into silent request refusals | Denial of service (self-inflicted) | seed only fields the transcript evidences; fail-closed `ModelProfile::new()` for the rest |
| Third-party GitHub Action in the new CI job | Tampering | reuse the pinned actions already in `ci.yml` (`actions/checkout@v5`, `dtolnay/rust-toolchain@stable`, `Swatinem/rust-cache@v2`); no new action |
