- **PD-01-1 (D-03, Claude's discretion on names):** script `scripts/check-findings-log.sh`, target `check-findings-log`, seam `FINDINGS_LOG_PATH` (a file path, not a root directory).
- **PD-01-2 (RESEARCH Open Question 3 — pointer requirement):** `in v0.11.1` must be followed by a non-empty pointer. After the token, strip whitespace, `*`, backticks and the separators `—`, `–`, `-`, `:`, `;`, `,`; if nothing remains the entry is `NO_POINTER`. D-02 says every disposition names its evidence, so a bare keyword is not a disposition.
- **PD-01-3 (status protocol):** file-level tokens in status-line precedence order are `UNREADABLE`, `UNCLOSED_FENCE`, `ZERO_ENTRIES`, then `BAD` (any per-entry finding), then `OK`. Per-entry tokens are `OPEN`, `MISSING`, `NO_POINTER`, `BAD_OUT`, `BAD_DUP_TARGET`, `UNRECOGNISED`, `DUPLICATE_ID` and `NOT_INCREASING`. A per-entry line reads `<path>:<line>: DF-nn: <TOKEN>`. Its line is the entry's last Disposition bullet. For `MISSING`, `DUPLICATE_ID` and `NOT_INCREASING` it is the heading's line instead. Lines are sorted by line, then token. The LAST detail line is always `parsed <N> entr(y|ies) from <path>`, on `OK` and on `BAD` alike, so the harness can check that the real log parses while it is still red. `<path>` is printed relative to the workspace root when it lies under it, else as given.
- **PD-01-4 (id rules):** ids compare as integers (`DF-7` equals `DF-07`). A value seen before is `DUPLICATE_ID`, which takes precedence over `NOT_INCREASING`. A value lower than the previous heading's and never seen is `NOT_INCREASING`.
- **PD-01-5 (milestone token):** the accepted keyword is the literal `in v0.11.1` (D-03). The header says that a D-00b forced break renaming the milestone to `v0.12.0` edits this one token in the same commit that records the break.
