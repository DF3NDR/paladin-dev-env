<planner_decisions>
- **PD-04-1 (disk control, orchestrator note):** builds are scoped to one package and target per command, and the workspace `target/` is reused (its deps are cached). Never run an unscoped `cargo test`. Before each cargo command print `df -BM --output=avail /`. If under 1500M, delete `target/debug/incremental` and `target/debug/examples` (both regenerable). If a command prints `No space left on device`, delete those two directories and retry once. If it fails again, run `cargo clean -p <the package>` and retry once more. A disk failure is never recorded as a finding (RESEARCH Pitfall 8).
- **PD-04-2 (zero-tests guard):** libtest exits 0 when a filter matches nothing. Each acceptance therefore greps every named test as `<name> ... ok` in the output. A named test that did not run means a feature gate is missing: re-run with the gate its module needs (located by reading the module's `cfg`), and never record "0 tests" as a pass.
- **PD-04-3 (disposition text):** `- **Disposition (<run date, UTC>):** in v0.11.1 — fixed by <REQ> (Phase <N>); proof: <names>, re-run green on <short HEAD sha> (56-DOGFOOD-EVIDENCE.md)`. One line, ASCII apart from the em dash.
</planner_decisions>
