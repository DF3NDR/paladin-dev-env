<objective>
Close DF-07 (S1, credential in logs) in a patch-compatible shape. The `paladin` binary's first log line Debug-formats the whole `Settings` at the default `debug` filter, and five credential fields reach it unredacted because their types derive `Debug`. This plan does both halves the finding asks for (DOGF-06, D-05, D-06):

1. Removes the whole-config format at its only call site (`src/main.rs`) and replaces it with a credential-free summary.
2. Gives every unredacted credential-bearing config type a redacting `Debug`, so no future `{:?}` can leak: `ApiKeyConfig`, `Settings`, `QueueConfig`, `FileStorageConfig` and `EmailAdapterConfig`. `AuthConfig` and `WebHttpConfig` delegate.

Purpose: the keys under `http.auth.api_keys` are the only authentication in front of the agent API, and any log aggregator collecting the binary's stdout/stderr has been receiving them since at least v0.9.0.
Output: one crate-private helper, five hand-written `Debug` impls, a summary line, regression tests, the CHANGELOG, MIGRATION and log records.
</objective>

<planner_decisions>
- **PD-11-1 (both halves, per the finding).** The call site is fixed AND the types redact. Removing the format alone leaves the next `{:?}` (a panic message, a test failure, a future debug line) to leak again. Redacting alone keeps a 6 KB config dump in every startup log for no operator benefit. `paladin-server` never logs its `Settings` (56-05 audit), so `src/main.rs` is the only call site.
- **PD-11-2 (crate-private mirror, not a widened `RedactedKey`).** `src/config/redaction.rs` holds a `pub(crate)` `RedactedSecret` with the exact `RedactedKey` rule. Making paladin-llm's type public would add public surface to a second crate for a patch fix (D-00b, D-06). paladin-notifications gets its own module-private copy of the same three-line rule, because it depends on neither crate's internals.
- **PD-11-3 (marker).** The marker is `<redacted>`, the one `LlmProviderConfig` and `OtelConfig` already print in the same log line. `NodeCacheConfig` and `AllowanceWebhookConfig` print `[REDACTED]` and `[redacted]`; they are left alone (no finding against them).
- **PD-11-4 (one build profile for Stage C).** Every cargo invocation uses `-p paladin-ai --features cli,web-server`, or `-p paladin-notifications --features email`. Lib tests, bin tests and the probe build then share one dependency build on a ~5.4 GB disk. 56-12 and 56-13 use the same profile.
- **PD-11-5 (URL-shaped fields are not redacted).** `llm_url`, `SourceConfig.url`, `QdrantSanctumConfig.url` and `MCPServerConfig.endpoint` hold a credential only when an operator embeds userinfo. The audit classed them as lower risk, and the only whole-config log site is removed here. Redacting them would mean URL parsing inside `Debug`. This is accepted as T-56-41 rather than silently dropped.
- **PD-11-6 (Serialize is out of scope).** `ApiKeyConfig.key` and the others still serialise. No shipped binary serialises `Settings` outward (every `serde_json::to_*` of a config in `src/` is in test code). Adding `skip_serializing` would change the 56-02 round-trip, so it is a separate decision. Accepted as T-56-42.
</planner_decisions>
