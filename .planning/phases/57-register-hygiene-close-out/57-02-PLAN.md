<planner_decisions>
- **PD-02-1 (one method, research Pattern 1).** D-01 asked for a newest-run method. D-02 makes the owner the earliest attributed run. The two callers of the old lookup (`load_visible_thread`/`visible_thread_page` and `ensure_thread_visible`) use it only to decide ownership.
  - So one method, `owner_run_for_thread`, closes both rows and adds one public item, not two.
  - It is named after the trait's existing `active_run_for_thread`.
  - The Task 1 checkpoint confirms this, because the port shape is `costly` and the rule is `one-way`.
- **PD-02-2 (earliest-run fallback).** Returning `None` both for "no run" and for "only unattributed runs" would let a tenant's submit claim a schedule-fired thread as thread birth. The old latest-run rule refused that submit (`http_surface_tests.rs:1054-1058` comments).
  - The ordering `(tenant_id IS NULL) ASC, submitted_at ASC, run_id ASC LIMIT 1` keeps the three cases apart with one row read: attributed owner, unattributed-only, and no run.
- **PD-02-3 (default body).** The default walks `list` pages (`limit: 100`, following `next_cursor` until `None`) and keeps the best candidate by the same key. It therefore decodes every row on the thread. That is acceptable for a third-party implementor, and the documented trade-off is that the three real adapters override it with a single-row read.
- **PD-02-4 (test-name stability).** `permits_thread_admits_all_and_only_the_latest_runs_tenant` is cited by `.project/v0.11.1/02-dogfood-findings-log.md`, which is append-only. It keeps its name. A doc comment on it notes that since Phase 57 D-02 its argument is the owner run.
</planner_decisions>

<assumption_delta_decision>
The detector fired on `fallback` inside the debug-session name "kimi fallback profile" (REG-03). That is a false positive: no pluralization happens there. The phase does carry one real identity-model shift, recorded here:

- **Decision:** `promote`. The owner run replaces the latest run as the only input to `permits_thread`. The latest-run lookup is removed from both callers in 57-03, not kept alongside, so no caller can judge ownership by recency.
