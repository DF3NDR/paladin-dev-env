<planner_decisions>
- **PD-14-1 (give-back inside `confirm` only).** The give-back is applied to the admission's notices in `confirm`. `notify_operator` keeps its signature and its log-and-swallow behaviour for `TreasurerSpendGuard`'s mid-run notices: there the warning is also emitted as the run's trace event and herald line, so it is not lost silently, and giving it back would re-emit the warning in another run. `guard.rs` is not modified; the module docs say so.
- **PD-14-2 (cancellation safety lives in the Treasurer).** `confirm` and `abandon` move their work into a detached task (`tokio::runtime::Handle::try_current()`; spawn; await the `JoinHandle`; a `JoinError` is logged with the notice count only). The task owns `Option<Arc<dyn TreasuryNoticePort>>`, `Option<OperatorNoticeTarget>` and the admission's notices (all `Clone`), so it needs no `&self`; the enqueue helper becomes an associated function that takes the target and notice. With no runtime handle the work runs inline, as today (no panic path). This covers the agent routes too, without touching `paladin-web` (P-14-2).
- **PD-14-3 (the persist window).** Only the submission path has an await between the claim and `confirm`/`abandon` (`persist_and_enqueue`). A private drop guard, `AdmissionSettlement { treasurer, repository, run_id, admission: Option<Admission> }`, is armed when `admit` returns and disarmed by `settle(persisted: bool)`. If it is dropped armed, `Drop` spawns a task that reads the run row: `Ok(Some(_))` means the row was written, so `confirm`; `Ok(None)` or `Err` means `abandon`. An unreadable row is given back rather than kept, which prefers a possible second notice over a lost one, the same preference the review's own fix states.
- **PD-14-4 (WINDOWS phase column).** `--phase 41`, as row 89.
</planner_decisions>
