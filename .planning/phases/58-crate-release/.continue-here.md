## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|----------------------|
| Parked watcher or polling | A `gh run watch`, a `sleep` loop or a spawned agent waiting for the merge, the tag or the `release.yml` run | blocking | The two-part resume condition below is checked once, by whoever resumes, not by anything running now |
| Reading an aggregate status | Using the commit status, the PR rollup or "the first `ci.yml` run listed" instead of each run's and each job's own conclusion | high | Read `status` and `conclusion` per run and per job; the deciding `ci.yml` run is the newest by `created_at`, then `id` |
| Tagging an ancestor, not the merge commit | A tag on a commit that is merely contained in `main` (or on the PR head, or after a squash or rebase merge) | blocking | Plan 58-13 Task 1 proves the tagged commit EQUALS the PR's `merge_commit_sha`; ancestry alone is rejected |

| Fixing or completing forward during a red release run | Re-running, re-dispatching or yanking by the agent | blocking | D-00s: read-only diagnosis, written down, then a hard stop; those acts are the maintainer's |
