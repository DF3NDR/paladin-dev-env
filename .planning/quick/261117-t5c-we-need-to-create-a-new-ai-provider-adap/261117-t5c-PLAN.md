in the ADR.

Selection rules (deterministic):
- F4: the model the chat-completion reference page's own request example uses, IF the model overview lists
  that model as current, text-only and general-purpose. Otherwise the first current, text-only,
  general-purpose GLM model on the overview page. A model is excluded when its id or description marks it as
  vision/audio/image/video/OCR, coding-plan-only, or deprecated. Record the reason for the choice in the
  constant's rustdoc.
- F5: F4 first, then up to three more current, text-only, general-purpose ids from the same page, in page
  order.
- F7: when the docs state an inclusive range, use it as written. When they state a half-open range
  (an upper bound that is excluded), use an inclusive upper bound just inside it, following the Qwen
  `(0.0, 1.99)` precedent and its rustdoc rationale. In both cases label it "vendor-documented, not
  live-measured".
- F8: a sampling field is carried (`true`) only when the chat-completion request schema documents it. For
  `stop`: documented with no cap gives `StopSupport::Supported { max: None }`; documented with a cap N gives
  `Supported { max: Some(N) }`; undocumented gives the `StopSupport` variant meaning not-sent.
- F10: if the docs state that thinking is enabled by default for the F4 model, the compiled timeout default is
  `registry::REASONING_DEFAULT_TIMEOUT_SECONDS` (300). Otherwise it is 60, the hosted-preset default.
- Env var names are Paladin's naming choice (discretion), following the vendor-prefix pattern of
  `MOONSHOT_*`, `DASHSCOPE_*` and `XAI_*`: `ZAI_API_KEY`, `ZAI_BASE_URL`, `ZAI_MODEL`, `ZAI_TIMEOUT_SECONDS`.
