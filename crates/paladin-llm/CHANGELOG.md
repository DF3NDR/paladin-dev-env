# Changelog

All notable changes to `paladin-llm` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project follows lockstep workspace versioning.

## [0.11.0] - 2026-10-26

### Added

- Phase 51 (REASON-01, REASON-04; plans 51-17 to 51-20, gap G-2): `LlmPort::check_reasoning`
  overrides on the nine adapters (`DeepSeekAdapter`, `OpenAIAdapter`, `AnthropicAdapter`,
  `GeminiAdapter`, `KimiAdapter`, `QwenAdapter`, `GrokAdapter`, `OllamaAdapter`,
  `OpenAiCompatibleAdapter`), each answering from the same precedence (`in_force`) and admission
  (`EffortSupport::resolve`) path its `generate` runs, with its own profile and provider-level
  defaults; `PricingLlmAdapter` and `CadenceLlmAdapter` forward it; `FallbackLlmAdapter` overrides
  it as the AND of every hop's own `check_reasoning`, the first refusal prefixed
  `fallback hop <index>: `. The conformance suite gains
  `check_reasoning_agrees_with_send_time_admission` (25 cases in all).

- Phase 51 (REASON-03, REASON-06; plans 51-02, 51-10, 51-14): the `live_vendor_smoke` example gains
  `--effort` (raw-wire effort probe, `--dry-run`, `--models`) and `--effort-smoke` (adapter-path
  smoke at the lowest and highest admitted level, `--max-tokens`, `--timeout-seconds`); both print
  numbers, statuses and metadata values only, never response content. The crate's
  `cargo-semver-checks` lint table gains `constructible_struct_adds_field`, the lint measured
  against the published 0.10.1 for `CompatRequestParameters.reasoning`; the
  `CompatRequestParameters` allowlist entry is now two measured entries.
- **Reasoning effort: `FallbackLlmAdapter` pre-flights every hop before the first call (REASON-04,
  REASON-05; D-08; Phase 51 plan 07).** A request that carries `reasoning` is resolved against each
  hop's own `model_profile` (the step's model, else the request's) in chain order; the first hop that
  has no profile or cannot honour or substitute the effort fails the whole request with
  `LlmError::UnsupportedParameter` naming that hop's provider, model and chain index, and no hop is
  called. The serving hop's `paladin.reasoning_requested` / `paladin.reasoning_effective` keys sit
  beside `paladin.served_by` / `paladin.served_model` on the buffered response and on the streamed
  terminal chunk. A request with no effort in force on any hop behaves exactly as before.

- Phase 51 (REASON-01, REASON-02, REASON-04; plan 51-06): all nine adapters honour
  `LlmRequest.reasoning` exactly or refuse it before HTTP (plans 51-03 to 51-05). Provider-level
  default: `reasoning_effort` / `reasoning_fallback` fields and `with_reasoning_effort` /
  `with_reasoning_fallback` builders on the nine `*Config` types (generated once in
  `config_knob_builders!`), and `LlmProviderConfig.reasoning_effort`, `.reasoning_fallback`,
  `.reasoning_wire` with `with_*` builders (YAML `llm.<provider>.reasoning_effort`,
  `reasoning_fallback`, `reasoning_wire`). Resolved per request below the request's own value; a
  refused default names `llm.<provider>.reasoning_effort`. `reasoning_wire` is accepted for
  `ollama` and `openai-compatible` only. No compiled-in default, no environment variable.

- Phase 51 (REASON-02 to REASON-04; plan 51-04): `compat::CompatRequestParameters.reasoning`
  (`ReasoningWire`), `OllamaConfig.reasoning_wire` / `OpenAiCompatibleConfig.reasoning_wire` with
  `with_reasoning_wire(ReasoningWire)`, and the shared compat engine's exact mapping for
  `top_level_effort`, `thinking_object` and `enable_thinking` (refused before HTTP on any other
  effort or an `unsupported` wire). `compat::ReasoningWire` re-exports the enum. See the
  repository `CHANGELOG.md`.
- Phase 51 (REASON-02 to REASON-06; plan 51-03): `paladin_llm::reasoning` (`ReasoningWire` and the
  re-exported `REASONING_REQUESTED_METADATA_KEY` / `REASONING_EFFECTIVE_METADATA_KEY`);
  `registry::ModelOverride.effort` (YAML `llm.<provider>.models.<model-id>.effort`); the DeepSeek
  and OpenAI adapters honour `LlmRequest.reasoning` exactly or refuse with
  `LlmError::UnsupportedParameter` before any HTTP call, and report a `model_profile` whose effort

- Phase 50.1 (SURFACE-02, D-05; plan 50.1-02): the `#[must_use]` builders `with_base_url(impl
  Into<String>)` and `with_timeout_seconds(u64)` on all nine `*Config` types, generated by

### Fixed

- `PricingLlmAdapter` installs its hop-bill pricer on the active `HOPPED_BILLS` collector before
  `generate` and `generate_stream` delegate (plan 50-32, review WR-03). A billed refusal a
  `FallbackLlmAdapter` hops past is therefore priced against its own model and counted into the
  attempt's spend at the hop, not when the whole call returns. The after-call pricing passes stay
  as an idempotent safety net.

- OpenAI and DeepSeek bill a buffered body with no `choices` (WR-04, Phase 50 iteration 2). They
  used to fail it as `LlmError::ProcessingError` ("No choices in response" / "DeepSeek response
  contained no choices"), which dropped the parsed `usage` and read as `Transience::Unknown`, so the
  retry loop could re-send a request the vendor had already billed. It is now
  `LlmError::EmptyCompletion("Response contained no choices")` carrying `billed_usage()` on the
  served model (else the request model) -- the shape the shared engine and Gemini already return --
  and is `Transience::Permanent` (`MIGRATION.md` 10.1 M-B-22).
- Every adapter bills its empty and refused calls (G-50-5a, Phase 50 plan 50-27). OpenAI,
  DeepSeek, Anthropic, Gemini and the shared engine (Kimi, Qwen, Grok, Ollama, OpenAI-compatible)
  map usage before the shared guard and put it on `LlmError::EmptyCompletion` /
  `LlmError::Refusal` (`billed_usage()`), on the buffered path and on the stream's terminal error
  item. The buffered bill names the served model, else the request model; a stream's bill names the
  request model. The compat "no choices" and Gemini "no candidates" failures bill the usage they
  report. No usage object means no bill, never a zero one.
- `PricingLlmAdapter` prices a billed error as it prices a success (G-50-5a, Phase 50 plans 50-27
  and 50-30): `generate` against the bill's model, a stream's error item against its bill's model
  (the request's model only when the bill names none; WR-01), and an error returned by
  `generate_stream` itself against its bill's model. It also prices
  every hopped-past bill a `FallbackLlmAdapter` recorded, against each hop's own model (see
  *Added*). An unpriced model keeps `cost: None` and its existing warn-once line.

- Gemini `toolUsePromptTokenCount` is folded into `prompt_tokens` (G-50-5a, Phase 50 plan 50-23).
  Gemini counts it in `totalTokenCount`, and the adapter used to drop it. Repro 100/20/300/10
  (total 430) mapped to prompt 100, and now maps to prompt 400. The Anthropic vision path now
  folds `cache_read_input_tokens` and `cache_creation_input_tokens` into `prompt_tokens`.
- Grok reasoning tokens are counted and priced (G-50-5a, Phase 50 plan 50-21): xAI reports
  `reasoning_tokens` beside `completion_tokens`, so the Grok adapter now folds them into
  `completion_tokens` and `total_tokens`, priced at the completion rate. Repro at $1/M input and
  $10/M output (prompt 663, completion 50, reasoning 124, vendor total 837): 1_163_000 nanos before,
  2_403_000 now. Live-measured 2026-10-18 on `grok-4.3`, `grok-4.5` and `grok-4.6` (plans 50-22
  and 50-24), with xAI's billed cost matching reasoning billed at the completion rate.
- The OpenAI adapter sends its output limit as `max_completion_tokens` on every chat-completions
  body (buffered, streamed, every `response_format`) and on the vision request (G-50-5b, Phase 50
  plan 50-19), so `gpt-5.4-nano` no longer answers HTTP 400. Measured accepting the key:
  `gpt-5.4-nano` and `gpt-4o-mini` only (2026-10-15). `OpenAIConfig.max_tokens` and
  `PromptParameters.max_tokens` keep their names; DeepSeek and the compat presets still send
  `max_tokens`.
- Phase 50 code-review fixes:
  - A typed `LlmError::Refusal` is no longer retried by the Anthropic, shared-engine, DeepSeek and
    Gemini retry loops (it is permanent and re-billed the whole prompt on every attempt).
  - A streamed SSE event split across network reads is reassembled instead of dropped, in all five
    streaming paths (Anthropic, OpenAI, DeepSeek, Gemini, shared engine); a multi-byte character
    split at a read boundary is decoded intact.
  - `max_retries` above 10 and `timeout_seconds` of 0 are refused when a provider is resolved from
    its `llm.<provider>` block or environment, and the OpenAI, DeepSeek and shared-engine back-off
    saturates at 10 s instead of overflowing or growing without bound.
  - `LlmProviderConfig.api_key` is no longer written by `Serialize`.

### Changed

- Phase 51 (REASON-01, REASON-04; plans 51-17 to 51-19, gap G-2): `FallbackLlmAdapter`'s
  pre-flight is `check_reasoning`, so each hop is judged against its own step model and its own
  provider-level `reasoning_effort` / `reasoning_fallback`; a request with no effort can be
  refused by a hop's default. `FallbackLlmAdapter::model_profile` reports effort `Unmeasured` (and
  no `effort_verified_on`) when any hop reports no profile; the sampling intersection is
  unchanged. The send-time refusal under an in-force `Refuse` fallback on an unlisted level now
  ends with the same "set a reasoning_fallback" hint the build-time check gives.

- Anthropic, OpenAI, DeepSeek and Gemini accept a reasoning effort on the models the 2026-10-22
  live probe measured (Phase 51 plan 51-12, REASON-02 to REASON-06; `51-EFFORT-PROBE.md`, commit
  `32ce9dd0`). The four native wires keep their documented capabilities (verdict: confirmed).
  OpenAI: 17 probed models take `low`..`xhigh` (`gpt-5.1` to `high`; `gpt-5`, `gpt-5-mini`,
  `gpt-5-nano` take `minimal`..`high`), `off` as `none` on 11 and `auto` where the default call
  reasoned. Anthropic: 11 models take `low`..`max` through `output_config.effort` (`xhigh`
  rejected on `claude-opus-4-6` and `claude-sonnet-4-6`); `claude-opus-4-8`, `claude-opus-4-7`,
  `claude-opus-4-6` and `claude-sonnet-4-6` pair it with adaptive thinking. DeepSeek:
  `deepseek-flash` and `deepseek-v4-pro` take `low`, `high`, `max`, `off`, `auto`; `minimal`,
  `medium` and `xhigh` are refused (the vendor runs them as another level). Gemini: 12 models take
  `low`..`high` in lowercase, six also `minimal`. No native model takes an explicit `Budget` (no
  vendor-documented maximum). Models the probe did not cover refuse an explicit effort. The
  conformance suite gains three cases (24 in all) and the required fixture method
  `ConformanceFixture::effort_wire_value`.
- Kimi, Qwen and Grok accept a reasoning effort on the models the 2026-10-22 live probe measured
  (Phase 51 plan 51-11, REASON-02, REASON-03, REASON-04, REASON-06; `51-EFFORT-PROBE.md`, commit
  `32ce9dd0`). Kimi keeps the `thinking.effort` wire and never sends a top-level
  `reasoning_effort` (the vendor ignored an invalid value there): `kimi-k3` and `kimi-k2.6` take
  `low`, `high`, `max`, `off`, `auto`. Qwen keeps `enable_thinking` / `thinking_budget`: all 13
  probed models take `off`, 11 also `auto` and `Budget(1..=32768)` (`qwen-max` and
  `qwen-plus-latest` `off` only), and no named level. Grok's wire changes from `Unsupported` to the
  top-level `reasoning_effort`: `grok-4.3`/`4.6`/`4.7` take `minimal` to `xhigh` and `auto`,
  `grok-4.5` `minimal` to `high` and `auto` (`xhigh` refused as coerced), `grok-4.20-reasoning`
  `auto` only. Models the probe did not cover refuse an explicit effort. No further public item changed beyond those listed in this section.
- BREAKING: `compat::CompatRequestParameters` gains the field `reasoning: ReasoningWire` and
  `CompatRequestParameters::all()` becomes `all(reasoning: ReasoningWire)` (Phase 51 plan 51-04,
  REASON-02). Migration: state `reasoning: ReasoningWire::Unsupported` in the literal, or pass the
  wire to `all(..)`. No alias.
- Every `*Config::validate()` now requires the base URL to start with `http://` or `https://`
  through one shared `registry::is_http_url` (WR-03, Phase 50.1 review fix `5ebd315b`). OpenAI,
  DeepSeek, Kimi, Qwen, Grok, Ollama and OpenAI-compatible used to test only `starts_with("http")`,
  so `httpx://host` or `http-gateway.internal/v1` was accepted; it is now refused by
  `Adapter::new` with `"Base URL must start with http:// or https://"` (the old text ended
  `"http or https"`). Anthropic and Gemini already checked the full prefix and are unchanged.
- DeepSeek's `EmptyCompletion` detail no longer embeds the provider-reported token counts (G-50-5a,
  Phase 50 plan 50-27). The message used to end in `(provider-reported usage: prompt_tokens=..,
  completion_tokens=.., total_tokens=..)`; that annotation (`annotate_with_usage`) is removed, and
  the counts are on the typed bill, `billed_usage()`. Code that read them from the text must read
  the bill.
- A billed empty or refused completion on the shared engine's buffered path (Kimi, Qwen, Grok,
  Ollama, OpenAI-compatible) now carries its usage on the error (G-50-5a, Phase 50 plan 50-26).
  The response's usage is mapped before the shared guard classifies it, and the guard's
  `LlmError::EmptyCompletion` / `LlmError::Refusal` gets `billed_usage()`: the served model (else
  the request model), the mapped `TokenUsage` and no cost. A body with no `usage` object yields no
  bill, never a zero one. An empty or refused body that omits `usage` now reaches the guard instead
  of failing as a schema mismatch; a successful body without `usage` is still that schema-mismatch
  `ProcessingError` (`MIGRATION.md` 10.1 M-B-22). Every other adapter path bills from plan 50-27.
- Vendor usage totals are reconciled on every adapter (G-50-5a, Phase 50 plans 50-23 and 50-24).
  - The OpenAI, DeepSeek and Gemini adapters parse their vendor total on both paths. The total is
    now optional on the wire, so a usage object without one parses. They record any disagreement,
    and any reasoning or cache containment breach, under `paladin.usage_unreconciled`, the same
    key the compat presets use.
  - The Anthropic adapter runs the containment checks only, because it gets no vendor total.
  - No total is ever copied.
  - The 2026-10-18 live usage probe was applied to every provider's reasoning reading, and changed
    none. Grok (beside completion, with billed cost confirmed), DeepSeek, Kimi, Qwen and Gemini
    are now labelled measured in code and in the guide. OpenAI, Anthropic, Ollama and
    OpenAI-compatible are labelled not live-measured.
- Phase 50: every adapter builds the user turn through one shared rule (the query, then the
  context, each only when non-empty after trimming, joined by one blank line); the OpenAI adapter
  previously sent an empty user message when only the query was set (PARITY-08). OpenAI no longer
  sends a fabricated `temperature` or `top_p`. The Kimi preset sends no `temperature`, `top_p`
  or penalty on any model: the seeded Kimi models and the adapter-wide fallback for an unseeded id
  both state `not sent`. Compat presets send
  stop sequences, except Grok. Default models and windows come from the registry (Anthropic
  `claude-haiku-5-5`, DeepSeek `deepseek-flash`, Kimi `kimi-k2.6`, Qwen `qwen3.8-flash`, Grok
  `grok-4.3`, Gemini `gemini-3.5-flash-lite`), and a direct `*Config` constructor defaults a seeded
  reasoning model to 300 s. An adapter-wide `context_window` now beats seeded windows. Gemini's
  `RECITATION`, `BLOCKLIST`, `PROHIBITED_CONTENT` and `SPII` finishes are `ContentFilter` (they
  were `Error`). The `llm.<provider>` blocks now take effect in the server, and a block's
  `default_temperature` is judged against the model's profile.

- Every adapter now surfaces its first 429 instead of retrying it inside its own loop (the OpenAI
  adapter, the compat engine, the Anthropic adapter and, beyond the original scope, DeepSeek and
  Gemini), carrying the provider's `Retry-After` and rate-limit headers on
  `LlmError::RateLimitExceeded`; network, timeout and 5xx retries are unchanged. An OpenAI 429
  coded `insufficient_quota` and an Anthropic 429 coded `enforced_spend_limit_reached` map to
  `UsageLimitExceeded`, not to a rate limit. A `FallbackLlmAdapter` built with `with_cadence` now
  retries a 429 on the same hop after its gate, for up to the pace budget, before hopping; a 5xx,
  timeout or network error still hops at once, and a chain built without `with_cadence` is unchanged
  (Cadence persona, ADR-0058).

### Breaking Changes

- Phase 50.1 (SURFACE-02, D-05, D-06, D-07; plans 50.1-02, -04, -05, -06): seven `*Config::new(..)`
  constructors take `(api_key, model)`, with no alias. `DeepSeekConfig`, `GeminiConfig`,
  `QwenConfig`, `GrokConfig` and `KimiConfig` drop `base_url`; `OpenAIConfig::new(api_key)` gains
  `model` (and `OpenAIConfig` the public field `model`, a label that changes no adapter-wide
  limit); `AnthropicConfig::new(api_key, base_url, model, max_tokens)` drops `base_url` and
  `max_tokens`. Each endpoint defaults to the type's `*_DEFAULT_BASE_URL` constant
  (`with_base_url` replaces it) and the timeout to 300 s for a seeded reasoning model and 60 s
  otherwise (`with_timeout_seconds` replaces it). `AnthropicConfig::new` sets `max_tokens` to 4,096
  for every model, as `from_env()` and the layered path already did (owner decision
  `compiled-default`, 2026-10-20); `with_max_tokens` is the override. `new(k, url, m)` becomes
  `new(k, m).with_base_url(url)`. `OllamaConfig::new` and `OpenAiCompatibleConfig::new` are the two

## [0.10.0] - 2026-09-18

### Added
- `FallbackLlmAdapter` — a new `LlmPort` implementation that hops across a configured provider
  chain on `Transient`/`Unknown` failures only, with a first-chunk streaming rule and a
  per-hop `FallbackHop` trace event; records the serving provider on `PaladinResult::served_by`
  (paladin-core, FT-05).
- A shared LLM conformance suite (`26-14`) measuring the OpenAI, Anthropic and DeepSeek adapters
  against the same contract (0 gaps at landing).
- Gemini native JSON mode and `response_format` wiring across the OpenAI, compat-engine, and
  DeepSeek wire adapters (RT-05, D-28).

### Changed
- Every provider adapter's non-2xx handling now routes through a shared `map_http_status` helper,
  redacting the response body before bounding it and returning a typed `LlmError::ProviderError
  { status, .. }` in place of the legacy untyped `ProcessingError(String)` (FT-FR-01, FT-FR-16;
  applies to openai, deepseek, anthropic, kimi, qwen, gemini, grok, ollama, openai_compatible).
- All 36 remaining `LlmRequest` construction sites in this crate migrated to the
  `LlmRequest::new` + `with_*` builder pattern (paladin-ports RT-FR-17).

### Fixed
- Redirects are refused on the OpenAI/Anthropic/DeepSeek HTTP clients so a credential header
  cannot be forwarded to an attacker-influenced host (CR-02).
- Anthropic usage-cap and parse-failure response bodies are redacted before being bounded/excerpted
  into an error, and the DeepSeek adapter's credential-redaction routine was deduplicated (CR-01,
  WR-01 follow-ons).
- Credential-shaped redaction markers (`key=`/`token=`) now require a preceding word boundary,
  avoiding a false-positive redaction inside an unrelated token (WR-01).
